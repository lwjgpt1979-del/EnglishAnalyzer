# R2 技术方案 · 真题 + 仿真接入(统一进 platform_question,落地"仿真派生真题"铁律)

> 依据:[重构-KP优先-需求分析.md](重构-KP优先-需求分析.md) 体系③④ + 路线图 R2;承接 R0.5(`platform_question`/`platform_question_kp`/`passage` 骨架)、R0.3(`kp_match_service`)、R1(教材抽取模式)。
> 原则不变:不破坏现有学生前台(仍读 `simulated_questions`);R2 建"平台题"写入与生成骨架并双写,**学生读取切换留到后续**。

---

## 0. 现状关键事实(已核实,决定 R2 怎么切)
- 真题 `exam_papers(卷)`+`exam_questions(题)`,**仅两层、无篇章块**;小题↔KP 多对多挂在**旧** `knowledge_points`(`exam_question_knowledge_points`)。
- 仿真 `simulated_questions`:`source_exam_question_id` **可空**;主生成路径是 **KP 直生**(`question_service.persist_questions`,source 恒 null)→ **铁律未落地**;派生路径(`generate_sim_questions_from_paper`)是 MVP(加`[仿真]`前缀、强用首个 KP)。
- `platform_question` 等 R0.5 表**全空**(仅 schema 测试),`platform_question_kp.node_id → knowledge_nodes`。
- 学生前台**到处读 `simulated_questions`**(练习/模拟考/自助出卷)。
- 错题"练同类"= AI 直生新题、无来源(`practice_for_question → practice_service`)。
- 无 passage 使用,阅读/听力篇章**内联在 stem**。

---

## 1. R2 范围圈定(本期做 vs 留后续)
**本期做(骨架 + 铁律 + 生成,后台与服务层为主)**:
1. 真题进 `platform_question(type='real')`,小题挂 `knowledge_nodes`(走 `kp_match_service`)。
2. 仿真进 `platform_question(type='sim')`,**强制 `parent_real_id`**(铁律),**继承母题 KP**。
3. **KP 直生备选**(决策④):某 KP 无真题母题 → 允许生成 `is_fallback=true`(parent 为空)备选;该 KP **一旦有真题** → 备选 `deprecated_at` 置位、下架。
4. AI 改写服务(真题→仿真,dev mock)+ 预生成入口(admin)。
5. 历史 `exam_questions`/`simulated_questions` 一次性迁移脚本 → `platform_question`(幂等、可 dry-run)。

**留后续(明确不在 R2)**:
- **学生前台读取切换**到 `platform_question`(R2 先双写,读切换单独一期,降风险)。
- **错题"练同类"改走 KP→真题→仿真链** = **R3 错题闭环**(路线图归属)。
- **篇章 passage 大规模拆分**:R2 仅给"结构化导入的新真题"支持 `block_id→passage`;历史内联 stem 不强拆(**决策 R2-D**)。

---

## 2. 新增 / 改动

### 2.1 铁律约束(平台题加 CHECK)
迁移给 `platform_question` 加约束:`type='real' OR parent_real_id IS NOT NULL OR is_fallback`。
→ 仿真要么派生自真题(parent_real_id),要么是显式备选(is_fallback);**杜绝无源仿真**。

### 2.2 真题/仿真写入与生成服务 `platform_question_service.py`(新)
- `import_real_question(db, *, paper_meta, question, kp_names)`:写 `platform_question(type='real', meta=卷信息)`;`kp_names` 走 `kp_match_service` → `platform_question_kp` 边 / 未命中候选(source_type='exam')。
- `generate_sim_from_real(db, *, real_id, count)`:取母题 → AI 改写(dev mock 确定性)→ 写 `platform_question(type='sim', parent_real_id=real_id, is_fallback=false)`;**继承母题 KP**(复制 `platform_question_kp` 边,决策④-C 甲)。
- `generate_fallback_sim(db, *, node_id, count)`:某 node 无真题 → `is_fallback=true` 备选(parent 空),挂该 node。
- `deprecate_fallbacks_for_node(db, *, node_id)`:该 node 有真题进来 → 把其 `is_fallback` 题 `deprecated_at=now` 下架。`import_real_question` 命中 node 后自动调用。

### 2.3 历史迁移脚本 `scripts/migrate_questions_to_platform.py`(新,幂等 + --dry-run)
- `exam_questions` → `platform_question(type='real')`;`exam_question_knowledge_points`(旧 kp)→ 经 **旧 kp 名 → node 别名** 映射建 `platform_question_kp`(命中)或候选(未命中)。
- `simulated_questions` → `platform_question(type='sim')`:有 `source_exam_question_id` → parent_real_id 映射;**无母题的历史仿真** → `is_fallback=true`(标记,不丢)。建 `exam_question_id→platform_question_id`、`sim_id→platform_question_id` 映射(临时表或内存)。

### 2.4 Admin API(`admin.py` 增补,AdminDep)
- `POST /admin/exam-papers/{paper_id}/import-platform`:把该卷的 exam_questions 导入 platform_question(real)+挂 node。
- `POST /admin/platform-questions/{real_id}/gen-sim`:由真题预生成 N 道仿真。
- `GET /admin/platform-questions?type=&node_id=&status=`:平台题查询/审核(复用审核范式,sim 默认 draft→published)。
- 复用 R0.4 候选审核(exam 抽取未命中的 KP 同样进 kp_candidates)。

### 2.5 双写(可选,降低后续切换成本)
新真题/仿真后台录入与生成 **直接写 platform_question**;现有 `simulated_questions` 生成路径**暂保留**(学生前台仍读它),不强拆。**决策 R2-E**:是否在现有仿真生成处加"同步写一份 platform_question"。推荐**否**——R2 以 platform_question 为新主、历史迁移一次到位,新生成只写 platform_question,避免长期双写复杂度;学生读取切换时一并改。

---

## 3. 决策点【✅ 已定 2026-06-17】
- **R2-A 历史真题/仿真 = 一次性迁移**进 platform_question + 旧表保留只读(系统未上线)。
- **R2-B 仿真铁律 = 加 CHECK**(`type='real' OR parent_real_id IS NOT NULL OR is_fallback`),无源仿真禁止。
- **R2-C 真题小题挂 KP = 走 `kp_match_service`**(命中挂 node / 未命中候选,source_type='exam')。
- **R2-D 篇章 passage = 仅新结构化真题支持 `block_id→passage`**,历史内联 stem 不强拆。
- **R2-E 学生前台读取 = 不切**(继续读 `simulated_questions`);平台题读取切换单列一期。
- **R2-F 错题练同类 = 不在 R2**,留 R3 错题闭环。

---

## 4. 分步实施(每步可验收、可独立提交)
- **R2.1** 铁律 CHECK 约束迁移 m85 + `platform_question_service` 写入/继承 KP 骨架 + 单测。
- **R2.2** AI 改写 `generate_sim_from_real`(dev mock 确定性)+ 继承母题 KP + 单测。
- **R2.3** 备选 `generate_fallback_sim` + `deprecate_fallbacks_for_node`(真题到来即下架备选)+ 单测(决策④闭环)。
- **R2.4** 历史迁移脚本(exam→real / sim→sim·parent 映射 / 无母题→fallback)+ 单测(幂等/旧kp→node 映射/dry-run)。
- **R2.5** Admin API(import-platform / gen-sim / 平台题查询审核)+ HTTP 测试 + 前端(后台真题→生成仿真入口)。
- **R2.6** 端到端验收:真题导入→挂node→预生成仿真(继承KP·带parent)→某无真题node建fallback→真题到来fallback下架;全量回归绿。

---

## 5. 验收
- 仿真**必有源**:platform_question 里 type='sim' 的行,要么 parent_real_id 非空、要么 is_fallback=true(CHECK 保证);继承母题 KP。
- 备选闭环:无真题 node 可建 fallback;该 node 真题到来后 fallback 自动 deprecated。
- 真题小题挂 knowledge_nodes;未命中入候选(可审)。
- 旧 `simulated_questions` 与学生前台不受影响(R2 不切读取)。
- 全量回归绿(注意既有 vocab media 6 个环境失败,见 [[test-env-gotchas]])。
