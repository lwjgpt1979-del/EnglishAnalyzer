方案 A · 分题型工作台

  • 按 section → 题型 Tab 切换，每种题型独立布局
  • 确认 = 解析 + 挂 KP 一步完成，消灭双轨
  • 表格批量处理语法题；完形/阅读用 passage + 子表
  • 高置信可「本题型一键采纳」

优点：题型语义清晰、与仿真/学生端同构

成本：前端改造大（2–3 周）

终态推荐。阅读看 evidence 高亮，完形看空位表格，写作看体裁+要点。

方案 B · Section 卡片聚合

  • 保留纵向列表，但按大题 Section 卡片分组
  • 头部集中操作；小题只留摘要 + 主 KP + ⋯
  • 阅读/完形语篇折叠；选项默认收起
  • 未挂统计按题型分桶，减少误报

优点：1 周内可落地，立刻减乱

缺点：AI 标签 vs 解析双轨仍在

适合先止血。对应当前 PlatformQuestions.vue 的渐进改版。

方案 C · 流水线自动化

  • 上传后自动：预标 → AI → 高置信 attach
  • Admin 主界面 = 异常队列（低置信 / 校验失败 / 缺口）
  • 卷级门禁：语法 100% + 阅读 rc 100% 才可发布
  • suggest 全量缓存，避免重复付费

优点：吞吐最高，46 题未挂可 overnight 清零

缺点：需置信度校准 + 抽检机制

依赖 A 的 confirm 模型稳定后再开闸。适合卷库规模化。
