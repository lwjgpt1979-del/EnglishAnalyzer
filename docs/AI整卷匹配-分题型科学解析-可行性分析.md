# AI 整卷匹配 · 分题型科学解析 可行性分析

> v1(2026-07-05)。前置文档:《真题模块分析与仿真落地-可行性报告》。
> 目标:把整卷匹配从「挂考点标签」升级为「**结构化解析对象**」——解析是仿真题的生成依据,仿真题是前端学生分题型学习的素材。全链路人机协同、逐题确认。

---

## 一、核心设计:三类题型,三种解析深度

解析必须**维度固定、可程序校验、可人工快速确认**,否则就是不可控的自由文本(=胡说八道的温床)。

### 1.1 词法/句法类(单选/词汇运用/动词填空/完成句子)——与教材同逻辑 ✅零开发

- **现状即可行**:题型级提示词 + 关注分类(`focus_node_ids` 圈定 cf-*/jf-* 子树)已是现行机制,与教材单元挂靠同一套受控目录匹配;且已叠加两个确定性预标器(rc 问法 / 词形归桶,精确项直接置前)。
- **解析对象**(存 `platform_question.meta.analysis`,免迁移):

```json
{ "kp_codes": ["jf-3-2"],
  "clue": "last year",              // 判定线索:必须是题干子串 → 程序校验
  "clue_type": "时间状语",           // 枚举:时间状语|从句引导词|主语数|固定搭配|上下文
  "distractor_notes": {"A": "原形,漏看时间标志", "C": "过去分词,混淆被动"} }
```

- **科学依据**:单点构念对齐(item–construct alignment);判定线索即命题学中「题目必须自含充分判定信息」原则——我们反向生成 prompt 已用同一原则(P0 已验证),现在把它变成**存量题的显式标注**。

### 1.2 阅读理解——维度多,解析分「篇章层+题目层」两层,每层维度封闭

**篇章层**(一篇一份,存 Passage 关联的 meta):

```json
{ "genre": "说明文",                 // 枚举:记叙|说明|议论|应用(图表/广告/信件)
  "topic": "科技·人工智能", "word_count": 286,
  "difficulty_est": 3 }              // 1-5,命题先验,后续被 CTT 通过率替换
```

**题目层**(一问一份):

```json
{ "rc_code": "rc-3-1",              // 已有确定性分类器打底(884题已标)
  "evidence": "He runs for half an hour and then has breakfast.",
                                      // ★定位句:必须是原文子串 → 程序自动校验,幻觉即打回
  "answer_reason": "由 then 的先后顺序推知跑步在早餐前",
  "distractor_types": {"B": "无中生有", "C": "张冠李戴", "D": "以偏概全"} }
                                      // 干扰项错因:封闭枚举 {原文近似词误配|以偏概全|过度推断|无中生有|张冠李戴|因果倒置}
```

- **科学依据**:
  - **定位句(evidence)= 基于证据的阅读测评**原则:每个客观题答案必须可回文定位。它同时是**最强的防幻觉锚**——`evidence in passage_text` 一行代码即可机器校验,不合格解析自动打回,不进人工队列。
  - **干扰项错因封闭枚举** = 干扰项理据分析(distractor rationale),阅读测评研究的标准做法;也直接变成反向生成的干扰项策略(现 `_READING_PROMPT` 里的「细节题→原文近似词陷阱」从写死变成按题数据驱动)。
  - rc-* 微技能税onomy 已建、已有 884 题确定性标注作校准集。

### 1.3 作文——解析=「审题要点+评分量规」结构化

```json
{ "genre_code": "wr-6-1",            // 体裁:书信/通知/日记/看图/话题(wr-6 子树)
  "required_points": ["自我介绍", "说明来意", "提出两条建议"],   // 要点清单:可逐条核对
  "target_language": ["一般将来时", "建议句型 Why not.../You'd better..."],
  "structure": "三段式:开头问候-主体建议-结尾祝愿",
  "rubric": {"内容": 40, "语言": 40, "结构": 20} }              // 与 essay_service 三维评分同构
```

- **科学依据**:基于量规(rubric)的写作测评;`essay_service` 已用同款三维+band 评分跑通(D-109),此处只是把「批改时才生成的维度」前移为「题目的固有解析」。要点清单同时是 LLM 判分的核对依据(要点命中式评分,阅读表达批改已实现同款)。

## 二、解析 → 仿真 → 前端的通路(为什么解析是"依据")

| 环节 | 现状 | 解析接入后 |
|---|---|---|
| 仿真生成 prompt | 只注入 KP 名称 | 注入 `clue_type/干扰项错因/体裁要点` → 变体保真度可控(同构念·同线索类型·同干扰策略) |
| 派生校验 | 无 | 生成的阅读变体同样跑「定位句子串校验」,不合格弃 |
| 前端学习策略 | 无分题型方法论 | 按题型聚合解析:阅读=「技能×定位句训练」卡;词法=「判定线索识别」卡;作文=「体裁要点清单+量规自评」卡。练习反馈里 explanation 旁可高亮定位句 |

## 三、人机逐题调试确认工作流(用户点名的关键环节)

**阶段0 · 校准(先小后大,防提示词漂移)**
- 每题型抽 **20 题**(近5年、已有 KP 标注的优先)→ LLM 按上述 JSON schema 出解析 → admin 逐题人工改/确认。
- 通过标准:**字段免修改率 ≥85%**(逐字段统计),不达标改提示词重跑该批,直到达标才放量。
- 词法/句法类因有确定性预标+受控目录,预计最先达标;阅读靠定位句机器校验兜底;作文样本少(近5年86题)可全量人工过。

**阶段1 · 放量(程序校验前置,人工只看过关件)**
- 机器自动打回:定位句非原文子串 / 枚举值非法 / KP code 不在目录 / JSON 不合 schema。
- 打回率纳入监控;人工确认沿用现有「AI 建议 → 逐题 ✓ 采纳」交互(admin 已有同款,零学习成本)。

**阶段2 · 应用与回归**
- 仿真生成注入解析字段;抽 30 组「注入解析 vs 只注入 KP 名」的生成对照,人工盲评保真度(有对照才叫科学,不做拍脑袋结论)。

## 五、风险与对策(全部有机制,不靠自觉)

| 风险 | 对策 |
|---|---|
| LLM 幻觉定位句/编造要点 | **定位句必须是原文子串**——程序校验一票否决;作文要点须能在题目要求原文找到对应 |
| 维度多→输出不稳定 | 所有分类字段**封闭枚举** + JSON schema 校验,自由文本仅 reason 类字段 |
| 提示词漂移 | 阶段0 校准门(免修改率≥85%);题型级提示词本就后台可配(system_configs,符合「运营可配置」铁律) |
| 人工吞吐瓶颈 | 机器校验前置打回 + 确定性预标托底,人工只处理过关件与边角 |
| 解析与真实考法脱节 | 解析字段全部来自测量学既有概念(构念/证据/干扰理据/量规),不自造维度 |

## 六、结论与建议起步

**可行**。三类题型三种深度,全部有:已验证的基建(受控目录/确定性预标/meta 存储/评分先例)、可程序校验的防胡说机制(子串/枚举/schema)、以及明确的人机确认流。

**建议第一刀(等批准)**:做「阅读题目层解析」试点——因为它有 884 题确定性 rc 标注做底、定位句校验最硬、且直接喂给已上线的 reading 反向生成。范围:近5年阅读题抽 20 题走阶段0 校准,产出:解析 service + 校验器 + admin 确认入口。
