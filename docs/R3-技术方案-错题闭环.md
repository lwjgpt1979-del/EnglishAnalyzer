# R3 技术方案 · 错题闭环(统一错题中心 + 练同类有源链 + 原题+N仿真判掌握)

> 依据:[重构-KP优先-需求分析.md](重构-KP优先-需求分析.md) 体系⑧ + 路线图 R3;承接 R0.5(`wrong_record`/`answer_log`/`student_kp` 窄表)、R0.3(`kp_match_service`)、R2(`platform_question` 真题派生/备选)。
> 原则不变:不破坏现有学生前台(错题复习/SM-2 仍读 `wrong_questions`);R3 建 KP-First 错题中心与有源练同类链,**前台读取切换留后续**。

---

## 0. 现状关键事实(已核实)
- 错题**两处存**:`wrong_questions`(单题上传/仿真练习做错/AI 练习做错;含 SM-2 复习字段、is_mastered/mastery_source)+ `user_paper_questions.is_wrong`(整卷错题)。错题↔KP 在 `wrong_question_knowledge_points` → **旧 `knowledge_points`**。
- 掌握度汇聚:四渠道都调 `kp_mastery_service.upsert_mastery()` 写 `student_kp_mastery`(kp_key 字符串 / correct·wrong_count / sources[])。**KP 级无统一"判掌握"**(只有错题行级 is_mastered)。
- **练同类(D-165)= AI 直生**:`practice_for_question → practice_service.generate_practice_questions` → DeepSeek 直生到 `ai_questions`,**无 parent_real_id、未用 platform_question**(违 R2 铁律)。
- R0.5 `wrong_record`/`answer_log`/`student_kp` + R2 `platform_question` 已建**未用**;`kp_match_service` 独立、错题系统未接。

---

## 1. R3 范围圈定【决策后扩大:全链路切到 KP-First】
**本期做**:
1. **统一错题事件中心 `wrong_record`**(决策 R3-A):各渠道做错 → 经**一个收口入口**写 `wrong_record`(指向 platform/uploaded 题 + 定位 `node_id`)。`wrong_record` **补 SM-2 字段**(承接复习)。单题拍照错题 → 落 `uploaded_question(student)` 再进中心(使其可被中心统一承载)。
2. **练同类改走有源链**(决策 R3-B):错题 → `node` → `platform_question` 真题母题 → **派生仿真**;无真题 → **KP 直生备选**。替换 AI 直生。
3. **原题 + N 仿真判掌握**(决策 R3-C):做对"原题 + N 仿真"(N 可配,默认 3)→ `wrong_record.status=mastered` + 回写 `student_kp`(+ 同步 `student_kp_mastery` 台账);作答落 `answer_log`。
4. **前台错题复习/SM-2 切到 `wrong_record`**(决策 R3-D 本期切):复习队列/提交/SM-2 调度读写 `wrong_record`;错题复习 API 改读 `wrong_record`(尽量保返回形状)。
5. **整卷管线 KP 归类切 `kp_match_service`**(决策 R3-E 本期切):`run_paper_pipeline` 的 `classify_kps→get_or_create(旧auto_)` → `match_kp`(命中 node / 候选);整卷错题正式写 `wrong_record`。

> 系统未上线,旧错题数据为测试数据 → 允许大胆切换;旧 `wrong_questions` 表保留(OCR/AI 诊断仍用其富字段),但**复习/收口/练同类/判掌握以 `wrong_record` 为新主**。

## 2. 新增 / 改动

### 2.1 错题中心写入 `wrong_center_service.py`(新)
- `record_wrong(db, *, student_id, q_scope, question_id, node_id, is_original=True)`:upsert `wrong_record`(同 student+question 已存在则保持 open);定位 node。统一收口入口,各渠道改调它(**与旧 wrong_questions 写入并存,不拆旧**)。
- `list_open_wrongs(db, *, student_id, node_id=None)`:查未掌握错题(KP-First 视图)。

### 2.2 有源练同类 `wrong_practice_service.py`(新)
- `practice_same_kind(db, *, student_id, node_id, count=N)`:
  1. 查该 `node` 的 `platform_question` 真题(type='real', published)。
  2. 有真题 → 取一道作母题 → `platform_question_service.generate_sim_from_real`(派生仿真,继承 KP)。
  3. 无真题 → `generate_fallback_sim`(is_fallback 备选)。
  4. 返回平台题(原题真题 + N 仿真)供作答;**不再 AI 直生 ai_questions**。
- 改 `user_paper_service.practice_for_question`:KP 名 → `kp_match_service` 命中 node → 调 `practice_same_kind`(命中)/ 提示待补真题。**旧 AI 直生入口保留兼容但不再是主路径**。

### 2.3 判掌握 + 回写 `mastery_judge_service.py`(新)
- `log_answer(db, *, student_id, q_scope, question_id, node_id, is_correct)`:写 `answer_log`(R0.5 分区表);更新 `student_kp`(practice_count/wrong_count/last_practice_at)。
- `judge_and_mark(db, *, student_id, node_id, original_question_id, required_sims=N)`:原题 + 最近 N 仿真**全对** → `wrong_record.status=mastered`+mastered_at;`student_kp.mastery=1.0`;同步 `student_kp_mastery`(复用 `upsert_mastery`,兼容)。N 后台可配(`settings` 或 system_configs)。
- 掌握口径与回写**双轨**:`student_kp`(新,node 维度)为新主、`student_kp_mastery`(旧,kp_key)继续兼容供现有诊断/前台。

### 2.4 Admin/配置
- N(判掌握所需仿真数)后台可配(复用现有 system_configs / settings 模式)。
- (可选)错题中心查询 admin/学生 API:`GET /wrong-center?node_id=`(KP-First 视图)。

### 2.5 不动
- `wrong_questions` 表与其 OCR/SM-2/复习/前台**全部保留**;`student_kp_mastery` 台账保留;诊断报告数据源不变。

## 3. 决策点【✅ 已定 2026-06-17】
- **R3-A = `wrong_record` 新窄表**作 KP-First 错题中心(指 platform/uploaded + node;补 SM-2 字段)。旧 `wrong_questions` 并存供 OCR/诊断富字段。
- **R3-B = 练同类有源链**(node→真题派生 / 无真题则 KP 直生备选),替换 AI 直生。
- **R3-C = 原题 + N 仿真全对判掌握**(N 可配默认 3),回写 `student_kp` + 同步 `student_kp_mastery`。
- **R3-D = 本期切**前台错题复习/SM-2 读取到 `wrong_record`。
- **R3-E = 本期切**整卷管线 KP 归类到 `kp_match_service` + 整卷错题写 `wrong_record`。
