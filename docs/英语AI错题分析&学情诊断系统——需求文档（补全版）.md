## 一、项目核心定位

一款面向中小学英语学生、任课老师、线下合作机构的AI学情诊断与错题管理SaaS系统。项目依托成熟的中小学英语学科学习体系，以试卷复盘、错题深度拆解为核心载体，通过AI智能识别试卷、精准匹配学科知识点，定位学生知识漏洞、归纳个人错题规律，自动生成学情诊断报告与个性化提分方案。同时赋能校内教师、线下合作机构轻量化开展精准教学、定制化辅导，解决教与学的核心痛点，最终通过阶梯式学生会员付费体系实现长期商业变现。

**项目核心价值：**
- **学生端**：解决盲目刷题、泛读无效、错题不复盘、知识漏洞模糊、成绩难以提升的学习痛点
- **老师端**：解决学情分析耗时费力、学生问题定位笼统、无法针对性出卷训练的教学痛点
- **机构端**：解决无标准化学情诊断工具、教学服务无差异化、难以精准提分的经营痛点

## 二、系统组织架构与权限体系

### 1. 机构分类定义

- **自营机构**：由平台自主运营，全权负责用户拓展、教学服务落地、会员产品售卖、用户后续维护等全流程工作。
- **非自营合作机构**：第三方线下实体入驻合作，核心包含中小学学校、线下英语培训机构、校园文具店等场景，依托平台系统能力开展获客与教学服务。

### 2. 层级架构与用户关系

系统固定层级架构：**独立入驻机构 → 下辖多名任课老师 → 每名老师管理多名学生 → 每名学生可关联最多4位亲人账号**

亲人可实时同步查看学生错题数据、学情报告、薄弱知识点与学习进度，实现家校共育、家庭监督联动。

**核心权限规则**：所有入驻机构（自营+非自营）均可自主定制专属教学服务包、自主开展线下获客运营、独立管理旗下师生所有数据，平台仅提供系统技术支撑、基础功能维护与统一运营规则，不干预机构自主经营。

### 3. 师生绑定分层规则（三场景）

**场景一：线下培训机构（团队子账号模式）**
- 培训机构批量采购团队账号套餐（支持自定义规格：5/20个子账号等多档位）
- 机构名下所有子账号（老师账号）由机构后台统一创建、统一分配
- 机构名下学生强制归属机构指定授课老师，学生无自主换绑、自主邀请老师权限
- 所有学情数据归属机构统一管理，保证教学团队闭环管理

**场景二：中小学学校（双开通模式）**
- 方式①：学校整体批量采购机构账号，统一分配全校老师子账号、纳入学校机构体系 → 学生属于**机构学生**，老师由学校统一分配，学生**不可自主换绑老师**
- 方式②：学生个人单独购买会员后，通过短信邀请方式绑定认证老师，绑定后学情数据纳入对应学校统计体系 → 学生属于**学校自由生**，可自主换绑同校认证老师，老师可查看其数据，但学生对换绑老师有完整自主权

**方式①与方式②的核心区别**：

| 对比项 | 方式①（学校整体采购） | 方式②（学生自行购买） |
|--------|---------------------|---------------------|
| 账号归属 | 机构学生，受学校管理约束 | 学校自由生，归属宽松 |
| 老师分配 | 学校统一指派，不可自主更换 | 通过短信邀请绑定认证老师，**可换绑**同校认证老师 |
| 数据可见 | 学校机构层+老师均可见 | 仅绑定老师可见，学校层可见汇总统计 |
| 学情报告 | 纳入班级/学校综合报告 | 纳入老师多学生汇总报告，不单独进学校管理池 |

**老师认证机制补充说明**：
- 老师申请入驻时需提交所在学校名称、教师证编号或学校开具的在职证明
- 平台后台人工审核通过后，老师账号获得"认证老师"标识，并关联对应学校
- 学生绑定认证老师有两条路径：
  - **主路径（学生发起）**：学生在 App 输入老师手机号 → 系统向该号码发送邀请短信（含确认链接，48小时有效）→ 老师点击链接确认绑定；若老师尚未注册，短信引导注册后自动完成绑定
  - **辅助路径（老师发起）**：老师在 App 生成专属绑定链接（7天有效）→ 在微信/家长群分享 → 学生点击后确认绑定
  - 两条路径均需老师主动确认，老师不会被动接单；仅认证老师可接受学生绑定申请
  - 学生也可按学校名称/老师姓名辅助搜索，用于确认老师身份信息，但不能直接通过搜索发起绑定
- 同一学校的认证老师超过3位后，系统向**该校所有已认证老师**推送站内通知：「您所在学校已有 X 位认证老师在平台，学校可整体申请机构账号以统一管理师生数据、享受批量采购优惠，点击了解→」；同时在平台超管后台将该学校标记为「潜在升级机构」，运营人员可主动跟进对接

**场景三：无机构零散学生（自由绑定模式）**
- 未加入任何学校的纯零散学生，可自主购买会员，主动邀请平台认证老师完成一对一绑定
- 归属对应老师单独管理，不入机构体系，仅享受师生一对一学情辅导服务

## 三、底层核心英语学科体系

### 1. 学科核心三大模块（强关联联动）

单词、句子、语法为英语学习底层核心，三者深度联动、互为支撑，系统所有错题拆解均围绕三者展开：单词支撑句子理解，句子结构依托语法规则，真题考点全部落地于三大模块，杜绝碎片化学习。

### 2. AI仿真题库体系（以真题为参照生成）

平台内置题库不直接使用、搬运或存储真题原题，而是以历年中小学英语真题为参照基准，从多个维度深度分析真题规律，再由AI生成全新题目，构建覆盖各年级学期的仿真题库。

**真题参照的五个核心维度**：

| 参照维度 | 说明 |
|----------|------|
| 知识点分布 | 分析真题各单元、各考点的出题频率与权重 |
| 题型结构 | 还原真题的题型比例（单选/填空/阅读/作文各占比）、题量分布与卷面结构 |
| 难度梯度 | 参照真题易/中/难三档难度配比，生成对应梯度题目 |
| 高频考点 | 提炼真题反复出现的词汇、固定搭配、语法点作为AI出题侧重点 |
| 干扰项逻辑 | 学习真题命题中常见干扰项的设置规律，生成具备真实迷惑性的选项 |

**AI生成题目的题型覆盖**：覆盖听力理解、单选题、填空题、阅读理解、英语作文全题型，完整对标统考卷面结构。

**核心突破考点**：以真题高频词汇、高频语法点为AI出题侧重口，语法专项聚焦时态、定状补、句式结构等核心易错模块。

**题型应试逻辑**：单选侧重词汇辨析与句法规则；阅读侧重语境理解、长难句拆解；作文依托标准化题型模板与通用套话。

> **说明**：学生上传的是自己在学校获得的真实试卷（供AI识别并分析错题），平台内置题库中的题目均为AI依照真题规律生成的全新原创题，不存在版权侵权问题。

### 3. 支持教材版本说明

系统优先覆盖全国主流英语教材版本，按需扩展：

| 优先级 | 教材版本 | 覆盖范围 |
|--------|----------|----------|
| P0 | 人教版（PEP） | 小学1-6年级、初中7-9年级 |
| P0 | 外研版 | 小学3-6年级、初中7-9年级 |
| P1 | 苏教版 | 小学1-6年级 |
| P1 | 北师大版 | 初中7-9年级 |
| P2 | 其他省编版本 | 按市场需求迭代扩展 |

> 每新增一个教材版本均需完整录入对应知识点体系，上线前需内容团队验收。

### 4.1 未成年人账号保护机制

依据《未成年人网络保护条例》（2023年9月实施），平台须对未成年用户（18岁以下）实施差异化保护策略。

#### 年龄核验方式

注册时要求学生填写出生年份，系统根据当前年份自动计算年龄：

| 年龄段 | 注册限制 |
|--------|---------|
| < 14岁 | 注册时必须填写监护人手机号；系统向监护人发送授权验证码，监护人验证通过后账号方可激活 |
| 14-17岁 | 允许独立注册；首次购买会员时须额外勾选「我已告知监护人并获得同意」（独立复选框，服务端留存记录含时间戳） |
| ≥ 18岁 | 正常注册流程，无额外限制 |

> 平台当前不接入公安系统人脸识别或身份证实名认证，年龄数据为用户自填声明。若发生「未成年人未经授权购买」申诉，客服按 4.7.4 节流程核实实际证件材料。

#### 未成年用户的特殊保护规则

| 限制项 | 规则 |
|--------|------|
| 数据对外共享 | 未成年人学情数据不得传输至任何第三方（广告商、数据公司），仅限绑定老师和亲人账号查看 |
| 营销推送 | 对14岁以下用户不推送任何商业促销通知（会员到期提醒除外） |
| 隐私默认设置 | 未成年账号默认关闭「对外展示学习排名」等社交功能 |
| 购买提醒 | 单笔消费默认同步通知至已绑定亲人账号（若无绑定亲人，仅通知本人） |

### 4.2 账号注销与数据保留规则

依据《个人信息保护法》第47条，用户有权申请注销账号并请求删除个人信息。

#### 注销入口与流程

```
入口：我的 → 账号设置 → 注销账号

Step 1：申请确认
  └── 展示注销后果告知（历史数据不可恢复、剩余会员时长不退款）
  └── 需输入手机验证码二次确认身份

Step 2：30天冷静期
  └── 账号进入「待注销」状态，功能暂停但数据保留
  └── 冷静期内可随时登录取消注销申请
  └── 冷静期结束后系统自动执行注销

Step 3：注销执行
  └── 个人可识别信息（姓名、手机号、头像）在数据库中匿名化处理
  └── 学情数据转为匿名脱敏数据，用于平台数据统计，不含个人标识
  └── 订单与支付记录按财务合规要求保留5年（脱敏存档，不可关联至个人）
```

#### 特殊情形处理

| 情形 | 处理规则 |
|------|---------|
| 机构学生申请注销 | 注销前通知机构管理员；机构30天内可将该学生从机构数据中移除并保留机构侧汇总统计；机构不操作则30天后按正常流程注销 |
| 有效会员期内申请注销 | 剩余会员时长不退款（适用超7天无退款规则），账号注销后会员权益同时终止 |
| 7天内申请注销 | 视同7天内退款申请，按退款规则处理后再执行注销 |
| 亲人账号注销 | 仅删除亲人自身账号，不影响绑定学生账号数据；学生侧自动解除该亲人绑定关系 |

## 四B、系统核心功能流程

### 核心业务主线

> 学生/老师上传英语试卷 → AI智能识别阅卷归集错题 → 匹配底层英语学科体系 → 逐题型拆解错题根源 → 精准定位个人知识漏洞 → 归纳专属错题规律 → 生成学情诊断报告 + 个性化补强方案 + 定制试卷

---

### 功能模块 1：试卷AI智能识别与错题采集

支持学生、任课老师上传纸质/电子英语真题试卷，系统AI全自动识别：
- 试题原题内容（印刷体）
- 学生作答内容（手写体，含选择题标记、填空作答、作文）
- 错题题号自动标记

**上传格式支持**：拍照图片（JPG/PNG）、扫描PDF、电子版试卷（Word/PDF）

**识别准确率基准要求**：
- 印刷体题目识别准确率 ≥ 99%
- 学生手写作答识别准确率 ≥ 90%
- 无法识别内容自动提示学生手动确认/修正，不允许静默丢弃

---

#### 1.1 混合内容处理架构（核心技术方案）

学生做完的试卷是**印刷体题目与手写作答混合在同一张图**上的，不能直接将整图送入单一 OCR 引擎。系统采用「图像预处理 → 版面分析分区 → 分区域 OCR → 结果融合」四步流水线处理：

```
学生上传试卷图片（拍照/扫描）
         │
         ▼
【步骤 1：图像预处理】
  ├── 自动检测并矫正拍照倾斜（透视变换纠偏）
  ├── 光线增强 / 去噪 / 二值化
  └── 分辨率标准化（低于 300dpi 提示重拍）
         │
         ▼
【步骤 2：版面分析分区】  ← 关键步骤
  使用版面检测模型（PaddleLayout / DocLayout-YOLO）
  自动识别并标注各区域类型：
  ├── 题目文字区（印刷体）：题目、题干、阅读语篇
  ├── 选项区（印刷体）：A/B/C/D 选项文字
  ├── 选择题作答区（手写体）：学生圈选/勾选的标记
  ├── 填空题作答区（手写体）：学生填写的词/短语
  ├── 作文区（手写体）：大段连续手写内容
  └── 批改标注区（忽略）：老师红笔批注，不参与识别
         │
         ▼
【步骤 3：分区域 OCR（对应技术选型）】
  ├── 印刷体区域 → 阿里云 OCR（读光高精度，>99.7%）
  │     └── 备选：百度 OCR（通用高精版，>99%）
  └── 手写体区域 → 腾讯云 OCR 手写识别（>90%，中文实测 94.7%）
        └── 备选：Google Document AI（英文手写实测 92-95%）
         │
         ▼
【步骤 4：结果融合与题目对齐】
  按空间坐标将各区域识别结果与题目结构对齐：
  ├── 每道题的题号 + 题目内容 + 学生作答内容 → 组合为结构化数据
  ├── 对比标准答案，标记错题
  └── 低置信度区域高亮提示学生手动确认
         │
         ▼
【步骤 5：送入 LLM 诊断层】
  结构化文本（题目 + 学生答案 + 错误标记）→ DeepSeek/Claude 错因分析
```

#### 1.2 各题型作答识别的特殊处理

| 题型 | 学生作答形式 | 识别策略 |
|------|------------|---------|
| 选择题 | 在选项旁圈/勾/填字母 | 版面分析定位选项区，检测手写标记位置判断选了哪个选项；若标记模糊，提示学生确认 |
| 填空题 | 在横线/方格内填写词句 | 精准定位填空框坐标，仅对框内区域做手写 OCR |
| 阅读理解 | 在题号旁圈选字母 | 同选择题处理逻辑 |
| 作文 | 大段连续手写 | 整块作文区域送手写 OCR，逐行识别后拼接 |
| 听力填空 | 在空白处填关键词 | 同填空题处理逻辑 |

#### 1.3 图像质量兜底机制

- **拍照倾斜 > 15°**：提示"图片倾斜过大，请重新拍摄或调整角度"
- **分辨率过低**：提示"图片不够清晰，建议在光线充足处重拍"
- **手写识别置信度 < 70%**：对应位置高亮标黄，提示"此处识别不确定，请确认或手动输入"
- **整体识别失败**（如图片严重模糊）：引导学生重新上传，不进入分析流程
- **电子版试卷（Word/PDF）**：跳过图像预处理和版面分析，直接解析文档结构提取文字，精度更高

#### 1.4 网络与服务异常处理

**上传与识别各阶段超时策略**：

| 阶段 | 超时阈值 | 用户侧体验 | 系统侧处理 |
|------|---------|----------|----------|
| 图片上传 | 30秒 | 提示"上传超时，请检查网络后重试"；已选图片保留，无需重新选图 | 重试最多2次，仍失败则终止 |
| OCR识别 | 60秒 | 提示"识别耗时较长，已在后台处理，完成后将通知您" | 转为异步任务，完成后推送小程序通知 |
| LLM诊断 | 90秒 | 同OCR | 同OCR，异步完成后通知 |

**OCR服务商降级策略**：
- 主选OCR（阿里云印刷体 / 腾讯云手写体）返回错误码或超时 → 自动切换至备选（百度OCR / Google Document AI），切换对用户透明无感知
- 主选＋备选均不可用 → 提示"识别服务暂时繁忙，请稍后重试"，同时写入运营故障工单

**运营报警触发阈值**：

| 监控指标 | 报警阈值 | 报警渠道 |
|---------|---------|---------|
| 整体识别失败率 | 超过 5%（滑动1小时窗口）| 企业微信报警 + 技术负责人短信 |
| 手写区域手动修正率 | 单日超过 15% | 企业微信通知技术团队评估OCR质量 |
| OCR API平均响应时间 | 超过 8秒 | 企业微信报警 |
| 备选服务切换次数 | 单日超过 20次 | 企业微信报警（主选服务可能不稳定）|

**用户重试引导**：
- 识别失败时提供折叠式"拍照建议"（用户可展开）：光线充足、试卷平放、镜头垂直、避免手指遮挡、图片大小建议1-10MB
- 连续失败3次：提示"识别持续失败，可联系客服协助处理"并附客服入口（见 13.1）
- 有电子版时引导优先上传PDF/Word（"电子版识别精度更高，建议优先使用"）

### 功能模块 2：全题型AI深度错题诊断

区别于传统单纯归集错题的错题本工具，系统针对每道错题精准拆解根本出错原因：

**单选题**：
- 精准区分：高频词汇不熟、固定搭配记忆错误、语法知识点漏洞、命题干扰项误判、基础句法理解偏差
- 输出：错误原因标签 + 对应课本知识点溯源 + 同类题型推荐

**阅读理解题**：
- 逐题拆解：上下文语境理解偏差、长难句无法拆解、语法结构模糊、细节定位失误、解题思路偏差
- 输出：题目解析路径 + 文中关键句标注 + 解题方法归纳

**填空题/语法题**：
- 精准归类：时态错误、定状补混淆、句式结构错误、主谓一致问题
- 输出：语法规则说明 + 错误类型标签 + 专项语法训练推荐

**英语作文**：
- 智能识别：句式单一、语法错误、词汇匮乏、逻辑不通、模板套用不当、中式表达
- 输出：逐句批注 + 优化版本对比展示（详见功能模块 5A）

### 功能模块 2B：错题复盘完整操作流程

> 错题复盘是学生日常最高频的核心操作。区别于「AI初次诊断」（系统自动完成），复盘是学生主动消化、练习、验证掌握的闭环过程。

**触发入口**：错题列表 → 点击任意错题 → 进入复盘详情页

```
Step 1：复盘详情页
  ├── 展示：原题目 + 学生原答案（标红） + 正确答案（标绿）
  ├── 展示：AI错误原因诊断（错因标签 + 详细说明）
  ├── 展示：关联知识点（点击可跳转知识点说明页）
  └── 操作按钮：「练习同类题」 / 「标记已掌握」 / 「下次再看」

Step 2A：练习同类题（推荐路径）
  └── 系统从AI仿真题库调取：同知识点 + 同题型 + 相似难度的题目（3-5道）
  └── 学生逐题作答
  └── 作答完成后展示结果：
        ├── 全部答对 → 提示「此知识点已巩固」，错题状态自动更新为「已复盘（验证通过）」
        ├── 仍有错误 → 提示「仍需继续练习」，错题状态保持「待复盘」，新错误加入错题库
        └── 系统将该知识点自动列入下次补强推荐计划

Step 2B：直接标记已掌握（跳过练习）
  └── 学生可手动点击「已掌握」
  └── 需二次确认弹窗：「确认标记？标记后此题将移出待复盘列表」
  └── 状态更新为「已复盘（手动）」，与「验证通过」分开记录，老师端可区分查看

Step 2C：下次再看
  └── 保持「待复盘」状态
  └── 学生可设置复盘提醒：明天 / 3天后 / 下周（三选一）
```

**错题状态体系**：

| 状态 | 触发方式 | 说明 |
|------|---------|------|
| 待复盘 | AI分析后自动生成 | 尚未复盘，默认状态 |
| 已复盘（验证通过） | 同类练习全部答对后系统自动更新 | 已通过练习验证掌握，可靠性高 |
| 已复盘（手动） | 学生手动标记 | 学生声称已理解，无题目验证 |
| 重新待复盘 | 已复盘后在新试卷中再次出错 | 知识点回退，优先安排复盘 |

**老师视角**：
- 老师在学生错题详情中可查看每道题的复盘状态及复盘方式（验证通过 vs 手动标记）
- 超过14天未复盘的错题，系统在老师端该学生列表中标红提醒

### 功能模块 5：学期教材对标专属服务包（核心产品）

平台核心标准化服务产品为按学期、按教材版本拆分的英语专项服务包。服务包内置的练习题均为AI依照对应学期真题规律生成的原创仿真题，不使用真题原题，同时完整还原真题的题型结构、知识点覆盖、难度配比。

- **知识点体系**：对应学期教材各单元核心知识点结构树（单词/固定搭配/语法重难点/单元考点）

- **教材与题目强关联**：服务包内每道AI生成题均标注对应教材版本、年级、学期、单元及知识点，学生做错后可直接溯源课本考点

**适配学生自学场景**：学生单独购买对应学期服务包后，可在平台内刷取AI仿真题，刷题错误自动归集至个人错题库，并溯源对应课本知识点，形成贴合本学期进度的查漏补缺路径。

**适配教学辅导场景**：老师/机构依托服务包题库开展同步教学，为学生布置对应单元的AI仿真练习题，教学节奏完全贴合校内教材进度。

**与学生上传真题的联动**：学生在校获得的真实试卷可上传至平台，AI分析错题后，将错误知识点与服务包知识点体系自动对标，推荐服务包内对应的AI仿真题进行专项补强，形成"真题暴露漏洞→AI仿真题精准补强"的学习闭环。

步骤5：分发给学生
  ├── 指定学生：发送给单名或多名学生，学生端收到通知
  ├── 完成时限：设置作答截止时间（可选）
  └── 分享方式：小程序内推送 / 生成试卷图片供打印

步骤6：批改与反馈
  ├── 客观题：系统自动批改并归集错题
  ├── 主观题（作文）：老师手动批改或启用AI批改
  └── 批改完成后，错题自动进入学生个人错题库，触发学情数据更新
```

#### 老师自定义题目内容审核规则

老师上传自定义题目后，系统立即触发内容审核（依据 5.6 敏感词与内容审核规则）：

| 上传类型 | 审核方式 | 通过 | 未通过 |
|---------|---------|------|-------|
| 文字录入 | 自动敏感词过滤（实时，秒级）| 题目状态「已通过」，可纳入试卷 | 阻断录入，标红违规内容并提示修改 |
| 图片上传 | 自动图像内容检测（实时）；疑似违规转人工审核（24小时内）| 同上 | 明显违规直接阻断；疑似违规标「审核中」，结果出来后通知老师 |

**审核中状态体验**：
- 题目列表标注「审核中」，不影响老师继续配置其他题目或平台题库题目
- 审核通过：状态更新为「已通过」，老师收到铃铛通知，可立即纳入试卷
- 审核不通过：标注「未通过」并说明原因，老师修改后可重新提交
- **分发前须全部自定义题目通过审核**，「步骤5 分发」按钮在有未通过/审核中题目时置灰

### 功能模块 5B-S：学生端接收与完成定制试卷

> 本模块为功能模块 5B 的学生侧对称模块。老师通过 5B 创建并下发定制试卷后，学生在此模块接收、作答并查看批改结果。

#### 入口

- **错题库 Tab → 老师任务** 子页（见四E 错题库 Tab 结构）
- **首页通知卡片**：老师下发任务后，学生首页出现「新任务待完成」提示卡，点击直达任务详情

#### 操作流程

```
步骤1：接收通知
  ├── 铃铛图标收到「老师布置了新试卷任务」推送
  └── 首页出现任务提示卡（显示：任务名称 / 截止时间 / 出题老师）

步骤2：进入任务列表（错题库 Tab → 老师任务）
  ├── 待完成任务：显示任务名称 / 布置时间 / 截止时间 / 状态（待完成/已提交/已批改）
  └── 已完成任务：按时间倒序排列，可查看批改详情

步骤3：开始作答
  ├── 点击任务 → 进入试卷详情页（显示试卷说明 / 题目数量 / 总分 / 截止时间）
  ├── 点击「开始作答」→ 进入在线作答界面
  └── 作答模式：逐题作答，支持标记疑难题，不限制单次作答时间

步骤4：提交试卷
  ├── 全部作答后点击「提交」→ 二次确认弹窗（「确认提交？未作答题目将计为错误」）
  ├── 客观题：提交后系统立即自动批改，错题自动归入错题库
  └── 主观题（作文）：标记为「待老师批改」，不立即出分

步骤5：查看结果
  ├── 客观题部分：立即展示得分 / 正确率 / 错题分布（知识点维度）
  ├── 作文部分：显示「老师批改中」状态，批改完成后收到铃铛通知
  └── 完整批改报告：老师全部批改完成后可在「任务详情」页查看完整分析报告

步骤6：错题复盘
  └── 定制试卷错题与普通上传试卷错题统一归入错题库，复盘流程相同
```

#### 任务列表字段

| 字段 | 说明 |
|------|------|
| 任务名称 | 老师创建时填写的试卷名称 |
| 布置时间 | 老师下发任务的时间 |
| 截止时间 | 老师设置的作答截止时间（若未设置则显示「无截止」） |
| 状态 | 待完成 / 已提交（待批改）/ 已批改 |
| 得分 | 批改完成后显示（作文未批改时显示「—」） |

#### 会员限制

- 接收并完成老师布置的定制试卷：**全档位学生均可**（基础/Pro/ProMax），属于老师主动推送，不受学生档位限制

#### 截止时间到达后的处理规则

| 情形 | 系统行为 |
|------|---------|
| 截止时间到达，学生**已提交** | 任务状态保持「已提交（待批改）」，不受影响 |
| 截止时间到达，学生**未提交** | 任务状态变为「已截止（未提交）」，学生不可再提交 |
| 截止时间到达时**正在作答中** | 倒计时归零后自动提交当前已作答内容，未作答题目留空（不自动计错，老师批改时可见空答标注）|

**老师侧通知**：截止时间到达后，向老师推送铃铛通知「[任务名称] 已截止：X人已提交，Y人未提交」；老师可在任务管理页一键查看未提交学生名单。

**补交机制**：老师可在任务详情页为特定未提交学生单独延长截止时间（每次最多延长7天），系统向该学生推送「老师已为你延长截止时间至 [新截止时间]，请尽快完成」通知。未使用补交机会的任务在30天后自动归档。

```
步骤1：配置参数 → 点击「生成试卷」
  └── AI 生成时间约10-30秒，显示生成进度条

步骤4：提交与报告
  ├── 客观题：立即出分，错题归入错题库
  ├── 作文：AI 自动批改（ProMax 专属能力），约2-5分钟出结果

### 功能模块 6：听力跟读训练模块

#### 6.1 素材来源与版权说明

平台听力素材不使用任何真实考试听力录音（版权归各省教育局/出版社），而是以真题听力为参照，采用以下方式生成平台专属素材：

- **AI 配音生成**：由 TTS（文字转语音）引擎生成标准英式/美式发音朗读音频，对标真题听力的语速、语调、题型结构
- **素材类型覆盖**：对话类（两人/多人短对话）、独白类（短文听力）、图片描述类，完整覆盖中小学统考听力题型
- **语速分级**：慢速（0.75x，适合初学）/ 标准速（1.0x）/ 真题速（1.1x，对标真实考试语速），学生可切换

#### 6.2 精听与泛听两种模式

**精听模式**（主要学习方式，会员核心权益）：
```
Step 1：题目预览
  └── 展示听力题目和选项，学生先阅读题目再开始听音

Step 2：首次聆听
  └── 播放完整音频（不可暂停），完成答题

Step 3：对照答案
  └── 展示正确答案，学生自查哪题答错

Step 4：精细回听（核心步骤）
  └── 错题对应音频片段单独提取，支持循环播放
  └── 同步展示听力原文（逐句高亮对应播放位置）
  └── 难词/难句支持点击展开释义与语法解析

Step 5：跟读练习（见 6.3）
  └── 精听后进入该段落的跟读训练
```

**泛听模式**（ProMax 额外开放）：
- 播放完整听力音频，不展示原文，仅用于训练整体理解能力
- 完成后对照答案，不提供逐句解析
- 适合已掌握基础的学生做综合训练

#### 6.3 跟读评分逻辑

**触发时机**：精听完成后，可对任意句子发起跟读；或在词力通学习单词时，对例句发起跟读。

**跟读流程**：
```
Step 1：示范播放
  └── 播放标准发音（可调速），学生跟着默读感受节奏

Step 2：学生录音
  └── 点击"开始跟读"后录音，自动检测停顿结束（或手动点结束）

Step 3：AI 评分（5秒内返回）
  └── 发音准确度：对比标准音素，标注每个单词的发音准确率
  └── 语速匹配度：与标准语速的偏差比
  └── 连读/弱读：识别是否掌握英语连读规则（Pro/ProMax 开放）
  └── 综合得分：100分制，分级（60以下/60-80/80-90/90+）

Step 4：逐词反馈
  └── 发音得分低的单词标红，点击可对比"标准发音 vs 我的发音"
  └── 给出改进提示（如"注意 th 的齿间音"）

Step 5：重跟
  └── 支持无限次重跟直到满意，最高分自动保存
```

**跟读评分技术方案**：调用语音评测 API（如科大讯飞语音评测 / 腾讯云语音评测），输入学生录音与标准文本，返回音素级评分数据。

#### 6.4 听力错题归集

| 触发条件 | 归集内容 |
|----------|---------|
| 精听答题答错 | 错误题目 + 对应音频片段 + 原文 + 错误原因标签 |
| 跟读得分低于 60 分 | 该句子加入"跟读薄弱句库"，下次学习时优先复现 |
| 老师标注 | 老师可在学生听力报告中手动标注"需重点练习"的题目 |

**听力错题库功能**：
- 独立展示听力错题列表，按错误次数和最近错误时间排序
- 支持一键"重练此题"，重新进入精听流程
- 听力错题数据进入学情报告的"听力模块"板块

#### 6.5 各会员档位听力权限

| 权限项 | 基础会员 | Pro会员 | ProMax会员 |
|--------|---------|---------|-----------|
| 可用素材范围 | 当前绑定学期基础听力题（约20题） | 当前年级全学期所有听力题 | 全学段所有年级学期听力题 |
| 精听模式 | 开放（无逐句解析） | 开放（含逐句解析） | 开放（含逐句解析+难句语法展开） |
| 泛听模式 | 不开放 | 不开放 | 开放 |
| 跟读功能 | 不开放 | 开放（基础发音评分） | 开放（含连读/弱读检测、纠音提示） |
| 跟读次数 | — | 每日20次 | 不限次 |
| 听力错题库 | 不开放 | 开放（保留最近30天） | 开放（永久保留） |
| 语速调节 | 不开放 | 慢速/标准速 | 慢速/标准速/真题速 |

#### 消息管理规则

- **已读/未读**：消息列表区分已读（灰色）/未读（高亮），Tab 图标展示未读数红点
- **批量操作**：支持「全部标为已读」、「删除已读消息」
- **消息保留时长**：
  - 💳 会员与支付类消息：保留 **12个月**（涉及消费记录）
  - 其他类型：保留 **3个月**，超期自动清理
- **推送与站内消息的关系**：每条推送通知同步写入站内消息中心；即使用户未授权小程序subscribeMessage订阅，站内消息中心仍可正常查看历史通知，不依赖推送授权

#### B端消息中心

老师端消息中心（同一入口）额外展示：
- 学生提交试卷待批改
- 学生完成老师布置的任务
- 系统自动生成的周班级学情报告

机构管理员的系统通知通过企业微信接收（见 Module 7），机构后台同步展示企业微信通知历史记录摘要，方便不常用企业微信的管理员查漏。

### 功能模块 8：AI仿真题库自主练习

> 除「错题复盘」和「老师布置任务」外，学生可通过独立的「题库练习」入口主动进行自主练习，巩固薄弱知识点。

**入口位置**：底部导航「学习中心」Tab → 「AI题库练习」子入口；或首页「题库练习」快捷宫格（见 四E 首页布局）。底部 Tab 不设独立「题库」Tab，题库入口归属「学习中心」Tab。

#### 8.1 独立「题库练习」入口

```
Step 1：筛选练习范围
  ├── 教材版本（默认当前绑定教材，可切换）
  ├── 年级 + 学期（默认当前绑定；Pro/ProMax 可跨年级选择）
  ├── 单元（单选 / 全部）
  ├── 题型（单选 / 填空 / 阅读 / 作文 / 混合）
  ├── 难度（基础 / 标准 / 挑战 / 全部）
  └── 知识点（多选；系统标注「薄弱」的知识点排在列表顶部）

Step 2：组卷预览
  └── 显示本次共 X 题，预计完成时间约 X 分钟
  └── 按钮：「开始练习」/「重新筛选」

Step 3：答题
  └── 逐题展示（每题一屏，支持上下题切换）
  └── 支持「标记此题」（回头再看）
  └── 客观题选项提交前不显示对错

Step 4：提交与结果
  └── 展示本次得分 + 各题对错明细
  └── 错误题目自动归入个人错题库（与试卷上传错题合并统计）
  └── 提示「本次新增 X 道错题，涉及 Y 个知识点」
  └── 按钮：「查看错题详情」/「再做一组」
```

#### 8.2 从「错题复盘」触发的题库练习

此路径由 Module 2B Step 2A「练习同类题」按钮触发，与独立入口的差异：

| 对比项 | 独立入口 | 从复盘触发 |
|--------|---------|-----------|
| 题目范围 | 用户自行筛选 | 系统自动匹配：同知识点 + 同题型 + 相似难度 |
| 题目数量 | 默认10题（可调）| 固定3-5道（快速验证）|
| 完成后效果 | 错误归入错题库 | 全部答对 → 该错题状态更新为「已复盘（验证通过）」|

#### 8.3 各会员档位练习权限

> **免费用户**：每日最多练习 3 题（仅单选/填空题型），完成后展示付费引导；从「错题复盘」触发的同类题练习（Module 2B Step 2A）不对免费用户开放。以下为付费会员权限：

| 权限项 | 基础会员 | Pro会员 | ProMax会员 |
|--------|---------|---------|-----------|
| 题库范围 | 当前绑定学期当前单元（约20题）| 当前年级全学期所有题目 | 全学段跨年级题目 |
| 每日练习题数上限 | 20题 | 100题 | 不限 |
| 题型覆盖 | 单选/填空 | 全题型（含阅读）| 全题型（含作文）|
| 筛选精度 | 年级/学期/题型 | + 单元 + 难度 | + 知识点精选 |
| 从复盘触发 | 支持（计入每日限额）| 支持 | 支持（不计入限额）|

> **后台可配置**：免费用户每日 3 题 / 基础会员 20 题 / Pro 会员 100 题均在 **5.6 系统配置** 中统一管理，可随时调整，无需发版。

#### 8.4 练习数据与学情关联

- 题库练习错题与试卷上传错题合并进入同一错题库，统一管理
- 知识点掌握率同时纳入题库练习答题数据（构成知识点掌握曲线的一部分）
- 老师学生报告中展示「自主练习」独立数据板块：练习次数、总题量、错题率趋势

```

        ├── 近期概况：本周上传试卷数 / 错题数 / 词力通打卡状态

        └── 操作区：
              ├── 「布置定制试卷」→ 跳转出卷中心，自动带入该学生薄弱点数据
              ├── 「发送学习提醒」→ 向该学生推送小程序通知
              └── 「查看复盘记录」→ 查看该学生各错题的复盘状态与进度

#### 操作线B：查看班级综合报告

```
班级学情页
  └── 默认展示本周全班整体概况：

        ├── 共性薄弱知识点 Top5（>50%学生出错的知识点，标红高亮）
        └── 需关注学生列表（自动标红）：
              ├── 本周无学习记录的学生
              └── 错题率突然上升超过20%的学生
  └── 筛选项：时间范围（本周/本月/本学期）、学生分组（若管理多个班）

```

Step 3：批改主观题

  └── 学生收到「老师已批改您的试卷」小程序通知
```

#### 操作线D：管理学生绑定（自由生场景）

```
  └── 【主路径·学生发起】学生输入老师手机号 → 系统发邀请短信（48h有效）→ 老师点链接确认接受 / 忽略

### 老师端平台功能使用限额

老师账号按认证状态与归属关系分为三类，各类权限与使用限额不同，以防止免费账号盗刷平台 AI 资源：

#### 认证状态与类型

| 类型 | 说明 |
|------|------|
| **未认证（审核等待期）** | 已注册，认证申请审核中（1-3 个工作日）|
| **已认证·个人老师** | 认证通过，无机构挂靠，通过场景三与散学生自由绑定 |
| **已认证·机构老师** | 认证通过，归属机构（场景一培训机构 / 场景二学校），权限由机构套餐决定 |

#### 各类权限与限额对比

| 权限项 | 未认证老师 | 已认证·个人老师 | 已认证·机构老师 |
|--------|----------|--------------|--------------|
| 绑定/接受学生 | **不可** | 最多同时绑定 **50 名**学生 | 由机构套餐决定，无个人上限 |
| 查看学生学情报告 | **不可**（仅可浏览示例数据）| **可以**（名下学生全量）| **可以** |
| 查看班级综合报告 | **不可** | **可以** | **可以** |
| 创建定制试卷（5B）| **不可** | 每月最多生成 **10 份** | 由机构套餐统一配置 |
| AI 作文批改（5B 批改）| **不可** | 每月最多 **20 次** AI 批改 | 由机构套餐统一配置 |
| 发送学习提醒 | **不可** | **可以**（不计入额度）| **可以** |
| 布置任务/跟踪批改 | **不可** | **可以**（计入出卷月度额度）| **可以** |

#### 个人老师月度额度说明

- **重置时间**：每月 1 日 0:00 自动重置出卷次数与 AI 批改次数
- **额度用尽提示**：出卷按钮置灰，提示「本月出卷额度已用完，下月 1 日恢复；如需更多额度，可联系客服升级机构账号」
- **防盗刷逻辑**：未认证老师不触发任何 AI 资源消耗，审核期间仅可浏览示例内容；认证通过前所有 AI 相关操作按钮不可见

> **后台可配置**：上表所有数字（绑定上限 50 名 / 月出卷 10 份 / 月AI批改 20 次 / 预警阈值 20%）均在 **5.6 系统配置** 中统一管理，可随时调整，无需发版；调整后自下月 1 日重置时生效。

#### 机构老师额度说明

机构老师不受个人额度约束，出卷 / AI 批改次数限额由机构购买的套餐类型统一配置（见 9.1 机构账号套餐）。机构管理员可在后台配置各老师的资源分配上限（如限制某老师每月最多出 30 份卷），未配置时默认使用机构套餐总额度，先到先得。

> **个人老师免费说明**：已认证个人老师使用平台不收费，平台通过其带来的学生付费会员实现变现。月度出卷/批改限额设计旨在区分轻量个人使用与规模商用场景——若一名个人老师每月需出超过10份试卷，说明其业务规模已适合升级为机构账号。

## 四D、亲人账号完整操作流程

> 亲人账号是平台家庭联动体系的核心，支持学生家长或亲属实时同步查看学情、直接代付会员费用，形成家校联动闭环。

### 亲人端小程序导航（Tab Bar）

亲人端采用底部 3-Tab 简化导航，聚焦「查看学情」和「代付」两大核心场景：

| Tab | 入口名称 | 核心内容 |
|-----|---------|---------|
| 1 | 学情 | 绑定学生的完整学情数据（学情报告 / 错题列表 / 词力通打卡 / 会员状态）|
| 2 | 代付 | 为绑定学生购买 / 续费 / 升级会员；历史代付订单记录 |
| 3 | 我的 | 亲人账号设置 / 已绑定学生管理 / 到期提醒偏好 / 解绑操作 |

**多学生支持**：若亲人同时绑定了多名学生（如两个子女），「学情」Tab 顶部显示学生切换选择器（姓名 Tab 切换），当前仅展示选中学生的数据；「代付」Tab 同样需先选择目标学生再操作。

**消息入口**：「学情」Tab 右上角铃铛图标，接收学生到期提醒、学情报告生成、代付成功确认等通知。

### 绑定方式

绑定由**学生端主动发起**，亲人无法主动搜索绑定学生：

```
Step 1：学生进入「我的 → 亲人管理 → 邀请亲人」
Step 2：生成6位一次性绑定码，同时生成含绑定码信息的「绑定专属小程序码」，有效期24小时
Step 3：学生选择分享方式
        ├── 方式A：口头告知或复制发送6位绑定码
        └── 方式B：保存「绑定专属小程序码」图片发送给亲人（系统自动将绑定码嵌入二维码）
Step 4：亲人完成绑定（二选一）
        ├── 收到绑定码：打开小程序 → 角色选择「我是家长/亲人」→ 手动输入6位绑定码
        └── 收到小程序码：微信扫描图片中的小程序码 → 直接跳转绑定确认页（无需手动输入）
Step 5：绑定成功，亲人账号与该学生关联，双方收到确认通知
```

**绑定约束**：
- 每名学生最多绑定 **4位**亲人账号
- 每个绑定码仅可使用一次，使用后立即失效
- 绑定码过期后需重新生成

### 亲人代付完整流程

```
Step 1：触发入口（两路径）
  ├── 路径A：亲人主动操作
  │     └── 亲人端「我的 → 管理学生 → 为TA续费/购买」
  └── 路径B：会员到期提醒联动
        └── 学生与绑定亲人同时收到「会员即将到期」通知
        └── 亲人点击通知 → 直接进入代付页

Step 2：套餐选择
  └── 展示会员档位选购页（与学生端购买页完全相同）
  └── 页面顶部显示「您正在为 [学生昵称] 购买会员」防止误操作
  └── 弹出支付确认弹窗（与 4.6 规范相同，亲人须勾选退款规则确认框）

Step 3：支付与通知
  └── 微信支付（亲人自己的微信账号完成支付，资金直接到平台）
  └── 支付成功后：
        ├── 学生端收到通知「您的亲人 XXX 已为您购买/续费 [套餐名]」
        ├── 亲人端显示「代付成功」确认页，展示会员有效期
        └── 订单记录中：payer_id = 亲人 user_id，user_id = 学生 user_id
```

**代付权限说明**：
- 亲人代付可选任意档位（基础/Pro/ProMax），无限制
- 代付订单计入学生账号，退款申请须由**学生**提交（亲人不可代为申请退款）
- 14-17岁学生账号由亲人代付，视为已获监护人同意，无需学生侧再单独勾选同意框

### 解绑规则

|--------|---------|------|

解绑后亲人的历史代付记录与学生的学情数据均保留，不受影响。

#### 年级与教材版本变更

注册时填写的年级和教材版本会随学生实际情况变化（升年级、转学换教材），需支持学生自主修改：

**入口**：我的 → 学习信息设置 → 年级/教材版本

**变更规则**：

| 变更类型 | 规则 |
|---------|------|
| 年级变更 | 任意时间可修改；变更后系统自动推荐对应年级服务包；历史数据（错题/报告）按原年级标注保留，不重算 |

- 会员权益不变：变更学习信息不触发任何会员重置或退款

**防滥用机制**：同一自然月内年级/教材版本变更不超过3次；超过后提示"本月已达修改上限，如需更多次修改请联系客服"。

> **后台可配置**：3次/月的变更上限在 **5.6 系统配置 → 其他配置项 → 学习信息变更月度上限** 中统一管理，可随时调整，无需发版。

## 五、平台超级管理员后台（补全）

超级管理员（平台运营侧）拥有全局管理权限，包含以下核心功能模块：

### 5.1 机构管理

#### 机构入驻申请流程

**入口**：平台小程序首页「机构合作入驻」入口，提交后进入审核队列。

**申请表单字段**：

| 字段 | 必填 | 说明 |
|------|------|------|
| 机构名称 | 必填 | 与营业执照或办学许可证保持一致 |
| 机构类型 | 必填 | 线下培训机构 / 中小学学校 / 校园文具店 / 其他 |
| 联系人姓名 | 必填 | 负责人/对接人实名 |
| 联系手机号 | 必填 | 用于账号开通和后续对接 |
| 所在城市 | 必填 | 省/市/区三级 |
| 服务学生年级范围 | 必填 | 多选（小学1-6年级 / 初中7-9年级）|
| 预计学生规模 | 必填 | 范围选择（<50 / 50-200 / 200-500 / >500）|
| 营业执照/办学许可证 | 必填 | 图片上传；学校可提交教育局批文替代 |
| 机构简介 | 选填 | 200字内 |
| 了解渠道 | 选填 | 单选（朋友推荐/搜索/学校合作/其他）|

**审核标准**：

| 结论 | 条件 |
|------|------|
| 通过 | 材料真实有效（营业执照/许可证在有效期内）；机构属教育相关类型；联系人手机号可正常联系 |
| 拒绝 | 材料明显伪造或信息不一致；机构类型与教育无关；同一机构已有在驻账号（防重复入驻）；机构在平台黑名单 |
| 补材料 | 材料不完整/不清晰，但基本资质无疑问 |

**审核流程（3个工作日内完成）**：

```
Step 1：机构提交申请
  └── 系统自动发送「申请已收到」通知至联系人手机

Step 2：平台运营人员审核
  ├── 材料初审（OCR自动提取营业执照关键信息，人工复核）
  └── 必要时致电联系人核实

Step 3A：审核通过
  └── 系统自动开通机构后台账号
  └── 联系人收到小程序通知（含登录账号、初始密码）
  └── 分配专属企业微信客服（见 13.1）
  └── 运营人员3个工作日内主动联系对接首次采购和企业微信绑定

Step 3B：需补充材料
  └── 联系人收到通知「需补充：[具体材料名称]」
  └── 机构可重新上传，进入优先审核队列（1个工作日内完成）

Step 3C：拒绝
  └── 联系人收到通知，附说明原因
  └── 机构可在30天内补充新材料申请复议
```

**机构账号开通后的必要配置**：

| 配置项 | 操作方 | 说明 |
|--------|--------|------|
| 企业微信绑定 | 机构管理员 | 用于接收系统通知（见 Module 7）|
| 首批老师账号开通 | 机构管理员 | 在后台邀请老师加入机构（老师扫码授权）|
| 学生账号采购 | 机构管理员 | 后台直接下单批量采购（见 5B.5）|
| 机构资料完善 | 机构管理员 | 上传机构 Logo、填写机构简介 |

**机构后台管理**（超管侧）：
- **机构状态管理**：正常/冻结/注销，冻结后该机构所有账号暂停使用
- **机构数据概览**：各机构的老师数、学生数、会员数、活跃度统计
- **套餐分配记录**：各机构购买的团队账号套餐明细、剩余配额

### 5.2 内容管理

- **教材知识点库管理**：按教材版本/年级/学期/单元维度维护知识点结构树
- **题库管理**：试题录入、编辑、审核、上架/下架，支持批量导入

- **内容版本管理**：知识点/题库更新记录，防止历史数据污染

### 5.3 用户管理

- **全平台用户查询**：按手机号/姓名/角色/机构搜索用户
- **会员状态管理**：查看、修改、延期、退款处理学生会员
- **异常账号处理**：封禁、注销、数据恢复

#### 5.3.1 账号封禁规则

**封禁触发场景**：

| 违规行为 | 封禁类型 | 触发方式 |
|---------|---------|---------|
| 上传含政治敏感/色情/暴力内容的图片 | 临时封禁（7天）| 内容审核系统自动触发 |
| 作文/反馈内容含严重违规文字 | 临时封禁（7天）| 敏感词过滤系统自动触发 |
| 在平台内发布广告/引流信息 | 临时封禁（30天）| 举报核实后人工触发 |
| 恶意申诉（连续2个自然年均使用年度申诉配额且全部驳回）| 永久限制申诉权限（账号不封禁）| 系统跨年自动统计 |
| 账号倒卖/共享（同一账号短期内在多地异常多设备同时登录）| 临时封禁（7天）| 系统自动检测异常登录 |
| 伪造支付截图申请退款 | 永久封禁 | 人工核实后超管操作 |
| 其他严重违规（骚扰、诈骗等）| 永久封禁 | 人工审核后超管操作 |

**封禁执行机制**：
- **自动封禁**：系统检测触发后立即执行，同时向用户发送小程序通知说明封禁原因和时长
- **人工封禁**：超管后台 → 用户管理 → 搜索账号 → 执行封禁 → 必须填写封禁原因（留存内部记录）

**被封禁账号的体验**：
- 封禁期间可登录但无法使用任何功能（仅可查看历史数据和封禁说明页）
- 会员有效期在封禁期间**暂停计时**（不浪费剩余会员时长）
- 封禁原因和剩余封禁时长在账号首页显著标注

**封禁申诉渠道**：
- 入口：被封禁账号首页「申诉封禁」按钮（封禁期间可见）
- 申诉提交后由运营人员在3个工作日内人工复核
- 误判导致的封禁：解封并按实际封禁天数补偿等量会员时长
- 永久封禁的申诉须升级至运营总监审批

**封禁与退款的关系**：
- 账号封禁期间发起退款申请：系统拒绝（`refund_status = REJECT_BANNED`）
- 封禁解除后剩余会员时长恢复，可重新发起退款申请（按正常退款规则处理）

### 5.8 老师认证审核队列

老师注册时提交认证申请（见 4.0 Step 4），平台超管后台提供独立审核队列。

**审核队列页面字段**：

| 字段 | 说明 |
|------|------|
| 申请人手机号/姓名 | 老师注册信息 |
| 申请时间 | 提交时间戳 |
| 所属学校 | 老师填写的学校名称 |
| 提交材料 | 教师证编号 / 在职证明图片（点击预览）|
| 状态 | 待审核 / 审核中（已认领）/ 通过 / 驳回 |
| 操作人 | 最近一次操作的审核员姓名 |

**审核操作流程**：

```
Step 1：审核员认领任务
  └── 防止多人同时处理同一申请；认领后状态改为「审核中」并显示认领人

Step 2：核实材料
  ├── 教师证编号 → 人工参照全国教师管理信息系统核实（或联系对应学校确认）
  └── 在职证明图片 → 确认格式规范、盖章有效、与填写学校名称一致

Step 3：给出结论
  ├── 通过 → 账号获得「认证老师」标识；老师收到小程序通知「认证已通过」
  ├── 驳回 → 必须填写驳回原因；老师收到通知并可补充材料重新提交
  └── 挂起（需进一步核实）→ 保持「审核中」，审核员添加内部备注后继续跟进
```

**SLA**：3个工作日内完成审核；超过3天未处理的申请自动发出内部提醒。

**审核质量监控**：后台展示近30天老师认证申请总量、通过率、驳回原因Top5，供运营团队评估认证门槛合理性。

## 六、内容运营体系（补全）

### 6.1 知识点库建设规范

**知识点四级结构**：
```
教材版本（人教PEP）
  └── 年级（初中八年级）
        └── 学期（上学期）
              └── 单元（Unit 3）
                    └── 知识点（现在进行时用法）
                          └── 关联题目（题库ID列表）
```

**每个知识点必须包含**：
- 知识点名称（简短标签，如"现在进行时"）
- 知识点详细说明（150字内，面向学生可读）
- 典型例句（2-3个）
- 常见错误示例
- 关联题目（至少5道）

### 6.2 AI仿真题生成与质检标准

**题目生成方式**：平台题库所有题目均由AI以真题为参照生成，不收录、不存储真题原题。

**AI生成题目时的输入参数**（由内容团队配置）：
- 目标教材版本 + 年级 + 学期 + 单元
- 目标知识点（从知识点库中选取）
- 题目类型（单选/填空/阅读/作文）
- 难度等级（1-5星，对应真题易/中/难梯度）
- 参照真题范围（指定参照哪些年份/地区真题的出题风格和干扰项逻辑）

**每道AI生成题目必须包含**：
- 题目类型（单选/填空/阅读/作文）
- 题目内容（含选项，阅读题含配套语篇）
- 标准答案 + 解析说明
- 关联知识点（可多选，关联至知识点库）
- 难度等级（1-5星）
- 生成批次标记（便于追溯是哪次内容更新生成的）

**上线前人工质检要求**：
- 题目表述自然、符合英语语言习惯，无AI生成痕迹
- 答案唯一性验证（确保无歧义）
- 干扰项有效性验证（干扰项具备真实迷惑性，非明显错误）
- 与关联知识点的对应关系验证
- 难度评级与实际难度吻合验证

> 内容团队初期可借助真题题型结构作为AI出题模板参数输入，系统沉淀足够用户作答数据后，可利用实际错题率反哺优化AI出题参数，实现题库质量持续提升。

平台自建词汇学习模块，品牌名称「词力通」，不使用任何第三方品牌名称。功能对标主流词汇学习产品，并深度结合本平台的教材体系与错题系统，形成差异化联动能力。

#### 6.4.1 词库数据结构

每个词条必须包含以下字段：

| 字段 | 说明 |
|------|------|
| 单词（英文） | 原形，如 `frequently` |
| 音标 | 英式 + 美式音标，附真人发音音频 |
| 词性 | adj. / adv. / n. / v. 等，支持一词多词性 |
| 中文释义 | 按词性分组，每条释义不超过15字 |
| 例句 | 每个词性至少2条例句，附中文翻译 |
| 固定搭配 | 与该词相关的高频固定搭配（如 `be proud of`） |
| 同义词 / 反义词 | 各2-3个，附简要辨析 |
| 记忆提示 | 词根词缀拆解 / 联想记忆句（选填，运营人工录入） |
| 关联知识点 | 关联至知识点库中的具体条目（可多选） |
| 所属教材 + 年级 + 学期 + 单元 | 支持一词关联多个教材/单元 |
| 频率标签 | 高频词 / 低频词 / 超纲词 |
| 考试高频标注 | 是否为近3年真题高频考查词 |

#### 6.4.2 记忆曲线算法（艾宾浩斯间隔重复）

系统采用 **SM-2 算法**（SuperMemo 2）驱动单词复习调度，基于艾宾浩斯遗忘曲线，对每名学生每个单词独立维护记忆状态。

**单词熟练度分级（5级）**：

| 等级 | 含义 | 复习间隔 |
|------|------|---------|
| ⭐ 初见 | 首次学习 | 当天 + 次日 |
| ⭐⭐ 模糊 | 做对1次 | 间隔3天 |
| ⭐⭐⭐ 认识 | 连续做对2次 | 间隔7天 |
| ⭐⭐⭐⭐ 熟悉 | 连续做对3次 | 间隔15天 |
| ⭐⭐⭐⭐⭐ 掌握 | 连续做对4次以上 | 间隔30天（长期维护） |

**答题结果对熟练度的影响**：
- 答对：熟练度 +1 级，下次复习间隔延长
- 答错：熟练度重置为 ⭐（初见），优先安排当日复习
- 答对但犹豫（用户标记"记得但不确定"）：熟练度不升级，间隔不延长

**每日任务计算逻辑**：
- 系统每天自动计算当日需复习的单词（到期复习）+ 当日新词
- 新词数量：学生在设置中自选，**上限由会员档位决定**（免费用户固定 5词/天不可调整；基础会员上限 10词；Pro 上限 30词；ProMax 上限 50词）；各档位上限在 5.6 后台统一配置
- 复习词数量：由算法自动计算，不可手动调整
- 若当日复习词超过100个，系统提示学生"积压较多，建议今日仅复习，暂停新词"

#### 6.4.3 词卡学习流程

**每个单词的完整学习流程（首次学习）**：

```
Step 1：展示词卡
  └── 显示：单词 + 音标 + 词性 + 中文释义 + 例句 + 固定搭配
  └── 点击音标区：播放真人发音（英式/美式可切换）
  └── 点击"记住了" 或 "没记住" → 进入测试

Step 2：即时测试（学完当批新词后统一测试）
  └── 随机抽取本批新词进行题型测试（见 6.4.4）
  └── 每个新词至少被测试1次

Step 3：当日复习
  └── 完成新词学习后，进入待复习词列表
  └── 复习词直接进入题型测试，不再展示词卡详情（除非答错）
  └── 答错时：自动展示词卡详情供重新记忆，再次测试

Step 4：完成当日任务
  └── 显示今日完成数据（新学X词 / 复习X词 / 答对率）
  └── 打卡记录更新（见 6.4.5）
```

#### 6.4.4 测试题型（5种轮换）

系统根据单词熟练度和当前学习阶段，自动选择适合的题型：

| 题型 | 形式 | 适用阶段 |
|------|------|---------|
| **看词选义** | 显示英文单词，4选1中文释义 | 首次学习、低熟练度 |
| **看义选词** | 显示中文释义，4选1英文单词 | 初见→模糊阶段 |
| **听音辨词** | 播放发音，4选1英文单词 | 认识→熟悉阶段 |
| **拼写填空** | 显示中文释义，手动输入英文拼写 | 熟悉→掌握阶段 |
| **例句填空** | 显示含该词的例句，单词被遮盖，选择或填写 | 掌握阶段强化 |

**题型选择规则**：
- 熟练度 ⭐：仅用「看词选义」
- 熟练度 ⭐⭐：「看词选义」+「看义选词」轮换
- 熟练度 ⭐⭐⭐：加入「听音辨词」
- 熟练度 ⭐⭐⭐⭐ 以上：加入「拼写填空」和「例句填空」

#### 6.4.5 每日打卡与连续学习激励

**打卡判定规则**：当日完成系统生成的全部复习词 + 至少1个新词，视为打卡成功。

**连续打卡记录**：
- 显示当前连续打卡天数（如"已连续打卡 23 天"）
- 断签后连续天数归零，历史最高连续天数单独记录
- 打卡记录对绑定亲人可见（支持家庭监督）

**学习提醒**：
- 当日未完成任务时，在设定时间推送提醒通知（默认晚上8点，学生可自定义）
- 连续3天未打卡，系统推送"积压单词较多，建议今天开始复习"提醒

#### 6.4.6 错词本（与错题系统深度联动）

**错词来源**：

| 机构批量采购学生账号（已激活） | 不退款 | — |

**第二层：超过7天，不支持无理由退款**

超过7天的普通退款申请（主观不想用、使用感受不佳等）一律不支持，在购买前明确告知用户。

**第三层：超过7天，有理由申诉通道（保留，规避法律风险）**

以下特定情形即使超过7天，消费者仍有法定权利，平台须受理申诉：

| 申诉情形 | 认定标准 | 处理方式 |
|---------|---------|---------|
| **平台系统故障**导致服务无法正常使用 | 平台日志可证明连续48小时以上核心功能不可用 | 按故障天数延长会员时长或部分退款，平台主动赔付，无需用户申请 |
| **服务内容与描述严重不符** | 用户提供截图证明，客服核实属实 | 全额退款或协商补偿 |
| **误操作重复购买**同一档位套餐 | 同一账号72小时内重复下单，且重复订单未使用 | 退还重复订单，保留一份 |
| **未成年人未经监护人同意购买** | 监护人提供身份证明及声明，客服核实 | 全额退款，账号转为免费体验状态 |

申诉通道设计原则：
- 入口位于"我的 → 订单记录 → 申诉"，不在首页显著位置，避免引导滥用
- 申诉必须填写具体原因并上传相关截图证明
- 同一账号每自然年限申诉**1次**，防止反复滥用
- 平台3个工作日内给出处理结果，结果不可接受时用户可向12315投诉

#### 4.5 退款与申诉系统技术实现规范

##### 4.5.1 退款规则引擎（服务端判定逻辑）

系统在用户提交退款申请时，按以下决策树顺序执行自动判定，无法自动判定的转入人工审核队列：

```
输入：订单ID + 当前时间 + 用户ID

Step 1 — 账号状态校验
  └── 账号已封禁？ → 拒绝，返回 REJECT_BANNED

Step 2 — 活动价订单校验
  └── 订单标记 is_promotional = true？ → 拒绝，返回 REJECT_PROMOTIONAL

Step 3 — 7天窗口判断
  └── (当前时间 - 购买时间) > 7天？
        ├── 是 → 跳转 Step 7（超7天申诉判断）
        └── 否 → 继续 Step 4

Step 4 — （直接继续，不消耗年度申诉配额）
  └── 7天内普通退款（无论全额还是按比例）不计入年度申诉配额；
       年度申诉配额仅针对 Step 7 超7天有理由申诉路径，两者使用独立计数器
  └── 继续 Step 5

Step 5 — 使用量判断
  └── ai_analysis_count（AI分析使用次数）= 0？
        ├── 是 → 自动全额退款，状态 AUTO_FULL_REFUND
        └── 否 → 转人工审核，状态 MANUAL_REVIEW_PARTIAL

Step 6 — 按比例退款计算（人工审核确认后执行）
  退款金额 = 实付金额 × (总购买天数 - 已使用天数) / 总购买天数
  已使用天数 = 购买日到申请退款日的自然天数（含购买当天）
  结果向下取整至分，最低退款金额 = 0.01元（若计算结果 < 0.01 则拒绝）
  → 退款状态：REFUND_PARTIAL_APPROVED

Step 7 — 超7天申诉类型判断
  └── 申诉类型 = ?
        ├── SYSTEM_FAULT（平台系统故障）→ 自动查询故障日志，核实连续≥48h
        │     ├── 核实通过 → AUTO_FAULT_COMPENSATION（自动延时或退款）
        │     └── 未核实 → REJECT_FAULT_UNVERIFIED
        ├── DESC_MISMATCH（服务描述不符）→ 转人工审核 MANUAL_REVIEW_APPEAL
        ├── DUPLICATE_PURCHASE（重复购买）→ 自动校验：
        │     同一账号、同一套餐档位、72小时内存在多笔订单
        │     且重复订单 ai_analysis_count = 0
        │     ├── 满足 → AUTO_DUPLICATE_REFUND（退多余订单）
        │     └── 不满足 → REJECT_DUPLICATE_INELIGIBLE
        └── MINOR_PURCHASE（未成年人购买）→ 转人工审核 MANUAL_REVIEW_MINOR
```

##### 4.6.3 服务端记录时机

```
POST /api/payment/confirm-record
{
  "user_id": "...",
  "plan_id": "...",
  "plan_snapshot": { 套餐信息快照 },
  "checkbox_refund_policy": true,
  "checkbox_digital_service": true,
  "device_id": "...",
  "session_id": "..."

服务端收到请求后：
1. 写入 `payment_confirm_logs` 表，生成 `log_id`
2. 返回 `log_id` 给客户端

- `ip_address`：从请求Header中提取（X-Real-IP / X-Forwarded-For）

#### 4.7 申诉审核操作手册（客服/运营版）

> **适用范围**：处理所有超7天有理由申诉，及7天内转人工的按比例退款申请。
> **SLA要求**：3个工作日内结案，第4天自动升级。

##### 4.7.1 申诉类型一：平台系统故障（SYSTEM_FAULT）

**用户声称因平台故障无法使用服务**

**证据要求（客服核实步骤）：**
1. 查询运维日志系统，核实用户申诉期间是否存在故障记录
2. 确认故障影响范围：是否为"核心功能"（AI分析/试卷上传/错题管理），非核心功能（通知推送延迟等）不计入
3. 确认故障持续时间是否连续≥48小时

**决策标准：**

| 核实结果 | 处理方式 |
|---------|---------|
| 有故障记录，核心功能，连续≥48小时 | 按故障天数延长会员时长（优先方案）或按比例退款（用户选择）|
| 有故障记录，但<48小时 | 致歉通知 + 延长7天会员，不退款 |
| 无故障记录，但用户有截图 | 升级至技术团队排查，48小时内回复用户 |
| 无任何证据，无故障记录 | 驳回申诉，回复参考模板-A |

**客服回复模板-A（驳回）：**
```
您好，感谢您反馈。经查，您申诉期间（XXXX年XX月XX日至XX日）平台系统运行正
常，无故障记录。本次申诉暂无法支持退款。如您确有截图或录屏等证明，可在3日内
补充上传，我们将重新核查。如有其他问题欢迎继续联系。
```

**客服回复模板-B（通过-延长时长）：**
```
您好，经核实，平台于XXXX年XX月XX日至XX日存在系统故障，影响了您的正常使用，
给您带来了不便，深表歉意。我们已为您延长会员时长X天，新到期时间为XXXX年XX月
XX日。如您希望选择退款方案，请回复"申请退款"，我们将在1个工作日内为您处理。
```

##### 4.7.2 申诉类型二：服务内容与描述严重不符（DESC_MISMATCH）

**用户声称购买时页面展示的功能与实际不符**

**证据要求（客服核实步骤）：**
1. 要求用户提供：购买时的页面截图或录屏
2. 调取 `payment_confirm_logs.plan_snapshot` —— 该字段记录了用户购买时页面展示的套餐内容
3. 对比 `plan_snapshot` 与用户截图，判断是否存在实质性差异

**判断"实质性差异"的标准：**
- 构成不符：页面标注有某功能（如"AI自动出卷"），但实际该档位无此功能；价格显示与实收不一致
- 不构成不符：功能描述与用户主观理解有差异（如"智能分析"≠"全科覆盖"）；用户未仔细阅读说明

**决策标准：**

| 核实结果 | 处理方式 |
|---------|---------|
| 确认存在实质性描述不符（平台责任） | 全额退款，并触发内部BUG修复工单 |
| 描述存在模糊（非明显错误） | 协商：退款50%或延长会员30天 |
| 属于用户主观理解偏差 | 驳回，回复模板-C |

**客服回复模板-C（驳回-理解偏差）：**
```
您好，感谢您的反馈。经核实，您购买时页面展示的套餐内容（已附图）与现有功能
一致，本次暂不支持退款。我们非常重视您的建议，已将您的反馈提交至产品团队参
考优化。如有其他问题欢迎继续联系。
```

##### 4.7.3 申诉类型三：误操作重复购买（DUPLICATE_PURCHASE）

**用户声称误操作下了两笔相同订单**

**系统自动核实逻辑（已内置）：**
- 同一账号
- 同一套餐档位（`plan_id` 相同）
- 72小时内存在多笔已支付订单
- 重复订单（后下单的）`ai_analysis_count = 0`

若系统已自动核实并退款（`appeal_status = AUTO_DUPLICATE_REFUND`），客服仅需确认退款已到账并通知用户。

**若系统未自动通过（手动核实）：**

| 情形 | 处理方式 |
|------|---------|
| 72小时内，重复订单未使用 | 退还重复订单，保留最早一笔 |
| 72小时内，重复订单已使用 | 不退，但赠送7天会员补偿 |
| 超72小时 | 驳回，回复模板-D |
| 不同套餐档位 | 按正常退款规则处理，不属于"重复购买" |

**客服回复模板-D（超时驳回）：**
```
您好，根据平台规定，误操作重复购买的退款申请须在重复下单72小时内提交。您的
申诉提交时间已超出该时效，暂无法支持退款。如有其他特殊情况请补充说明，我们
将再次评估。
```

##### 4.7.4 申诉类型四：未成年人未经监护人同意购买（MINOR_PURCHASE）

**监护人声称未成年子女未经授权购买**

**必须收集的证据（用户须提供）：**
1. 监护人身份证正反面照片（证明与账号实名信息的监护关系）
2. 学生/子女身份证或户口本（证明未成年身份，年龄<18岁）
3. 书面声明（格式不限）：声明购买时本人不知情，账号由未成年人实际操控

**客服核实步骤：**
1. 核查账号注册信息（手机号归属）与监护人提供信息是否一致
2. 查看账号使用记录（登录设备、登录时间）是否与未成年人使用场景吻合
3. 若账号注册时填写的是成年人信息（如大学生），需升级审核确认

**决策标准：**

| 核实结果 | 处理方式 |
|---------|---------|
| 证据完整，账号确为未成年人使用 | 全额退款，账号转为免费体验状态，通知监护人 |
| 证据不完整（缺少身份证明） | 要求补充，给3天补充期，超期驳回 |
| 疑似冒充监护人申请退款（使用记录明显成人行为）| 升级至运营总监 + 法务评估 |

**客服回复模板-E（通过）：**
```
您好，经核实，本次申诉材料齐全，我们已为您办理全额退款，预计T+3个工作日到
账（原路返回至付款账户）。同时，该账号已调整为免费体验状态。如需重新开通会
员，请由监护人实名认证后操作。感谢您的理解与配合。
```

##### 4.7.6 7天内按比例退款人工审核流程

> 适用于7天内、AI分析已使用≥1次的退款申请（非申诉类）

**核实步骤：**
1. 确认订单 `purchase_at` 至申请时间确实在7天内
2. 查看 `ai_analysis_count`，记录实际使用次数
3. 计算退款金额：`实付金额 × 剩余天数 / 总购买天数`（剩余天数 = 总购买天数 - 已使用自然天数）
4. 核查是否为ProMax高阶功能（作文多轮精修、AI自助出卷）已使用 → 若已使用，退款金额需扣除高阶功能使用价值（参考ProMax vs Pro差价）
5. 向用户确认退款金额，用户确认后执行退款

**客服回复模板-F（按比例退款告知）：**
```
您好，根据您的订单记录，您于XXXX年XX月XX日购买了[套餐名]，共X天，实付¥XXX。
截至申请退款时，您已使用X天，根据比例退款规则，可退金额为：
¥XXX × X天 / X天 = ¥XXX.XX

退款将在确认后3个工作日内原路返还至付款账户。
请问是否确认申请此金额退款？（回复"确认"即可）
```

## 九、B端机构账号与定价体系

### 9.1 机构账号套餐构成

机构可购买两类账号，相互独立，分别计费：

| 账号类型 | 说明 |
|----------|------|
| **老师子账号** | 机构旗下任课老师使用，用于管理学生、查看学情、出卷、批改 |
| **机构学生账号** | 机构统一采购并分配给学生使用的会员账号，与老师子账号分开购买 |

**老师子账号套餐（参考档位）**：

| 套餐名称 | 老师子账号数 | 机构月出卷总量 | 机构月AI批改总量 | 适用场景 |
|----------|------------|-------------|---------------|---------|
| 入门包 | 5 个 | 100 份（默认）| 500 次（默认）| 小型培训机构 / 个人老师工作室 |
| 标准包 | 20 个 | 400 份（默认）| 2,000 次（默认）| 中型培训机构 |
| 旗舰包 | 50 个 | 1,000 份（默认）| 5,000 次（默认）| 大型培训机构 / 学校 |
| 定制包 | 自定义数量 | 自定义 | 自定义 | 大型连锁机构 / 教育集团 |

> **配置说明**：具体定价及各套餐AI资源配额（出卷总量 / AI批改总量）均在后台 5.6 系统配置中统一管理，由运营团队制定后配置，无需发版；表中数字为参考默认值，运营团队可按实际情况调整。机构内老师共享套餐总额度，先到先得；机构管理员可在后台为单个老师设置分配上限（见 四C 机构老师额度说明）。

---

### 9.2 机构学生账号批量采购规则

机构可批量采购学生会员账号，统一分配给旗下学生使用，适用于培训机构统一管理学员的场景。

**采购规格**：
- 最小采购单位：10个学生账号起批
- 每个学生账号的档位（基础/Pro/ProMax）和时长（最小1学期）由机构统一指定，批次内规格一致
- 支持多批次采购，每批次可指定不同档位/时长组合

**账号分配方式**：
- 机构后台生成激活码（每个激活码对应1个学生账号额度）
- 分发方式：机构将激活码线下告知学生 / 或在后台直接绑定已注册学生的手机号完成分配
- 学生首次使用激活码注册或绑定后，账号正式激活，会员时长从激活当日起计算

**指定老师分配**：
- 机构可在分配账号时同步指定该学生的授课老师（从机构旗下老师子账号中选择）
- 也可先分配账号，后续在机构后台统一批量调整学生与老师的对应关系

---

### 9.3 机构学生与自由生的核心权限差异

| 规则项 | 机构学生（机构采购账号） | 自由生（学生自行购买） |
|--------|----------------------|-------------------|
| 老师来源 | 机构统一指定，学生**不可自主选择或更换**老师 | 学生通过短信邀请或老师分享链接绑定认证老师，老师主动确认 |
| 换绑老师 | **不允许**，只能由机构后台操作调整 | **允许**，学生可主动解绑并重新绑定其他老师 |
| 所属机构 | 强制归属采购账号所在机构，不可跳出 | 无机构归属（或归属学校体系，见场景二） |
| 数据归属 | 学情数据归机构统一管理，机构及指定老师均可查看 | 数据仅归属学生本人及绑定老师，无机构层可见 |
| 学情报告 | 纳入机构班级综合报告 | 仅出现在绑定老师的多学生汇总报告中 |

---

### 9.4 机构学生账号到期后的归属转换规则

机构学生账号到期时，系统根据续费主体判定后续归属，规则如下：

```
账号到期
    │
    ├── 机构续费（机构为该学生账号续期）
    │       └── 学生继续归属该机构
    │           老师指定关系保持不变
    │           数据归属不变
    │
    └── 机构不续费（账号到期未被机构续期）
            │
            ├── 学生自行购买会员（独立付费）
            │       └── 账号转为「自由生」身份
            │           脱离原机构体系，数据归学生本人
            │           可自主选择绑定任意认证老师
            │           原机构不再可见该学生任何数据
            │
            └── 学生不续费
                    └── 账号进入「过期」状态
                        历史学情数据保留（可查看，不可新增）
                        过期后30天内自行续费：身份规则同上（自行购买→自由生）
```

**补充规则**：
- 机构学生账号到期前，机构可在后台提前批量续费（续期时长叠加至到期日，最小1学期）
- 学生自行购买转为自由生后，原机构的历史学情数据不跟随迁移，学生仅保留个人维度的错题和报告数据，机构侧数据归机构留存
- 自由生如需重新加入某机构，须经机构管理员手动邀请/重新分配账号，不可自行申请加入

---

### 9.5 机构分成规则

- 非自营合作机构（文具店等推广渠道）：按实际成交会员金额的固定比例返佣（具体比例由签约合同约定）
- 学校合作：通常采用整体采购方式，不涉及分成，按实际购买账号数计费
- 分成结算：按月结算，财务管理后台自动计算，机构可在后台查看结算明细

## 十、技术架构核心要求（补全）

本章列出开发前需确认的关键技术约束，供技术团队参考。

### 10.1 多租户数据隔离

- 各入驻机构数据必须在数据库层面完全隔离，防止跨机构数据泄露
- 机构被注销后，其数据进入归档状态，保留3年后可物理删除

### 10.2 AI识别与诊断

**OCR 与 LLM 分层架构（已验证技术选型，详见附录 A）**

OCR 识别层与 AI 诊断层必须分开，不可用同一模型包揽：

```
学生上传试卷图片（印刷体题目 + 手写作答混合在同一张图）
       │
       ▼
【第零层：图像预处理】
  └── 倾斜矫正 / 去噪增强 / 分辨率检测（低质量图提示重拍）
       │
       ▼
【第一层：版面分析分区】  ← 关键前置步骤，不可跳过
  使用 PaddleLayout / DocLayout-YOLO 等版面检测模型
  将同一张图分割为：印刷体区域 / 手写作答区域 / 批改标注区（忽略）
       │
       ▼
【第二层：分区域 OCR 引擎】  各区域用对应引擎，追求各自准确率
  ├── 印刷体区域
  │     ├── 主选：阿里云 OCR（读光高精度版，官方准确率 >99.7%）
  │     └── 备选：百度 OCR（通用高精版，官方准确率 >99%，有免费额度）
  └── 手写作答区域
        ├── 主选：腾讯云 OCR 手写识别（官方 >90%，中文实测 94.7%）
        └── 备选：Google Document AI（实测英文手写 92-95%）
       │ 按坐标融合，输出「题目 + 学生答案」结构化文本
       ▼
【第三层：大语言模型 LLM】  负责错因诊断、学情分析、报告生成
  └── DeepSeek / Claude 等（语义理解、错因拆解的强项）
```

**各服务商准确率对比（来源：附录 A 完整调研）**：

| 场景 | 服务商 | 官方准确率 | 实测 | 定位 |
|------|--------|-----------|------|------|
| 印刷体 | 阿里云 OCR（读光高精度） | >99.7% | 强 | 主选 |
| 印刷体 | 百度 OCR（通用高精版） | >99% | 良好，有免费额度 | 备选 |
| 手写体 | 腾讯云 OCR 手写识别 | >90% | 中文实测 94.7% | 主选 |
| 手写体 | Google Document AI | — | 英文实测 92-95% | 备选（英文手写为主时） |
| 综合 | DeepSeek-VL2 | — | 生产环境 75-80% | **不用于 OCR 层** |

**不使用 DeepSeek 做 OCR 的原因**：截至 2026 年 5 月，DeepSeek 官方 API 不支持图像输入；其视觉模型 OCRBench v2 得分 43.3/100，生产环境复杂文档实测仅 75-80%，与印刷体 ≥99% 的要求差距过大（详见附录 A）。

**其他要求**：
- 识别置信度低于阈值时，自动高亮提示学生手动确认/修正，不允许静默丢弃
- 错因诊断模型需持续迭代：建立用户反馈机制（学生/老师可对 AI 诊断结果标记"不准确"），反馈数据用于模型优化
- LLM 诊断结果不确定时，需标注置信度，避免给出误导性强结论

### 10.3 数据安全与隐私合规

- 系统用户含大量未成年人（中小学生），需严格遵守《个人信息保护法》《未成年人网络保护条例》
- 学生数据不得用于广告推送、第三方数据共享
- 亲人绑定涉及未成年人数据授权，需明确告知并获得家长同意
- 支付功能对接正规第三方支付（MVP：微信支付；P2 Web/App 阶段扩展支付宝），平台不存储支付敏感信息

### 10.4 系统性能要求

- 试卷上传后，AI分析结果返回时间 ≤ 60秒（单张标准试卷）
- 学情报告生成时间 ≤ 30秒
- 系统可用性目标 ≥ 99.5%（考试季高峰期需做好弹性扩容预案）

### 10.5 双减政策合规说明

- 平台定性为**学情诊断工具**，不提供在线直播授课、一对一在线辅导等受"双减"严格管控的业务形态
- "个性化补强学习方案"为系统自动生成的学习计划，非人工在线辅导，需在用户协议中明确说明
- 如后续计划引入老师在线辅导功能，需提前进行政策合规评估

### 10.6 前端技术架构策略（分阶段演进）

#### 第一阶段（MVP / P0-P1）：微信小程序唯一前端

**选型原因**：
- 目标用户（学生、家长、老师）微信覆盖率接近100%，无需额外安装
- 小程序与企业微信互通，机构端老师可在企业微信内直接访问
- 分发成本低，更新即时生效，无 App Store 审核周期
- 亲人代付、微信支付、小程序服务通知均在微信生态内闭环完成

#### 第二阶段（P2+，根据业务规模决策）：多端扩展

根据 DAU / 用户需求再决策是否扩展，候选端：

| 端 | 适用场景 |
|----|---------|
| 独立 Web 前端（PC网页版）| 老师端/机构管理员在电脑端操作（报告查看、出卷、批量管理）|
| iOS App | 学生深度使用场景，离线功能需求 |
| Android App | 非iPhone学生用户群体 |

#### API 设计原则（从第一天起预留多端扩展能力）

后端必须从 MVP 起遵循以下原则，防止小程序强绑定导致后期改造成本高：

| 原则 | 具体要求 |
|------|---------|
| **前后端完全分离** | 所有业务逻辑在后端 API 层实现，小程序/Web/App 均只调用 API，不在前端含业务逻辑 |
| **统一响应格式** | 所有 API 返回统一 JSON 格式：`{ code, message, data, timestamp }` |
| **平台无关的用户标识** | 微信 `openid` 不作为业务主键；登录后映射为平台 `user_id`，`openid` 仅在认证层使用 |
| **标准化认证** | 使用 JWT Token（`Authorization: Bearer <token>`），微信 `session_key` 不透传业务层 |
| **版本管理** | API 路径包含版本号（`/api/v1/...`），后续迭代通过新版本号隔离，不破坏已发布客户端 |
| **文件上传通用化** | 图片/音频上传返回通用 CDN URL，不绑定微信云存储，未来可无缝迁移至其他存储 |
| **推送渠道抽象** | 通知推送通过统一推送服务层（`NotificationService`）发出，底层渠道（小程序/企业微信/短信/App Push）可按用户端类型路由，无需修改业务代码 |

#### 微信小程序与企业微信的账号关联

- 老师同时持有：普通微信身份（小程序使用）+ 企业微信身份（机构通知接收）
- 两个身份共享同一 `user_id`，通过不同 OAuth 渠道登录后在平台侧自动关联
- 企业微信小程序（企业内部版）在 P1 阶段评估；P0 先用普通小程序，企业微信仅作通知渠道

## 十二、项目整体闭环总结

本项目以中小学各学期英语教材体系为核心底层支撑，以「学期教材对标服务包」为核心产品，以AI试卷识别+教材知识点联动错题诊断为核心技术壁垒，搭配档位+时长双维度差异化会员体系。

通过学校、文具店、线下培训机构三大线下场景批量获客，彻底解决学生刷题脱离课本、老师学情分析低效、机构教学服务无差异化的全链条痛点，打造出「教材同步赋能、AI数据精准提分、家校双向联动、分层精细化管理、多场景获客、合规双模式变现」的完整英语教育SaaS商业闭环。

## 附录 A：OCR 技术选型调研报告

> 调研背景：需求文档要求印刷体识别准确率 ≥99%、手写体识别准确率 ≥90%。本次调研评估 DeepSeek 能否作为 OCR 层满足上述要求，并给出最终技术选型建议。

### A.1 结论（摘要）

**DeepSeek 不满足本项目 OCR 准确率要求，且当前官方 API 不支持图像输入，无法直接接入。**

推荐采用专用 OCR API 承担识别层，DeepSeek 等 LLM 仅用于识别后的语义分析与诊断生成。

---

### A.2 DeepSeek 视觉能力现状

**API 可用性（截至 2026 年 5 月）**

| 模型 | 官方 API 是否支持图像 | 说明 |
|------|----------------------|------|
| DeepSeek-V4-Flash / V4-Pro | **否** | 官方 api.deepseek.com 现役模型不支持图像输入 |
| DeepSeek-V4 视觉模块 | **否（灰度内测）** | 视觉能力仍在内测，未正式开放，无 SLA 保障 |
| DeepSeek-VL2（第三方平台） | 可通过 SiliconFlow 等平台调用 | 非官方渠道，稳定性和 SLA 无法保证 |

**准确率基准数据**

| 评测基准 | DeepSeek-VL2 得分 | 说明 |
|----------|-----------------|------|
| OCRBench v1（满分 1000） | 834/1000 | 综合多子任务得分，非字符准确率 |
| OCRBench v2（满分 100） | **43.3/100** | 更严苛测试集，主流模型普遍低于 50 分 |
| 生产环境复杂文档（实测） | **75-80%** | 与 benchmark 相比大幅下滑 |
| 英文手写（小样本非正式实测） | 92-96% | 样本量不足，中文手写无可信数据 |

**与项目要求的差距**

| 项目要求 | DeepSeek 现状 | 差距 |
|----------|-------------|------|
| 印刷体 ≥ 99% | 生产环境 75-80% | **差距约 20 个百分点** |
| 手写体 ≥ 90% | 中文手写无数据，英文小样本 92-96% | **不可信，无法作为选型依据** |
| API 可直接接入 | 官方 API 不支持图像 | **根本障碍** |

**已知短板**

- 手写草书、连笔识别误差明显；中文手写训练数据稀缺
- 表格错位占错误总量 30%，多列版面解析混乱
- 文档文字密度高（>1200 token）时精度骤降至 59.1%
- 中英文混排时标点、格式错误率偏高

### A.3 主流专用 OCR API 对比

| 服务商 | 印刷体准确率 | 手写体准确率 | 中文支持 | 适用场景 |
|--------|------------|------------|---------|---------|
| **阿里云 OCR（读光高精度全文版）** | 官方 **>99.7%** | 支持，无独立数据 | 极强 | 文档、试卷印刷体，首选 |
| **百度 OCR（通用高精版）** | 官方 **>99%** | 实测 89.2%（中文手写） | 极强 | 有免费额度，备选 |
| **腾讯云 OCR（手写识别专项）** | 官方 **>95%** | 官方 **>90%**，实测 **94.7%**（中文） | 强 | 手写作答识别，首选 |
| **Google Document AI** | 实测 >98%（结构化文档） | 实测 92-95%（多语言手写） | 良好 | 英文手写备选，国内网络需评估 |
| **DeepSeek-VL2（第三方）** | 生产环境 75-80% | 中文无数据 | 强 | **不推荐用于 OCR 层** |

### A.4 最终技术选型决策

| 识别场景 | 选用服务 | 满足要求 | 备注 |
|----------|----------|---------|------|
| 印刷体题目识别 | **阿里云 OCR（读光高精度）** | ✅ 满足 ≥99% | 首选；百度 OCR 为备用 |
| 学生手写作答识别 | **腾讯云 OCR（手写识别）** | ✅ 满足 ≥90% | 实测 94.7%，中文表现稳定 |
| 错题诊断 / 报告生成 | **DeepSeek / Claude 等 LLM** | — | OCR 输出文本后再传入 LLM |

**DeepSeek 的正确用法**：仅作为第二层 LLM 使用，承担 OCR 后的错因拆解、学情分析、报告生成，不承担图像识别工作。待 DeepSeek 官方视觉 API 正式开放并达到生产级准确率后，可再评估是否引入视觉层。
