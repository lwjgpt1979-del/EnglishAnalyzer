# 长难句解析 · 设计(来源 / 理解 / 验证学会)

> 定位:长难句**不是新体系**,是"句法轴"知识点(`knowledge_nodes` axis=knowledge / node_kind=句法,如 定语从句/状语从句/非谓语/倒装/强调/同位语…)的**应用入口**。完全复用 KP-First 骨架(R0 节点+受控匹配、R2 platform_question、R3 错题闭环+判掌握、R4 student_kp、R6 资源)。
> 三条铁律延续:**句子必有源**(来自真题/教材/上传,不无源 AI 造句)、**挂句法 node**、**验证走有源练习链**。

---

## 一、长难句从哪来(来源)

**句子一律从已有"有源内容"里抽,不凭空造**:
1. **平台真题**(`platform_question.stem` / `passage.text`,R2):阅读/完形/语法填空里的长句 —— 主来源(权威、有源)。
2. **教材课文**(教材单元 passage / 课本原文):跟当前学期教材走。
3. **学生上传卷 / 错题**(`uploaded_question.stem`):学生自己卷子里的长句(个人化)。

**抽取判定(什么算"长难句")**:长度阈值(如 ≥20 词)+ 结构信号(含从句引导词/非谓语/多重修饰/插入语)→ AI 受控识别。抽出后:
- AI 识别该句涉及的**句法点名**(如"定语从句""分词作状语")→ 走 **`kp_match_service.match_kp`** 命中/落候选 → 挂**句法 node**(一句可挂多 node,多对多)。
- 记录**来源指针**(q_scope + question_id / passage_id),保证可溯源、有源。

**域**:平台真题来的句子=平台域(共享);学生上传来的=个人域(student scope)。沿用 R0.5 分域。

---

## 二、用户怎么理解长难句(理解 / 教学)

**AI 结构化拆解 + 分层呈现 + 句法点跳讲解**:
1. **AI 拆解**(一次性生成,存结构化 `analysis_json`):
   - **主干**:抽出 主谓宾(SVO)核心句。
   - **修饰/成分分层**:定语、状语、从句、非谓语、插入语 分块标注(带在原句中的位置区间)。
   - **涉及句法点**:每块挂到对应**句法 node**(点击可跳 R6 讲解资源)。
   - **中文翻译** + **难点提示**(为什么难、易错点)。
2. **学生端呈现**:
   - 原句**分层高亮**:主干一色、各修饰成分各色;可"只看主干"折叠修饰 → 理解骨架。
   - 点某成分 → 显示它是什么句法点 + 跳该 node 的讲解(R6 `node_resource` lecture/example)。
   - 看译文、难点提示;可"再来一句同句法点"的句子继续练。
3. **存储**:长难句解析存为**结构化资源**(见决策 §4-A),挂句法 node;复用 R6 资源审核/发布链(讲解可运营审核)。

> 设计取向:**先懂骨架(主干)再看修饰**,把"长句"降解为"主干 + 已学句法点的组合",和知识图谱一致。

## 三、怎么验证学会了(掌握验证)

**沿用错题闭环(R3)的"做对原题 + N 道同类全对 → 判掌握 → 回写"**,针对**句法 node**:
1. **理解后即时小测**(对这句):
   - **主干识别题**:从选项里选出该句主干 / 标出从句边界(结构题)。
   - **翻译题**:译这句(或译一句同句法点的新句)。
2. **同句法点扩展练**(有源链,复用 R3 `wrong_practice_service.practice_same_kind`):
   - 该句法 node → `platform_question` 真题派生仿真(无真题则 KP 直生备选)→ N 道同句法点题。
3. **判掌握 + 回写**(复用 R3 `mastery_judge_service`):
   - **原句小测做对 + N 道同句法点仿真全对** → 判该**句法 node 掌握** → `student_kp.mastery=1`(R4);作答落 `answer_log`。
   - 做错 → `record_wrong`(q_scope+question_id, node=句法点)进 **错题中心**(R3),进错题复习(SM-2)。
4. **个人图谱体现**:句法 node 的掌握度/趋势直接出现在"我的知识地图"(R4 `/student-kp/graph`、`/trend`),长难句能力 = 句法轴掌握度。

> 验证口径与错题/练习统一:句法点也是 KP,"学会长难句"= 该句法 node 在个人图谱上判掌握。

## 四、数据建模(怎么落到骨架)+ 决策点

### 已有可复用(无需新建)
- 句法 node:`knowledge_nodes`(node_kind=句法)+ 受控匹配 `match_kp`。
- 句子来源:`platform_question` / `passage` / `uploaded_question`(stem/text)。
- 讲解资源:`node_resource`(R6,resource_type 可加 `long_sentence` 或用 `example`/`lecture`)。
- 练习有源链:`wrong_practice_service.practice_same_kind`;判掌握 `mastery_judge_service`;错题 `wrong_record`;个人图谱 `student_kp`。

### 需新建(轻)
- **`long_sentence`**(长难句条目,挂来源 + 句法 node):
  `id / scope(platform|student) / owner_id? / source_q_scope / source_question_id|passage_id / text(句子原文) / analysis_json(主干/分层/译文/难点) / status(draft|published) / created_at`。
- **`long_sentence_node`**(长难句 ↔ 句法 node 多对多)。
- (复用 R6 `node_resource` 也可承载解析;见 R-A 决策)

### 决策点【✅ 已定 2026-06-18】
- **决-A = 新建 `long_sentence` 表**(+ `long_sentence_node` 边):长难句是独立学习对象,需按来源/句法点检索;解析存 `analysis_json`。
- **决-B = 抽取服务对三来源同构 + 后台配置开关控制启用,默认只开①平台真题**:
  - 抽取服务设计上对 ①平台真题 / ②教材课文 / ③学生上传 **同构**(只是触发点/域不同),即"全开能力";
  - 实际启用哪些来源由**后台配置**(`system_configs` key `long_sentence.sources`)控制,**默认 `["platform_real"]`(只平台真题)**;
  - 跑通后把 ②③ 配置打开即接入,无需改代码。
- **决-C = 验证题型 ②–⑨ 全部纳入,后台逐题型开关、默认全开放,学生在已开放题型中自选**:
  - 题型集:②句法点完形 / ③结构类型选择 / ④主干识别(选SVO) / ⑤翻译(英译中) / ⑥成分/从句边界标注 / ⑦成分重组排序 / ⑧改写合并句 / ⑨朗读复述(口语)。
  - 后台配置(`long_sentence.verify_types`)逐题型开关,**默认全开放**(已实现的题型可选;未实现的随上线逐步可选)。
  - **判分/判掌握口径**:客观题(②③④⑦)自动判分,可硬判掌握(进 `judge_and_mark`→`student_kp` 句法 node);主观题(⑤⑥⑧)走 **AI 评分**(达阈值算通过)、⑨口语走**发音评测**(复用 tts/发音打分)——主观题作"通过/未通过"软判,达标同样回写。
  - 学生在"已开放题型"里**自选**用哪种验证;掌握判定 = 原句理解 + 所选题型 N 题达标。
- **决-D = 独立后台抽取任务**:`scripts/extract_long_sentences.py`(扫 `platform_question` 未抽真题,长句判定→AI 拆解→`match_kp` 挂句法 node→落 `long_sentence`;幂等"已抽"标记、可重跑回填、`--dry-run`);可选导入处加"打标待抽"轻钩子(只标不跑 AI)。不拖累导入、可控可演进。

### 配置(后台,沿用 system_configs)
- `long_sentence.sources` = `["platform_real"]`(默认)| 可加 `"textbook"` / `"uploaded"`。
- `long_sentence.verify_types` = 默认全开 `["cloze","struct_type","main_clause","translate","span_label","reorder","rewrite","read_aloud"]`;未实现项上线前后台灰显。
- `long_sentence.min_words` 长句阈值(默认 20);`long_sentence.required_pass` 判掌握所需达标题数 N(默认 3)。

## 五、实现路线(决策已定,分步;C 题型按"客观先、主观后"内部分期)
- **L1** `long_sentence`(+ `long_sentence_node` 边)建表(迁移)+ 抽取服务(三来源同构骨架,source 由配置控、默认 platform_real)+ 独立任务 `extract_long_sentences.py`(平台真题→长句判定→AI 拆解→match_kp 挂句法 node;幂等/dry-run)+ 测试。
- **L2** 学生端读取 API(列长难句/取解析,按句法 node/来源)+ 理解呈现数据(主干分层/译文/句法点跳 R6 资源)。
- **L3 验证·客观题**:②句法点完形 / ③结构类型选择 / ④主干识别 / ⑦重组(客观)题型生成+自动判分 + `judge_and_mark` 回写 student_kp 句法 node + 错题收口 `record_wrong`;后台 `verify_types` 配置 + 学生自选。
- **L4 验证·主观题**:⑤翻译 / ⑥成分标注 / ⑧改写(AI 评分达阈值)+ ⑨朗读(发音评测)→ 通过/未通过软判回写;同走配置+自选。
- **L5** 后台:抽取任务调度/手动触发 + 解析审核(复用 R6 审核范式)+ `system_configs` 配置项(sources/verify_types/min_words/required_pass)。
- **L6** 端到端验收 + 串测。

> 说明:C 的 8 种题型工作量大,L3 先交客观题(可硬判掌握、口径稳),L4 再交主观/口语题(需 AI/发音评分);`verify_types` 默认全开,未实现题型上线前后台灰显、学生不可选。全程复用 R0–R7 骨架,新增仅 `long_sentence`(+边)+ 抽取/验证接线 + 配置项;句法点掌握直接进个人图谱。
