# D 期(简短方案)— 知识图谱总览 / 维护页

> 状态:**待确认范围**。确认后分步实现。
> 目标:补一个统一入口,能**看全 + 管**整个基础知识框架(`knowledge_nodes`)。
> 现状:节点只能间接产生(生成自动建 / 候选审批建),无浏览全图、无改节点、无停用、无合并。

## 范围(分 3 步,每步独立可交付)

### D1 浏览总览(只读,先做)
- **后端**:扩 `GET /admin/kp-nodes` —— 加 `status` 过滤 + 分页(skip/limit/total),
  每个节点带摘要:**六维完整度**(几维有讲解)、**引用单元数**、**引用真题数**、**别名数**。
- **前端**:新页「🧠 知识图谱」(挂导航"内容生产"组)。
  过滤 轴(知识/能力/考点)/ 学段 / 状态 / 关键词;表格列:名称 · 轴 · 子类型 · 状态 · 学段 · 完整度 · 引用单元 · 引用真题 · 别名数;分页。

### D2 节点详情 + 维护
- **后端**:`GET /admin/kp-nodes/{id}` 详情(别名列表、引用单元列表、引用真题数/抽样、六维完整度、可选:学生掌握分布);
  `PATCH /admin/kp-nodes/{id}`(改 名称 / 子类型 / 学段 / 描述);`POST .../retire` 与 `.../restore`(状态 active↔retired,**不硬删**)。
- **前端**:节点详情抽屉(别名 / 被哪些单元·真题引用 / 六维完整度 + 跳去补全 / 掌握分布)+ 改名编辑 + 停用/恢复。

### D3 合并去重(最重、最后做)
- **后端**:`merge_nodes(source→target)` —— 把别名、`unit_node` 边、`node_resource`、
  `platform_question_kp`、`student_kp` 全部重指到目标,源节点 retire。
  ⚠️ 风险:`node_resource` 唯一键 (node,type,dim) 合并会冲突需取舍;`student_kp` 是学生数据需谨慎。
- **前端**:详情里"合并到…"搜目标 → 预览影响行数 → 确认。
