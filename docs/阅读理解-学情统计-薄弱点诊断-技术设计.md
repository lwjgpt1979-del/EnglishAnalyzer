# 阅读理解·学情统计 → 薄弱点诊断 技术设计(精简版)

> 状态:**设计待评审,未开发**。目标是在现有「作业·阅读理解」基础上,把学生本来就在做的行为(查词 / 解长难句 / 答题)统计起来,单篇 + 阶段两级汇总,纯阈值照出薄弱点,再用**现成模块**(词力通 / 长难句 / 题型专项)给针对性指导。**不另起六维 BKT 体系**。

## 0. 已定的设计决策

| # | 决策 |
|---|---|
| ① 生词口径 | **点查 + 词义题错 都计**(取并集) |
| ② 判弱标准 | **纯阈值**:生词出现 ≥N 篇=高频薄弱词;题型正确率 <60%=弱题型;某句法结构卡 ≥3 次=弱结构。规则透明可解释,不用 BKT/CAT |
| ③ 题型标签 | **独立字段**(不复用 `rc-*`),由**一次性归类工序**产出:先从精讲缓存回填、未覆盖补跑归类,人工可改 |
| 对错来源 | **A+B**:A=练同类(PracticeQuiz 判分)落库;B=真题原题在精讲里作答记 `is_correct`。分开看「真题正确率 / 练同类正确率」 |

## 0.1 修订(P1 重定基 — 开发前侦察纠错)

开发前侦察发现原设计基于**错的目标表**,据实纠正(P1 据此实现):

1. **目标表 = `user_paper_questions`(学生上传作业题),不是 `platform_question`(平台真题库)。** 作业精讲的阅读理解跑在 `UserPaperQuestion`(`user_paper_sections.section_type='reading'`)上;原 §1 里 platform 侧的计数与口径对本需求无关。
2. **对错已落库,无需新表/无需 A+B 作答交互。** `UserPaperQuestion` 自带 `is_wrong` + `student_answer` + `correct_answer`。原 §2.2 `reading_answer_log` 与"对错缺口""口径 A+B"**作废**;题型标好后 `题型正确率` 直接 join `is_wrong` 即得。
3. **题型细标精讲已顺手在产,只是没落到题上。** `question_analysis` 每次精讲产出 `skill` 存 `reading_analysis_cache`。P1 只需把它落到题上并可聚合。

**纠正后 P1(实现口径)**:给 `user_paper_questions` 加一列 `reading_skill`;精讲时顺手写;存量从 `reading_analysis_cache` 按 md5 回填(含同内容邻题复制);未覆盖的补跑归类;admin 复核可改。对错用 `is_wrong`,不建表。下文 §2 起以此为准,旧 `reading_answer_log`/`reading_question_type` 段落保留仅作对照。

## 1. 数据现状与缺口(只读排查结论)

| 信号 | 现状 | 可否直接聚合 |
|---|---|---|
| 题型分类 | 阅读精讲「题目层解析」LLM 已判(`skill`=细节/主旨/推理/词义/态度… + `rc_code`),存 `reading_analysis_cache`(按题 md5),**非题上列**,仅覆盖被看过精讲的题 | ⚠️ 有能力、不可聚合 → 需固化成列 |
| 词义题错 | `wrong_record`(带 `question_type`、`vocab_word_id`、`source_label`) | ✅ 有(仅错题) |
| 点查生词 | 阅读点词进词力通 | ❓ 需确认是否落「查词事件」,大概率要补采集 |
| 长难句三态 | `student_long_sentence.did_comp/did_gram/did_word` + `analysis_json`(含语法结构) | ✅ 有 |
| 考纲词判定 | `vocabulary_words` 已有频档(真题反哺:中考/高考 + 高中低频档) | ✅ 有 |
| **阅读题作答对错** | `reading_question_studied` **只记"看过=已学",无 is_correct**;`wrong_record` 只收错题(无对题分母) | ❌ **缺,是硬前置** |

**结论**:题型「有能力没落地」、对错「信号断了」是两块必补;词汇/长难句信号基本齐,词汇点查事件待确认。题型归类以**补跑为主、缓存回填仅捡漏**(现网缓存极少)。

## 2. 表结构改动清单

> 迁移文件按现有 alembic 习惯,`IF NOT EXISTS` 幂等。当前 head = `m196_media_asset_ls_progress`。

### 2.1 新增 `reading_question_type`(题型标签,固化 → 可聚合)
```
reading_question_type
  question_id   UUID PK        -- 指向 platform_question.id(阅读小题)
  skill_type    VARCHAR(16)    -- 细节理解|主旨大意|推理判断|词义猜测|作者态度|指代关系|图表数字|其他
  rc_code       VARCHAR(24)    -- 冗余精讲的 rc-*,便于对照
  source        VARCHAR(8)     -- cache(回填)|llm(补跑)|manual(人工改)
  confidence    SMALLINT       -- 0-100,补跑归类可给;低置信在 admin 标黄待复核
  updated_at    TIMESTAMPTZ default now()
```
> 选独立表而非往 `platform_question` 加列:不污染通用题主表,阅读专属,后续可扩展听力等同法建 `listening_question_type`。

### 2.2 新增 `reading_answer_log`(阅读作答对错,A+B 统一落这)
```
reading_answer_log
  id           UUID PK
  student_id   UUID
  question_id  UUID           -- platform_question.id
  source       VARCHAR(12)    -- real(真题原题,口径B) | sim_practice(练同类,口径A)
  skill_type   VARCHAR(16)    -- 冗余题型(落库时从 reading_question_type 带,免 join,便于按题型聚合正确率)
  is_correct   BOOLEAN
  chosen       VARCHAR(8)     -- 选了哪项(可选,做错因/干扰项分析用)
  created_at   TIMESTAMPTZ default now()
  index (student_id, created_at)   -- 阶段窗口查询
  index (student_id, skill_type)   -- 题型正确率
```
> 正确率 = 该题型 `is_correct` 命中数 / 总作答数。A、B 靠 `source` 分流,能分别出「真题正确率 / 练同类正确率」。

### 2.3 新增 `reading_word_lookup`(阅读点查生词事件,口径①的"点查"半)
```
reading_word_lookup
  id           UUID PK
  student_id   UUID
  word_id      UUID           -- vocabulary_words.id(点查命中词库时);未命中留 word 文本
  word         VARCHAR(64)
  is_exam_word BOOLEAN        -- 落库时判:该词是否在中考/高考考纲频档
  freq_tier    VARCHAR(8)     -- 冗余频档(高频/中频/低频),便于"高考高频生词"聚合
  source_qid   UUID           -- 来自哪道阅读题/哪篇(可空)
  created_at   TIMESTAMPTZ default now()
  index (student_id, word_id)
```
> 生词并集 = `reading_word_lookup`(点查) ∪ `wrong_record`(题型=词义猜测 且有 `vocab_word_id`)。**只统计考纲词**(`is_exam_word=true`)。

### 2.4 长难句:**不新增表**
「卡的句法结构」直接查 `student_long_sentence`:`did_gram=false`(或理解探针未过)的句子,取其 `analysis_json` 里的语法结构标签聚合计数。需确认 `analysis_json` 里语法结构字段命名(设计阶段待核)。

### 2.5 阶段快照:**先不做物化**
阶段薄弱点直接实时查 2.1–2.4(单学生数据量小)。若后续慢,再加 `reading_weakness_snapshot` 物化。

## 3. 采集点(在哪写这些表)

|---|---|---|
| `reading_question_type` | ① admin 一次性工序回填/补跑 ② 精讲生成解析时顺手 upsert(增量覆盖新题) | 复用 `reading_intensive_service` 的 skill 输出 |

## 4. 统计口径与判弱规则(纯阈值)

### 4.1 单篇读后小结(按 passage / 作业批次)
- 词汇:本篇命中考纲词数、其中生词数(点查∪词义错)、生词清单(带频档)。
- 长难句:本篇解析句数、卡语法句数、卡在哪些结构。
- 提问:本篇作答题数、错题数、按题型对错。

### 4.2 阶段薄弱点(时间窗 + 多篇,如近 2 周)
- **高频薄弱词**:考纲生词按"出现篇数"降序,`篇数 ≥ N`(默认 N=3,可配)高亮。
- **弱题型**:各题型 `正确率 < 60%`(且样本 ≥ M,默认 M=3)判弱。
- **弱句法结构**:某结构累计卡 `≥ 3` 次判弱。
- **一句话诊断**:取三类里最突出的各 1 项,拼成"短板 = 推理判断题 + 非谓语长句 + 高考高频词 impose 类"。

> 阈值 N/M/60%/3 全部**走后台可配**(`system_configs`),不写死(遵从"运营可配置值"铁律),常量仅兜底。

## 7. 一次性归类工序(admin)

> **归类范围 = 折中·跟着上架走**(不空跑草稿):要发布哪批阅读题就归类哪批,避免为永不发布的草稿烧钱。成本量级到实现期再按当批题量估。

1. **回填(捡漏,非主力)**:扫 `reading_analysis_cache`,命中的把 `analysis.skill`/`rc_code` 映射成 `skill_type` upsert(`source=cache`)。**回填量极小,别指望它。**
2. **补跑(主力)**:范围内未覆盖的阅读题批量调题型归类(复用精讲的题型判定 prompt,`feature="reading_qtype_classify"`,`mode=chat` 快档即可——规格明确的分类,不占推理档),写 `source=llm` + `confidence`。
3. **复核**:admin 逐题可改(`source=manual`);低置信标黄优先复核。
4. **增量**:此后精讲每出一次解析、或阅读题上架时,顺手 upsert 题型,保持覆盖。

## 9. 待核 / 风险

- **「阅读理解小题」的精确圈定口径**:按 `block_id` 挂 reading_text passage,还是按 `question_type='阅读'`?两者口径不同。倾向按 `block_id`(阅读小题以「单选」存于短文下),P1 前敲定统一 SQL 口径。
- `student_long_sentence.analysis_json` 里语法结构标签的确切字段名(P4 前核)。
- 阅读里"点词查词卡"的现有入口/埋点位置(P4 前核)。
- 口径B 给精讲加"先作答"交互,注意别破坏现有"直接看解析"的复习动线(可作为可选模式)。
- 题型枚举收敛:精讲输出的 skill 是自由中文,归类工序需**映射到固定枚举**(细节/主旨/推理/词义/态度/指代/图表/其他),避免同义异名分散统计。
