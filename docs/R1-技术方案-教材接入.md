# R1 技术方案 · 教材接入(单元内容 → 受控匹配 → 单元↔KP 节点边)

> 依据:[重构-KP优先-需求分析.md](重构-KP优先-需求分析.md) 体系② + 路线图 R1;承接 R0(`kp_match_service` / `knowledge_nodes` / `kp_candidates` 已就绪)。
> 原则不变:**不动旧 `knowledge_points` / `unit_knowledge_points` / 旧 persist 路径**(旧前台照常),R1 新增"教材→新知识节点"这条边并把单元抽取接到 `kp_match_service`。这是设计 §6 所说"逐模块切换"的第一个模块。

---

## 0. R1 目标(精确)
把"教材单元"接进 KP-First 骨架:
1. 单元的知识点名(AI 生成 / PDF 上传抽取得到)→ 逐个走 **`kp_match_service`** 受控匹配。
2. 命中 `knowledge_nodes` → 建 **`unit_node`(单元↔知识节点)多对多边**。
3. 未命中 → 落 `kp_candidate`(pending),并在候选上记下"它来自哪个单元"(`source_ref.unit_ids`)。
4. 候选经 R0.4 审核 **approve/merge** 后 → **自动回填** 该单元的 `unit_node` 边(闭环,不让审过的候选与单元失联)。

> 教材层级(版本/学段/学册/单元)**已满足**:`curriculum_units(textbook_version, grade, semester, unit_no)` 四元组唯一键即"完整四级"(grade+semester≈学册,学段由 grade 推导)。R1 **不重构层级表**。

## 2. 新增 / 改动

### 2.1 新边表 `unit_node`(模型 d16 增补 + 迁移 m84)
| 列 | 说明 |
|---|---|
| unit_id PK | → `curriculum_units.id`(ON DELETE CASCADE) |
| node_id PK | → `knowledge_nodes.id` |
| source enum | `ai_extract` / `upload_extract` / `manual`(可演进 varchar) |
| created_at | |
- 多对多:一单元多 KP、一 KP 被多单元引用(KP-First 必然)。**指向新 `knowledge_nodes`,与旧 `unit_knowledge_points` 并存**。

### 2.2 共享学段工具
把 `_stages_from_grades` 移到 `app/services/kp_normalize.py`(或新 `kp_stage.py`),`migrate_kp_to_node.py` 与 R1 共用;`grade→stage` 单一真源。

### 2.3 抽取服务 `curriculum_kp_service.py`(新)
```python
async def extract_unit_nodes(
    db, *, unit_id, kp_names: list[str], source="ai_extract"
) -> ExtractResult:
    """单元知识点名 → 受控匹配 → 建 unit_node 边 / 落候选(带 unit 来源)。"""
```
流程:
1. 取 `unit` → `stage = stages_from_grades([unit.grade])[0]`(axis_hint='knowledge')。
2. 逐名 `match_kp(axis_hint='knowledge', stage_hint=stage, source_type='textbook', source_ref={'unit_id': unit_id})`:
   - 命中(alias/controlled/fuzzy)→ upsert `unit_node(unit_id, node_id, source)`。
   - 未命中 → 已落候选;**把 unit_id 追加进该候选的 `source_ref.unit_ids`**(供审核回填)。
3. 返回 `ExtractResult{matched:[{name,node_id,matched_by}], candidates:[{name,candidate_id}], stats}`。

> `kp_names` 来源 = `AIGeneratedUnit.knowledge_points[].name`(AI 生成或 PDF 上传抽取),复用现有生成器,不重造抽取。

### 2.4 候选审核回填(增强 `kp_candidate_service`)
`approve` / `merge` 成功后:读 `candidate.source_ref.unit_ids`,对每个 unit upsert `unit_node(unit_id, resulting_node_id, source='manual')`。→ 审过的候选自动补上单元边,闭环。

### 2.5 接入点:generate 后自动抽取(**决策 R1-B**)
`persist_unit()` **本体不改**(仍 upsert 旧表供现有前台)。在**生成流程**(单元生成 service / `POST /units/{id}/generate` + 批量学期生成)里,于 `persist_unit` **之后追加一步** `extract_unit_nodes(unit_id, kp_names=该单元 KP 名)`——additive,不影响旧数据路径。效果:每次生成单元,新边 `unit_node` 同步建立、未命中自动入候选。
- `GET /admin/curriculum/units/{unit_id}/nodes` → 查该单元的 `unit_node` 边(含节点名/轴/学段)。
- (可选)`DELETE /admin/curriculum/units/{unit_id}/nodes/{node_id}` 人工解绑;`POST .../extract-kps` 保留为"重跑抽取"入口(幂等)。

## 3. 决策点【✅ 已定 2026-06-17】
- **R1-A 边表 = 新建 `unit_node`(→ knowledge_nodes)** 与旧 `unit_knowledge_points` 并存(贴"不动旧、加新边")。
- **R1-B 抽取触发 = generate 内自动抽取**:`persist_unit` 后追加 `extract_unit_nodes`(additive,旧路径不变);另留显式 `extract-kps` 端点供重跑。
- **R1-C 候选回填 = 自动**:审核 approve/merge 后读 `source_ref.unit_ids` 自动回填 `unit_node` 边,闭环。
- **R1-D 范围 = 只接教材**:学生上传卷/错题抽取留 R3。
