## 0. 顶层原则（北极星）

**唯一核心 = 知识点（标准知识体系 / 知识图谱）。其余全部降级为"资源层"或"投影层"。**

- 教材、真题、仿真题、讲解、视频、词汇、错题、写作素材 …… 一律是**挂在知识点下的资源**，不是独立体系。
- 学生的一切（教材选择 / 上传试卷 / 错题 / 背词 / 练习）→ 都先**定位到知识点**，再在知识点上沉淀"掌握度 + 来源 + 关联资产"。
- 学生个人知识体系 = 标准体系的一个**个性化子集投影**（子集来源：所选教材 / 上传试卷 / 错题 / 机构试卷）。
- **AI 出题铁律**：扩展练习必须有源 —— `错题 → 知识点 → 真题 → 仿真题`；**禁止** `错题 → AI 直接生成`。

```
标准知识体系（唯一核心）
      ▲ 引用/拓展（多对多）
 ┌────┼──────┬──────┬──────┬──────┬──────┐
教材  真题   仿真题  讲解/视频 词汇  写作素材   ← 资源层
      │
      ▼ 个性化投影（子集 + 掌握度 + 来源）
学生个人知识图谱
```

### 0.1 横切原则：三域强边界（平台 / 机构 / 个人）
整个系统的一切实体先归属一个**域**，边界硬隔离。**硬墙在"平台 vs 非平台"之间**；机构与个人同属"非平台上传内容"，靠 scope 再分。

| 平台域（共享·治理·审核发布） | 机构域（机构内共享） | 个人域（按学生私有） |
|---|---|---|
| 标准知识体系（KP 多轴树） | 机构老师上传的试卷/题（机构内老师+其学生可见） | 学生上传内容（试卷/作业/错题原图与拆题） |
| 平台题库（真题、仿真题） | 机构内共享的练习/材料 | 学生作答记录、掌握度、个人知识图谱（投影） |
| 教材体系、学习资源、标准词库、通用词库 | | 个人背词记录、个人错题本 |

**三条铁律：**
1. **非平台 → 平台 只能经"候选审核"单向、且需超管批准**（机构/学生上传里抽出的新知识点只是"建议"进候选池，超管通过才入平台标准体系；机构/学生的**题/答案/错题永不**自动进平台题库）。
2. **平台 → 非平台 只读引用**（机构/个人图谱"引用"平台 KP/题，不反向写平台）。
3. **机构 ↔ 个人**：机构上传题在机构内共享给该机构老师与其名下学生；学生自己上传只属该生。

> KP 标准体系是**平台域共享**（所有人用同一套知识坐标）；个性化只发生在"（学生/机构）× KP 的状态"和"非平台私有题/作答"上。

### 0.2 内容类型：题 vs 语料（passage/audio）
题模型里区分两类内容（避免把"篇章/音频/对话原文"当成"客观题"塞错地方）：
- **题（question）**：可判分的客观/主观题（单选/完形小题/阅读小题/翻译/写作…），挂 KP。
- **语料（passage）**：承载题的篇章/听力音频/对话原文等素材。
  - **结构归属**：在"题型块"一级承载（如 阅读D篇 = 1 段 passage + N 道小题；听力段 = 1 条 audio + N 道小题），小题挂在其 passage 下。
  - **口语场景的"课本原文对话"** = 教材资源（挂教材单元/KP），口语功能从这里取材。
  - passage 同样分域（平台真题的篇章=平台域；学生上传卷的篇章=个人域）。

## 体系① 标准知识体系（核心骨架）—— 待确认

### 1.1 better0617 揭示的关键：标准体系不是一棵树，是**三条正交的轴**

better0617 把"标准体系"明确拆成三块（这是和你聊天里"听说读写+词汇语法"那棵树最大的不同，必须先定）：

- **知识轴（学什么）**：词汇 / 短语 / 句法 / 听力知识 / 阅读知识 / 写作知识。
  - 词汇：按词性 / 构词 / 话题场景 / 频率 多种分类。
  - 短语：动词短语 / 介词短语 / 形容词短语 …（结构骨架）。
  - 句法：简单/并列/复合句、名词性/定语/状语从句、特殊句式、句式转换。
- **能力轴（会不会）**：听力能力 / 阅读能力 / 写作能力 / 口语能力（各自再细分，如 阅读→推理判断、写作→逻辑衔接、听力→信息提取）。
- **考试轴（怎么考）**：题型（听力题型/客观题/主观题）× 考法（动词变形/时态辨析/主旨归纳…）× 难度（学段 小初高 + 认知层级 1–5）。

> **核心建模决策**：你聊天里画的那棵树（高中英语→阅读理解→推理判断 / 语法→定语从句）其实把"能力/题型"和"知识"混在一棵树里了。要先定：

### 1.2 决策点 A（最关键）：单树混合 vs 多轴正交

- **方案甲｜单棵知识树**：学段 → 板块（阅读/完形/语法/写作…）→ 细点，全混一棵。
  - 优点：直观、贴近你画的图、前端一棵树好展示。
  - 缺点：一道"阅读 D 篇推理判断 + 长难句（定语从句）"的题，"推理判断(能力)"和"定语从句(知识)"塞进同一棵树会拧巴；统计/推荐时维度纠缠。
- **方案乙｜多轴正交（推荐）**：一套**知识点节点**带 `axis` 标识（知识/能力/考试）+ 各自的树；任何资产（教材点/真题题/错题/仿真题/词）可**同时挂多个轴的多个节点**（多对多）。
  - 优点：一题可同时标"能力=推理判断""知识=定语从句""题型=阅读理解""难度=层级4"；统计、薄弱诊断、出题来源各取所需，互不污染。学生图谱可按任一轴切看。
  - 缺点：建模/前端略复杂；但这是"知识图谱"该有的样子，长期最省。
- **方案丙｜知识树为主 + 能力/考试为标签**：保留一棵知识树作主干，能力点/题型/难度作为**资产上的标签枚举**（不建独立树）。
  - 折中：比乙轻，比甲清晰；但能力/考试无法形成可下钻的层级。

### 1.3 决策点 B：节点的统一属性（无论哪个方案都要定）
每个标准知识点节点至少含：`轴(知识/能力/考试)`、`学段(小/初/高)`、`父节点(树)`、`名称`、`编码`、`同义词/别名(供 AI 受控匹配)`、`状态(正式/待审)`、`来源(种子/教材抽取/真题抽取)`。

### 1.4 决策点 C：知识体系"从哪来"
better0617：知识体系**自动从教材、真题中摘取**汇入（人教七上、中考真题…），未命中的新点**暂存标准体系待管理员审核**。
→ 含义：标准体系是"**AI 抽取 + 人工审核**持续生长"的，不是一次性灌死的静态树。需要一条 `候选知识点 → 审核 → 正式入库 / 合并到已有` 的治理流程（体系⑩细化）。

### 1.5 与现有实现的差距（体系①范围）
- 现有 `knowledge_points`：有树(parent_id)/学段/教材/category(grammar/vocab/reading/writing/listening)。**category 缺 speaking、缺"能力/考试"轴、缺别名**。
- 现有 AI 归类：**自由命名 + 按名精确匹配** → 产生游离 auto_ 点（碎片化）。重构要改成**受控匹配（喂候选+别名+就近）+ 未命中转候选待审**。

### 1.6 体系① 拟定结论【待确认 —— 否决即改】

> brainstorming 后的推荐默认值。每条给了"为什么"，你只需 确认 / 指出要改的。

- **A. 轴模型 = 多轴正交（方案乙）**。一套 `knowledge_node` 带 `axis ∈ {知识, 能力, 考试}`，各自成树；任何资产（教材点/真题题/错题/仿真题/词）可同时挂多个轴的多个节点（多对多）。
  - 为什么：一道"阅读D篇推理判断+长难句"的题，能力(推理判断)/知识(定语从句)/题型(阅读理解)/难度(L4)四个标签互不污染；诊断、推荐、出题各取所需。这才是"知识图谱"。
- **B. 学段 = 小 / 初 / 高 三段**（标准体系节点只带学段三值；具体年级"初一上"放到**教材层**，不进标准体系轴）。
  - 为什么：标准体系要稳、跨教材通用；年级是教材的属性，不是知识本身的属性（"定语从句"不属于某个年级）。
- **C. 生长方式 = AI 抽取 + 人工审核**。标准体系从教材/真题 AI 抽取知识点；命中已有→挂上；未命中→进"候选知识点"待管理员审核入库或合并。标准体系是**持续生长**的，非一次性灌死。
  - 为什么：英语知识点海量且各教材表述不一，纯人工建不全、纯 AI 会碎片化；抽取+审核是唯一可规模化又可控的路子。
- **D. 节点统一属性**：`axis / 学段 / 父节点 / 名称 / 编码 / 别名aliases[] / 状态(正式·候选) / 来源(种子·教材抽取·真题抽取)`。其中 **`aliases` 是关键**——AI 受控匹配靠它把"过去完成时态/过去完成时"归一，杜绝游离 auto_ 点。

**体系① 状态：【✅ 已确认 2026-06-17】** A=多轴正交 · B=小初高三段 · C=AI抽取+人工审核 · D=节点统一属性含 aliases。

## 体系② 教材体系（资源层 / KP 引用来源）—— 待确认

### 2.1 KP-First 下教材的定位
教材**不是独立体系**，是"知识点的引用来源 + 学生的一个学习入口"。核心边是 **教材单元 → 引用 → 知识点（多对多）**，知识点**不**挂在教材层级下面。
- 一个教材单元涉及多个知识点；一个知识点被多个教材（人教必修二U3 / 外研M2 / 新概念L56）引用 → 多对多。
- 教材**保留自己的层级**（版本/学段/学册/单元）只为两件事：**① 组织上传与关联的粒度；② 学生"按教材学"的入口/进度**。它产出的产品价值 = "单元 ↔ 知识点"的边。

### 2.2 better0617 的教材结构
版本（人教/译林/牛津…）→ 学段（小/中/高）→ 学册（1上…9下）→ 单元（1–9）→ 上传单元内容 → AI 分析单元知识点、与标准体系已有点关联，未命中暂存为候选待审。

### 2.3 决策点
- **决策点 ②-A：教材层级粒度**
  - 甲｜完整四级 版本→学段→学册→单元（贴 better0617；单元为上传/关联粒度）。**推荐**。
  - 乙｜简化两级 版本→单元（弱化学段/学册，靠单元自带标签）。
- **决策点 ②-B：单元↔知识点关系**
  - 甲｜**多对多**（单元引用多 KP，KP 被多单元引用）。**推荐**（KP-First 必然）。
  - 乙｜一对多（一单元多 KP，但 KP 只属一个单元）。会破坏跨教材复用，不推荐。
- **决策点 ②-C：单元内容上传 + 抽取**：上传单元内容（课文/词表/语法点）→ AI 抽取知识点 → 命中标准体系则建"单元→KP"边；未命中 → 候选待审（**复用体系①-C 的生长机制**）。这条若无异议默认采用。

### 2.4 与现有实现差距
现有 `CurriculumUnit`（textbook_version/grade/semester/unit）+ `KnowledgePointContent`（KP×维度讲解）+ `CurriculumWord`（单元↔词）已接近。差距：①单元↔KP 的**显式多对多边表**未必齐（现在更多是 KP 自带 applicable_textbooks 字符串，不够"引用"语义）；②抽取未命中的"候选待审"流程未建。

**体系② 状态：【✅ 已确认 2026-06-17】** A=完整四级(版本/学段/学册/单元) · B=单元↔KP 多对多 · C=单元抽取→候选待审（复用①-C）。

## 体系③ 真题体系（资源层 / 挂 KP，多对多）—— 待确认

### 3.1 定位
真题**不是独立体系**，是挂在知识点下的高质量资源。一份真题（如"2024 全国甲卷 阅读 D 篇"）可关联多个知识点（主旨大意/推理判断/词义猜测/长难句），形成多对多。真题的产品价值 = ① 给知识点提供"权威母题"；② 作为仿真题的**生成来源**（体系④）。

### 3.2 better0617 的真题结构
- 选教材(版本→学段→学册)+地区 → 上传真题（中考 / 高考），按题型结构化存：
  - 中考：听力/口语/单项选择/完形/阅读(A–D篇)/词汇运用/短文填空/阅读表达/句子翻译/书面表达。
  - 高考：听力(短/长对话独白)/阅读(A–D篇、七选五)/语言运用(完形、语法填空)/写作(应用文、读后续写)。
- AI 分析真题知识点、与标准体系关联，未命中待审 → 再对真题生成仿真题。

### 3.3 决策点
- **决策点 ③-A：真题结构化粒度** = 整卷 → 题型块（听力/完形/阅读A–D/语法填空/写作…）→ 小题；**每小题挂 KP**。**推荐**（与上传学生卷的拆题模型对齐，复用同一套题模型）。
- **决策点 ③-B：真题（小题）↔ KP** = **多对多**。**推荐**（KP-First 必然）。
- **决策点 ③-C：真题的归属/检索维度**
  - 甲｜**地区+年份+学段(中考/高考)+题型** 为主组织；与教材的连接**走 KP 间接发生**（高考是统考、跨教材，不直接绑人教/外研版本）。**推荐**。
  - 乙｜直接绑教材版本（版本→学段→学册 + 地区）。贴 better0617 字面，但真题强绑某版本在语义上别扭。

### 3.4 与现有差距
现有 `exam_papers / exam_questions / simulated_questions` 已是"真题+题型+仿真"骨架。差距：①真题小题↔KP 的多对多边、未命中候选待审；②与"学生上传卷"的题模型是否**统一为一套题结构**（值得在体系⑪迁移里合并，避免两套题模型）。

**体系③ 状态：【✅ 已确认 2026-06-17】** A=卷→题型块→小题(每小题挂KP) · B=真题↔KP 多对多 · C=地区+年份+学段+题型组织，教材连接走KP间接。

## 体系④ 仿真题体系（资源层 / 真题派生）—— 待确认

### 4.1 定位（你最强调的铁律）
仿真题**不单独建库**，必须**从真题派生**：`知识点 → 真题 → 仿真题`。AI 生成时有明确母题来源，质量可控、不跑偏。**禁止** `知识点/错题 → AI 直接生成`（无源题）。
- 仿真题结构与真题**完全一致**（同一套题结构/题型）——这条 better0617 已定，直接采用。
- 仿真题**继承来源真题的 KP**（一份真题生成的仿真题，默认带它母题的知识点标签）。

### 4.2 决策点
- **决策点 ④-A：来源约束（铁律刚性）**
  - 甲｜**强制派生自真题**：某 KP 下若无真题母题，则**不生成**仿真题（提示"该知识点暂无母题，待补真题"）。最严，质量最高。**推荐（符合你的铁律）**。
  - 乙｜柔性退化：优先真题派生；该 KP 无真题时**退化为 KP 直接生成**，但标记 `来源=KP直生`、质量较低、可后台关掉。保证学生总有题练。

## 体系⑧ 错题闭环（流程 / KP-First 的核心价值）—— 待确认

### 8.3 决策点
- **决策点 ⑧-A：错题来源统一收口**
  - 甲｜**所有渠道做错的题统一进一个错题本**（上传错题 / 上传卷错题 / 复习再错 / 智能出题做错），统一定位 KP。**推荐**（一个错题中心，避免多套错题模型）。

- **决策点 ⑧-B：扩展练习链 + 冷启动处理**

  - 乙｜无真题时允许"KP 直生"兜底（破铁律，但保证有题练）。
- **决策点 ⑧-C：错题"掌握"判定**
  - 甲｜**原题 + N 道仿真全做对 → 判掌握 → 更新掌握度**，N 后台可配（默认如 3）。**推荐**（贴 better0617"1 原题+几仿真"）。

### 11.4 ⑪-B 修正：题模型按"平台/个人域"物理分域（不是一张大表）

> 回应你的两点：① 学生多→表压力；② 真题/仿真是平台级，学生卷/错题是个人级，**个人内容不能进平台**。原"统一一张 question 表"改为**统一题结构/逻辑、但按域物理分表**：

- **`platform_question`（平台题库，共享）**：真题 + 仿真题（"练习题"= 仿真，无独立类型）。审核发布、挂 KP、全员共享。量级 = 题库规模，与学生数无关。**物理独立**——这是硬墙。
- **`uploaded_question`（非平台上传题）**：机构老师上传 / 学生上传 的拆题，`owner_scope ∈ {institution, student}` + `owner_id` + RLS。**永不进 platform_question**；可挂 KP（仅供机构内/个人图谱）。机构与个人在此表内靠 scope 隔离。
- **`passage`（语料，分域）**：篇章/音频/对话原文，挂在"题型块"级，小题引用其 passage_id；同样有 scope（平台/机构/个人）。
- **`wrong_record`（错题事件，窄表）**：`owner_id + (source_table, question_id) + 结果/时间`。错题**不是题类型**，是"答错了某道题"的事件，指向 platform_question 或 uploaded_question。
- **`answer_log`（作答事件，窄表）**：同上结构，记每次作答 → 算掌握度。学生多→大表就是它，按 学生/时间 分区。

**共享的是"题结构与拆题/归类/渲染逻辑"（一套 service/schema 形状），物理分表保证平台与个人结构性隔离、不可能误混。** 容量上：平台题表小且共享；个人题表/作答表按学生分区，可控。

> **决策点 ⑪-B'【✅ 已确认 2026-06-17】= 物理分表**（platform_question / student_question 两张物理表，同一套列结构与 service 逻辑；wrong_record / answer_log 为个人窄表）。结构性杜绝个人内容越界进平台。
