# 真题模块科学分析与仿真落地 · 可行性报告

> 版本:v1(2026-07-05)。本报告**只使用三类依据**:①本库真题实测统计(SQL 可复跑);②仓库内已实现且带测试的代码;③有名有姓的测量学/学习科学方法。凡未验证的均明确标注「假设/待验证」。

---

## 一、结论先行

1. **技术管线可行,且大部分已实现并通过测试**(P0–P2a 共 9 个已合入 main 的提交,详见 §5)。
2. **当前真正的瓶颈不是技术,是数据标注覆盖率:存量 12,838 道真题的考点(KP)挂载率为 0%**(2026-07-05 实测)。管线是「考点驱动」的——没有标注,派生、练习、学情全部空转。
3. 落地关键路径 = **标注(自动预标+AI受控匹配+人工确认)→ 派生仿真(继承考点)→ 审核发布 → 作答数据回流校准难度**。第一步已有可立即执行的杠杆:rc 规则补标脚本 dry-run 实测**可零成本精准标注 884 道阅读题**。

## 三、统一分析框架(每个模块都过这六步)

科学依据均为测量学/学习科学的成熟方法,不自造概念:

| 步骤 | 方法 | 依据 | 本项目落点 |
|---|---|---|---|
| ① 测什么(构念) | 把模块映射到考点轴 | 内容效度 / **双向细目表**(test blueprint) | `k-*`/`rc-*`/`wr-*` 图谱(已建) |
| ② 考频权重 | 近5年频次分布 | 蓝图抽样代表性 | §2.2 表(已测) |
| ③ 拆解粒度 | 整题→单空/单问微题 | 一题一构念,便于诊断 | 存储层已逐空/逐问一行(已确认) |
| ④ 判分方式 | 客观=字符串/形态;主观=LLM 评分 | CTT 客观计分;主观评分需评分量规(rubric) | `_grade` + 阅读表达/作文 LLM 批改(已实现) |
| ⑤ 仿真生成约束 | 同考点·同题型·同难度改写;或考点反向生成含**判定线索**的题 | 平行试题(parallel forms)原则 | `generate_sim_from_real` / `generate_fallback_sim`(已实现) |
| ⑥ 掌握与复习 | 弱项驱动 + 间隔重复 | **BKT**(Corbett & Anderson 1994,参数已在 `mastery_judge_service`:L0=0.25,T=0.18,G=0.20,S=0.10)+ **SM-2**(`wrong_record`)+ 检索练习效应(testing effect) | 自适应练习/错题闭环(已实现) |

难度校准路线(诚实版):作答量小(181 条)时**先用命题难度 1–5 作先验**,随作答积累用 **CTT 通过率(p 值)/区分度**渐进回填;IRT 等作答量足够(经验上单题 ≥200 作答)再上,现在上是伪科学。

## 四、逐模块分析与落地方案

> 「现状」列:✅=已实现并有测试;🔶=部分实现;❌=缺口。

### 4.1 单项选择/填空(5年 758 题,22%)
- **构念**:单点语法/词汇探针,一题≈1 个 `k-*` 叶子(时态/代词/介词/连词/辨析)。
- **判分**:选项字母精确比对 ✅。
- **仿真**:①真题派生(同考点换情境)✅;②KP 反向生成 `grammar` 维度 ✅。
- **前端学习策略**:单点刻意练习+即时反馈(`v2-session`)、BKT 弱项自适应(`adaptive`)✅。
- **缺口**:❌ 存量标注 0 → 需 AI 整卷匹配(admin 已有入口)+人工确认。

### 4.2 完形填空(5年 721 题,21%)
- **构念**:逐空异构——实词辨析(`k-*`)、搭配/介词、逻辑衔接(`rc-6-1`)、语境推断(`rc-4`)。**必须逐空标注,整篇打一个标签无诊断价值**。
- **存储**:已逐空一行、共享 `block_id→Passage` ✅;练习端已带短文上下文渲染 ✅。
- **仿真**:①整组改写保每空考点(`generate_sim_for_block`)✅;②`cloze` 单空微题反向生成 ✅。
- **前端策略**:先单空微题按考点补弱,再整篇限时(先分解后整合,刻意练习原则)。🔶 前端"先微题后整篇"的编排未做。
- **缺口**:❌ 逐空考点标注 0。完形空的问法无规律,**只能走 LLM 受控匹配+人工确认**,成本最高的模块。

### 4.3 阅读理解(选择)(5年 823 题,24%)
- **构念**:`rc-1`细节 / `rc-2`主旨 / `rc-3`推理 / `rc-4`猜词 / `rc-5`态度 / `rc-6`结构,一问一微技能。
- **独有优势:问法可确定性分类**。已实现 `classify_reading_skill`(问法→rc 叶子,10 类问法规则,宁缺勿错),**dry-run 实测:3,835 道阅读题中 884 道可零 LLM 精准标注**(细节 305、猜词 162、标题 125、推理 109、主旨 105、指代 41、情感 30、目的 7),其余 2,951 交 LLM/人工。
- **仿真**:`reading` 维度反向生成(短文+单技能一问,干扰项按该技能典型陷阱)✅。
- **前端策略**:按 rc 子技能出分项正确率(「细节 90%、推理 50%」),弱技能定向练 ✅(数据就绪后自动生效)。
- **缺口**:❌ 执行 `backfill_rc_skills.py --apply`(脚本已写好、dry-run 已验证,待批准)。

### 4.4 词汇运用(5年 555 题,16%)+ 动词填空(45 题)
- **构念**:**产出正确词形**(复数/比较级/派生/动词形态),与"选对"是不同能力(接收 vs 产出,与词力通双维 BKT 一致)。
- **判分**:候选集字符串比对(`goes|go`)✅。
- **仿真**:`vocab_form`/`verb_fill` 反向生成,prompt 强制**句内自带判定线索、答案唯一/有限** ✅;物化已放行进练习流 ✅。
- **前端策略**:变形规则分桶练(名词复数桶/比较级桶/时态桶),错后同桶再练(SM-2)✅链路就绪。
- **缺口**:❌ 存量标注;🔶 变形类型自动归桶(词尾特征可写规则,类似 rc 分类器,**建议做**)。

### 4.5 短文填空/首字母/选词填空(5年 ~271 题)
- 构念=词汇语义+拼写+`rc-6` 语境;判分字符串 ✅;已进练习流(P0 补齐)✅;标注同样 ❌。首字母题干带首字母约束,反向生成 prompt 需加该约束(🔶 小改)。

### 4.6 任务型阅读/信息还原(5年 190 题)
- 构念:`rc-1`/`rc-6`(信息还原**只考 rc-6 篇章衔接**——逻辑关系/句子还原/指代)。rc 分类器可扩 3–5 条问法规则覆盖其常见形态(🔶)。

### 4.7 阅读表达(主观简答,5年 113 题)
- **构念**:`rc-*` 定位 + `wr-2` 语言产出,双构念。
- **判分**:LLM 评分量规(逐要点命中+语言扣分),**参考答案服务端持有防作弊** ✅;miss 落 KP 错题闭环 ✅;前端自测/按题练两模式 ✅(浏览器实测)。
- **待验证(诚实标注)**:LLM 判分与人工判分的一致性未测。落地动作:抽 50 题人工双评,算与 LLM 的一致率(目标 ≥90% 要点判定一致),不达标改 prompt/换模型。

### 4.8 书面表达(5年 86 题)
- 构念:`wr-1`内容/`wr-2`准确/`wr-3`丰富/`wr-4`连贯/`wr-6`体裁。`essay_service` 已按维度 LLM 评分+逐处批注 ✅。仿真=换话题保体裁(题目生成成本低)。一致性验证同 4.7。

### 4.9 补全对话(13 题)/ 听力
- 补全对话:题量过小,**不值得建独立管线**,归入"其他"人工处理。
- 听力:**库里几乎无听力语料**,不做(此前已勘察确认)。做了才是胡说八道。

## 六、分期落地计划(按依赖排序)

**Phase A · 标注攻坚(当前瓶颈,人机协同)**
1. 执行 rc 补标 `--apply`:+884 道阅读题精准 rc 标注,零 LLM 成本。【脚本就绪,待批准】
2. admin「AI 整卷匹配」批量跑近5年卷(单选/词汇运用/动词填空优先——占比高且构念单一),人工逐题 ✓ 采纳。目标:**近5年 2,902 道核心客观题标注率 ≥80%**。
3. 完形逐空标注最后做(成本最高)。
4. 词形归桶规则分类器(仿 rc 分类器,词尾特征确定性归桶)。

**Phase B · 批量派生与发布**
5. 按模块跑 `gen-sim-bulk`(每母题 2–3 变体,继承考点),draft→人工审核→published→物化进练习。
6. 主观题判分一致性抽检(4.7/4.8 的 50 题双评)。

**Phase C · 数据回流校准**
7. 作答量起来后按 CTT 回填题目难度(p 值),替换命题先验;BKT 弱项引擎自动受益。
8. 前端按模块出「rc 子技能分项报告 / 词形分桶报告」(数据就绪即可做,接口已有聚合基础)。

**风险与对策**
- LLM 标注漂移 → 受控目录(只能选已有节点)+人工 ✓ 采纳,已是现行设计。
- 主观判分不一致 → 双评抽检门槛,不达标不放量。
- 作答数据不足 → 难度先验+渐进校准,不提前上 IRT。
- 多会话并发开发 → 每刀独立文件域+分支提交(本会话已验证的工作方式)。
