# R0 · 系统/数据库设计（骨架与对齐）

> 依据：`docs/重构-KP优先-需求分析.md`（已定稿）。本阶段只设计、待评审，不写代码。
> R0 目标：立**知识骨架 + 对齐机制**——多轴 knowledge_node、别名、候选审核、受控匹配；并建好"统一题（分域）+ 个人窄表"的**空骨架**（数据灌入在 R1+）。立住它，后面教材/真题/错题/词/图谱才有处可挂。

## 2. 知识骨架（核心）

### 2.1 `knowledge_node`（多轴知识节点）
| 列 | 类型 | 说明 |
|---|---|---|
| id | uuid PK | |
| axis | enum(`knowledge`/`ability`/`exam`) | 三轴正交，决定属于哪棵树 |
| node_kind | varchar | 轴内子类型（知识:词汇/短语/句法/听力知识/阅读知识/写作知识；能力:听/说/读/写；考试:题型/考法/难度层级）|
| parent_id | uuid FK self, null | 树形（同 axis 内） |
| name | varchar | 规范名（如"定语从句"） |
| code | varchar unique | 稳定编码（非 auto_ 随机；如 `gram.attr_clause`） |
| applicable_stages | text[] | 适用学段 {小/初/高}（可多值；"定语从句"=初+高） |
| status | enum(`active`/`candidate`/`retired`) | candidate=未审核（一般在 kp_candidate，正式入库即 active）|
| source | enum(`seed`/`textbook`/`exam`) | 来源 |
| description | text null | |
| sort_order | int | |
| created_at/updated_at | timestamptz | |

- 索引：`(axis, parent_id)`、`(axis)`、`code unique`、`applicable_stages` GIN。

### 2.2 `node_alias`（别名归一 —— 杜绝碎片化的关键）
| 列 | 类型 | 说明 |
|---|---|---|
| id | uuid PK | |
| node_id | uuid FK knowledge_node | |
| alias | varchar | 别名/同义写法（"过去完成时态"→归"过去完成时"）|
| alias_norm | varchar | 归一化（去空格/全半角/大小写）用于匹配，**唯一**保证一个写法只指一个节点 |
| source | enum(`seed`/`merge`/`extract`) | merge=审核时合并产生 |

- 唯一：`alias_norm` 全局唯一（同一写法不能指向两个节点）。

### 2.3 `node_relation`（轴间/同轴关联，可选 R0 建表）
跨轴/跨节点的弱关系（如 能力"推理判断" 常考于 题型"阅读理解"；知识"定语从句" 关联 能力"长难句分析"）。
| 列 | 类型 |
|---|---|
| from_node_id / to_node_id | uuid FK |
| relation | enum(`related`/`assessed_by`/`prereq`) |
| PK(from,to,relation) | |
> R0 先建表，关系数据后续补；不阻塞。

### 2.4 `kp_candidate`（候选知识点 + 审核）
| 列 | 类型 | 说明 |
|---|---|---|
| id | uuid PK | |
| raw_name | varchar | AI 抽取的原始名 |
| name_norm | varchar | 归一化（用于聚合同一候选） |
| suggested_axis / suggested_stage | | AI 建议 |
| occur_count | int | 出现次数（聚合，越高越该优先审）|
| context_sample | jsonb | 抽取上下文（题干/单元/来源）|
| source_type | enum(`textbook`/`exam`/`uploaded_student`/`uploaded_institution`) | |
| source_ref | jsonb | 来源对象引用 |
| status | enum(`pending`/`approved`/`merged`/`rejected`) | |
| merged_into_node_id | uuid null | merged 时指向归并到的节点 |
| reviewed_by / reviewed_at | | |

- 唯一：`(name_norm, suggested_axis)` 聚合同名候选（occur_count++）。
- 审核动作：approve→建 knowledge_node(active)；merge→把 raw_name 写进目标节点 node_alias；reject→关闭。

## 3. 受控匹配服务（替换"自由命名+精确匹配"）

**输入**：一段内容抽取出的"知识点候选名"（中文）+ 上下文（学段/教材/axis 提示）。
**目标**：尽量命中已有 `knowledge_node`，命中不了才进 `kp_candidate`。

**匹配管线（短路顺序）**：
1. **归一化精确**：name_norm 命中 `knowledge_node.name` 或 `node_alias.alias_norm` → 直接命中。
2. **受控选择**：把"该 axis + 学段 下的候选节点清单（名+别名）"喂给 LLM，让它**从清单里选**（"选不中"才允许 NONE）。→ 命中即用。
3. **模糊兜底**：编辑距离/包含/分词重叠 阈值内的最近节点 → 命中（标记 `fuzzy`，可让审核复核）。
4. **都不中** → 写/累加 `kp_candidate`（occur_count++），**不**自动建节点。

> 可选增强（R0 后）：节点名向量化做语义就近匹配。R0 先用 1–3，够用且省。

**抽取入口统一**：教材单元/真题/学生卷/作业 抽 KP **都走这一个服务**，口径一致。

## 4. 统一题模型（分域骨架，R0 只建表）

### 4.1 `platform_question`（平台题：真题/仿真，硬独立）
| 列 | 说明 |
|---|---|
| id PK | |
| type enum(`real`/`sim`) | 真题/仿真 |
| parent_real_id uuid null | sim 派生自哪道真题（real 为 null）|
| is_fallback bool | true=KP直生备选（无真题母题时）|
| deprecated_at timestamptz null | 该 KP 有真题后，KP直生备选废弃时间 |
| block_id uuid null | 所属题型块（→ passage）|
| question_no / question_type enum / stem / options jsonb / answer / explanation | 题内容 |
| difficulty smallint | 认知层级 1–5 |
| meta jsonb | 真题元信息（地区/年份/学段）|
| status enum(`draft`/`published`/`retired`) | |

### 4.2 `uploaded_question`（非平台上传题：机构/个人）
| 列 | 说明 |
|---|---|
| id PK · owner_scope enum(`institution`/`student`) · owner_id uuid | 域隔离（RLS）|
| paper_id uuid · block_id uuid null | 来源卷/题块 |
| question_no/question_type/stem/student_answer/correct_answer/explanation | |
| is_wrong bool | |
> **永不进 platform_question**（物理独立=硬墙）。

### 4.3 `passage`（语料，分域）
| 列 | 说明 |
|---|---|
| id PK · scope enum(`platform`/`institution`/`student`) · owner_id null | |
| kind enum(`reading_text`/`audio`/`dialogue`) · text/audio_url · source_ref | 篇章/听力音频/对话原文 |

### 4.4 题↔KP 关联（两张，FK 完整）
- `platform_question_kp(question_id, node_id)` PK；`uploaded_question_kp(question_id, node_id)` PK。
- 多对多；一道题多 KP，一 KP 多题。

## 5. 个人域窄表（R0 建表骨架）

- `student_kp`（个人知识图谱投影）：PK(student_id, node_id)；mastery numeric、practice_count、wrong_count、last_practice_at、source_tags text[]、in_scope bool。
- `answer_log`（作答事件，分区）：student_id、q_scope enum(`platform`/`uploaded`)、question_id、is_correct、feature、answered_at。**按月/学生分区**。
- `wrong_record`（错题事件）：student_id、q_scope、question_id、node_id（定位 KP）、is_original bool、status enum(`open`/`mastered`)、created_at、mastered_at。

---

## 6. 与现有 `knowledge_points` 的过渡（渐进，不停机）

- R0 **新建** `knowledge_node` 等，不动现有 `knowledge_points`/业务代码。
- 一次性**种子迁移**：把现有 `knowledge_points`（含 category/grades）映射进 `knowledge_node`（axis=knowledge 为主，category→node_kind，grades→applicable_stages，旧名→name，旧 auto_ 名→并入 alias 由审核归并）。
- 新抽取/新功能写 `knowledge_node`；旧模块读 `knowledge_points` 暂不动，按 R1+ 逐个切换映射，切完废弃旧表。

---

## 7. R0 验收标准
- [ ] 传一段内容 → 受控匹配：命中已有节点（含别名）直接挂；命中不了 → 进 kp_candidate（occur_count 聚合）。
- [ ] 超管审核候选：approve 建节点 / merge 归并为别名 / reject。
- [ ] 复跑同类内容**不再产生游离 auto_ 节点**（碎片化被治住）。
- [ ] platform/uploaded/passage/个人窄表 建表完成、域隔离（RLS）就绪（暂无数据灌入）。
- [ ] 现有功能不受影响（旧表旧代码照常）。

## 8. 设计开放点【✅ 已确认 2026-06-17】
1. **node_kind = 按提议**：知识(词汇/短语/句法/听力知识/阅读知识/写作知识)、能力(听/说/读/写)、考试(题型/考法/难度)。
2. **种子迁移**：现有 `auto_*` 游离点**全部转 `kp_candidate` 待审**（approve/merge别名/reject），骨架从一开始干净。
3. **受控匹配 = 先轻量**：归一化精确 + 候选清单受控选择 + 编辑距离模糊兜底；**不上向量**（留作 R0 后增强）。
4. **题↔KP = 两张 FK 表**：`platform_question_kp` / `uploaded_question_kp`，FK 完整、与物理分域一致。

## 9. R0 实现计划（设计已定，待开工）
按依赖顺序、小步可验收：
- **R0.1** 迁移建表：`knowledge_node` / `node_alias` / `node_relation` / `kp_candidate`（+ 索引/枚举）。
- **R0.2** 种子迁移脚本：`knowledge_points` → `knowledge_node`（正常点 active；`auto_*` → kp_candidate 待审），别名表回填。
- **R0.3** 受控匹配服务 `kp_match_service`（归一化+清单选择+模糊；统一抽取入口调用）+ 候选累加。
- **R0.4** 超管审核：候选队列 API + 后台页（approve/merge别名/reject）。
- **R0.5** 题分域 + 个人窄表 **建表骨架**（platform_question/uploaded_question/passage/两张KP表/student_kp/answer_log/wrong_record），RLS 就绪，暂不灌数据。
- **R0.6** 测试：受控匹配命中/候选/合并；复跑不产生游离点；验收 §7。
> 全程不动现有 `knowledge_points` 与旧代码（旧功能照常），R1+ 再逐模块切换。
