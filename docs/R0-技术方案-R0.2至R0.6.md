## R0.2 · 种子迁移脚本(`knowledge_points` → `knowledge_node`)

### 目标
把现有 `knowledge_points` 一次性映射进新域,且**幂等、可复跑、带 --dry-run**:
- **标准点**(code 非 `auto_` 前缀)→ `knowledge_node`(active),并回填 `node_alias`。
- **游离点**(code 以 `auto_` 开头)→ `kp_candidate`(pending),交 R0.4 审核归并,**不**直接建节点。骨架从第一天就干净(设计 §8-2)。

### 现状锚点(已核实)
- 旧模型:[`backend/app/models/d4_knowledge.py:29`](../backend/app/models/d4_knowledge.py) `KnowledgePoint(code unique / name / category enum{grammar,vocabulary,reading,writing,listening} / description / applicable_grades[] / applicable_textbooks[] / parent_id / sort_order)`。
- 标准 code 形如 `yl-g5s1-u1-kp1`(见 `curriculum_service.persist_unit`),游离 code 形如 `auto_{slug}_{uuid8}`(见 [`practice_service.py:75`](../backend/app/services/practice_service.py))。
- 新模型:[`d15_knowledge_graph.py`](../backend/app/models/d15_knowledge_graph.py) `KnowledgeNode / NodeAlias(alias_norm unique) / KpCandidate(unique(name_norm, suggested_axis))`。

### 新增文件
| 文件 | 作用 |
|---|---|
| `backend/app/services/kp_normalize.py` | **共享归一化工具**(R0.2/R0.3/R0.4 全依赖) |
| `backend/scripts/migrate_kp_to_node.py` | 迁移脚本(独立、幂等、`--dry-run`) |
| `backend/tests/api/test_kp_seed_migration.py` | 迁移测试(R0.6 内) |

> 用独立脚本而非 alembic 数据迁移:与现有 `scripts/seed_curriculum.py` 一致,便于反复跑、改规则、出报告。**【✅ 决策①】**

### `kp_normalize.py`
```python
def normalize_kp_name(raw: str) -> str:
    """KP 名归一:NFKC 全角→半角、去首尾空白、去内部空白、剥离尾部标点与引号。
    中文不做同义改写(留给别名/审核)。结果用于 alias_norm / candidate.name_norm 的唯一键。"""
```
- 规则刻意"轻":只做**确定性**归一(大小写/全半角/空白/标点);语义同义("过去完成式"vs"过去完成时")**不在这里合并**,交受控匹配(R0.3 步2/3)与人工审核(R0.4 merge 别名)。
- 单测覆盖:全角括号、CET 词中英混排、多空格、尾部句号/引号。

### 映射规则
**category → axis / node_kind**(legacy 标准点全部落 `knowledge` 轴;能力/考试轴 R0 不从 legacy 生,后续单独种子):
| 旧 category | 新 axis | 新 node_kind |
|---|---|---|
| grammar | knowledge | 句法 |
| vocabulary | knowledge | 词汇 |
| reading | knowledge | 阅读知识 |
| writing | knowledge | 写作知识 |
| listening | knowledge | 听力知识 |

**applicable_grades → applicable_stages**:`"小学5年级"→"小"`、`"初中7年级"→"初"`、`"高中…"→"高"`,去重成 `["小","初","高"]` 子集。

**字段直迁**:`code`(复用旧 code,稳定且 unique,**保住与旧关联的可追溯**)、`name`、`description`、`sort_order`;`status='active'`、`source='seed'`。

### 执行流程(两遍 + 报告)
1. **Pass 1 建节点**:遍历标准点 → upsert `knowledge_node`(按 `code` 幂等,已存在则跳过),构建 `code → new_node_id` 映射;同时为每个节点写 `node_alias(alias=name, alias_norm=normalize(name), source='seed')`。
2. **Pass 2 接树**:用映射回填 `parent_id`(旧 parent 的 code → 新 id;旧多数 parent 为空)。
3. **游离点 → 候选**:遍历 `auto_` 点 → `kp_candidate` upsert,`ON CONFLICT (name_norm, suggested_axis) DO UPDATE occur_count = occur_count+1`;`suggested_axis` 由 category 推断(**默认 `knowledge`,不留 NULL**,规避唯一键 NULL 去重失效,见 R0.3 注),`suggested_stage` 取 grades 首段,`source_type='legacy_auto'`,`context_sample` 存旧 id/name。
4. **冲突处理**:两个标准点 `normalize(name)` 撞同一 `alias_norm`(unique 冲突)→ **不崩溃**:跳过后者、记入"待人工归并"报告(这是真重复,本就该合并)。
5. **报告**:打印 `标准→节点 N / 别名 N / 游离→候选 N(去重前 M) / 冲突跳过 N`;`--dry-run` 只算不写。

### 验收(并入 R0.6)
- 复跑两次结果一致(幂等);标准点全部成 active 节点且名进别名;`auto_*` 全部进候选 pending;无脏写旧表。

## R0.3 · 受控匹配服务 `kp_match_service`

### 目标
一个统一入口:输入抽取出的"知识点名 + 上下文",尽量命中已有 `knowledge_node`,命中不了才累加 `kp_candidate`——**替换** `practice_service.get_or_create_knowledge_point` 那套"自由命名 + 按名精确 + 建 auto_ 点"。

### 现状锚点(已核实游离点产生链)
- `get_or_create_knowledge_point`([`practice_service.py:63`](../backend/app/services/practice_service.py)):按 `name==` 精确查,查不到就建 `auto_` 点 → **碎片化源头**。
- 3 处调用:[`user_paper_service.py:88`](../backend/app/services/user_paper_service.py)(整卷管线主源)、`practice_service.py:147`、`practice_service.py:142`(诊断兜底)。
- 归类产名:`kp_classifier_service.classify_kps()` 返回 `{题号: 中文KP名}`([`kp_classifier_service.py:44`](../backend/app/services/kp_classifier_service.py)),dev 有 mock。

### 新增文件
| 文件 | 作用 |
|---|---|
| `backend/app/services/kp_match_service.py` | 受控匹配主服务 |
| `backend/app/schemas/kp.py` | `MatchResult` 等 DTO(R0.3/R0.4 共用) |
| `backend/tests/api/test_kp_match_service.py` | R0.6 内 |

### 接口
```python
@dataclass
class MatchResult:
    node_id: uuid.UUID | None
    matched_by: str        # exact | alias | controlled_llm | fuzzy | candidate
    candidate_id: uuid.UUID | None
    confidence: float

async def match_kp(
    db, *, raw_name: str,
    axis_hint: str = "knowledge",     # 默认 knowledge,避免候选唯一键 NULL 去重失效
    stage_hint: str | None = None,    # 小|初|高
    source_type: str,                 # textbook|exam|uploaded_student|uploaded_institution
    source_ref: dict | None = None,
    context: str | None = None,
    use_llm: bool = True,             # 关掉则只走 1+3+5(离线/省钱)
) -> MatchResult: ...
```

### 匹配管线(短路,设计 §3)
1. **归一化精确**:`name_norm = normalize(raw_name)` → 查 `node_alias.alias_norm == name_norm` → 命中(`alias`)。(别名表已在 R0.2 回填了所有节点名,故无需再单独比 node.name。)
2. **受控选择(LLM)**:取 `axis_hint(+stage_hint)` 下的节点清单(名+别名,**限量**,如按 node_kind 再缩)喂 LLM:"从清单里选最匹配的,选不中返回 NONE"。命中 → `controlled_llm`。复用 `kp_classifier_service` 的 DeepSeek 客户端 + dev mock;`use_llm=False` 跳过。
3. **模糊兜底**:在同 axis(+stage)节点名/别名上算 编辑距离 / 包含 / 分词重叠,过阈值取最近 → `fuzzy`(置信度低,建议 R0.4 复核;R0 仅在结果里标记,不阻断)。
4. **都不中 → 候选**:`kp_candidate` upsert `ON CONFLICT (name_norm, suggested_axis) DO UPDATE occur_count+1` 并追加 `context_sample`;返回 `candidate`、`node_id=None`。

> **唯一键 NULL 陷阱(重要)**:`kp_candidate` 的 `UniqueConstraint(name_norm, suggested_axis)` 里 `suggested_axis` 若为 NULL,PG 视多 NULL 互不相等 → 同名候选会重复堆积,违背"去重累加"。**对策**:`match_kp` 与 R0.2 一律传非空 `axis_hint`(默认 `knowledge`)。**【✅ 决策②】** 采用非空 axis;`coalesce` 表达式唯一索引作为可选加固。

### 独立抽取入口(满足验收,不动线上)
```python
async def extract_and_attach(db, *, items: list[str], scope, owner_id, source_type) -> list[MatchResult]
```
- 给"传一段内容→抽 KP→受控匹配"一个干净的可测入口(§7 第1/3 条直接打这里)。
- **线上 `user_paper_service` 管线本期不切**:仍走旧 `get_or_create_knowledge_point` 写旧表;R1 教材/真题接入时,把抽取统一改调 `match_kp` 并写新域(`uploaded_question_kp` / `platform_question_kp`)。**【✅ 决策③】** 本期只交服务+独立入口+测试,线上管线 R1 统一切——系统未上线,无 auto_ 增长之忧,不背新旧关联表并存的过渡复杂度。

## R0.5 · 题分域 + 个人窄表(纯 DDL 建表骨架,不灌数据)

### 目标
按设计 §4-5 建 8 张表,**结构隔离硬墙**就位,暂不写业务、不灌数据。

### 新增文件

### 表(对齐设计 §4-5)
1. **`platform_question`**(平台题,硬独立):`id / type(real|sim) / parent_real_id→platform_question.id(self,null) / is_fallback bool / deprecated_at / block_id→passage.id(null) / question_no / question_type / stem / options jsonb / answer / explanation / difficulty smallint / meta jsonb / status(draft|published|retired)`。
2. **`uploaded_question`**(非平台,机构/个人):`id / owner_scope(institution|student) / owner_id / paper_id / block_id→passage.id(null) / question_no / question_type / stem / student_answer / correct_answer / explanation / is_wrong bool`。**无任何指向 platform_question 的外键**(物理硬墙)。
3. **`passage`**(语料,分域):`id / scope(platform|institution|student) / owner_id null / kind(reading_text|audio|dialogue) / text / audio_url / source_ref jsonb`。
4. **`platform_question_kp`**(PK `question_id, node_id`;node_id→`knowledge_nodes.id`)。
5. **`uploaded_question_kp`**(PK `question_id, node_id`;node_id→`knowledge_nodes.id`)。
6. **`student_kp`**(个人图谱投影,PK `student_id, node_id`):`mastery numeric / practice_count / wrong_count / last_practice_at / source_tags text[] / in_scope bool`。
7. **`answer_log`**(作答事件):`id / student_id / q_scope(platform|uploaded) / question_id / is_correct / feature / answered_at`。
8. **`wrong_record`**(错题事件):`id / student_id / q_scope / question_id / node_id→knowledge_nodes / is_original bool / status(open|mastered) / created_at / mastered_at`。

> KP 关联只指向**新 `knowledge_nodes`**(不再连旧 `knowledge_points`),与 R0.2 迁移结果对齐。

### 两个必须拍板的工程点
- **【✅ 决策④】RLS 落地方式 = 应用层 scoped 过滤**:本项目**现无 Postgres RLS**(全靠应用层 `owner_id/institution_id` 过滤,已核实)。R0.5 只加 `scope/owner_id` 列 + 索引 + 共享查询助手 `scoped(query, scope, owner_id)` 统一强制过滤;**不引入 PG RLS**(避免新增一套与现有不一致的机制)。PG RLS 留作上线前安全硬化项。
- **【✅ 决策⑤】`answer_log` 分区 = 建表即月分区**:声明 `PARTITION BY RANGE (answered_at)` + 一个默认分区 + `create_answer_log_partition(year, month)` 助手。现在没数据、几乎零成本,避免 R4 有数据后再改分区的表重写。

### 范围
R0.5 **只建表 + schema 测试**,无 service/API。题数据灌入与业务在 R2(平台题)/R3(错题)/R4(个人图谱)。
