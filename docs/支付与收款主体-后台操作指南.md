# 支付与收款主体 · 后台操作指南

> 面向运营/你本人。讲清楚：钱由哪个主体收、密钥怎么填、怎么加公司/渠道、退款怎么走、安全怎么保。
> 配套技术文档：`微信支付接入清单.md`（申请细节）、`决策归档.md` D-148/支付系列。

---

## 一、整体设计（一图理解）

```
订单 ──下单时按"学生城市"路由并固化──▶ 收款主体(payment_account)
                                          │  每个主体 = 一个营业执照 + 一个支付渠道
                                          │  类型：个体 / 公司 / 子公司
                                          │  渠道：微信 / 支付宝 / 苹果IAP / ...
退款 ──按订单固化的主体──▶ 原路退回当初收款的那个商户（铁律）
```

**三个核心概念**
- **收款主体（payment account）**：一个能收钱的商户身份。个体、公司、各地子公司都各是一个主体。
- **支付渠道（provider）**：微信支付 / 支付宝 / 苹果IAP……同一主体可按渠道各建一条。
- **密钥三件套（以微信为例）**：
  - `WECHAT_PRIVATE_KEY_PEM`（API证书私钥）= 给我们的请求**签名**（下单/退款）
  - `WECHAT_PLATFORM_PUBLIC_KEY_PEM`（微信支付公钥）= **验**微信回调的签名
  - `WECHAT_API_KEY_V3`（32位）= **解密**微信回调内容

**钥匙怎么存（安全核心）**：所有渠道密钥**加密后存数据库**，后台录入；服务器只放**一个主密钥** `FIELD_ENCRYPTION_KEY` 用来加解密。明文永不落库、后台永不回显、加公司加渠道不用动服务器。

## 二、一次性准备（运维做一次）

服务器 `.env` 配置一个主密钥（**设一次，永久不动**）：
```bash
openssl rand -base64 32        # 复制输出
# 写入 /opt/enggramer/.env：
FIELD_ENCRYPTION_KEY=<上面的输出>
WECHAT_PAY_SKIP_SIG_VERIFY=false   # 生产必须 false（启用回调验签）
WECHAT_PAY_REFUND_ENABLED=true     # 允许真实退款
```
> ⚠️ **`FIELD_ENCRYPTION_KEY` 丢失 = 所有已存密钥无法解密**。请离线备份（如密码管理器/保险箱），切勿改动。

部署到 m57 后执行一次种子（建默认个体主体 + 回填老订单）：
```bash
cd backend && python -m scripts.seed_payment_account
```

## 三、配置微信支付（阶段①：个体工商户，现在就能上）

**第 1 步 · 在微信商户平台申请**（pay.weixin.qq.com，详见 `微信支付接入清单.md`）
1. 商户号 mchid（已有）
2. **商户API证书** → 下载 `apiclient_key.pem`（私钥）+ 记证书序列号
3. **微信支付公钥** → 下载 `pub_key.pem`（公钥）
4. **APIv3密钥**（32位）→ 设置并立刻保存

**第 2 步 · 后台填非密信息**
进入 admin →「🏦 收款主体」→ 默认那条（个体）→「编辑」：
- config 填：`{"mch_id":"商户号","cert_serial":"证书序列号","app_id":"小程序appid"}`

**第 3 步 · 后台录入密钥**（加密存库）
同一条 →「密钥」按钮 → 粘贴三项 → 「加密保存」：
| 字段 | 粘贴内容 |
|---|---|
| WECHAT_PRIVATE_KEY_PEM | apiclient_key.pem 全文 |
| WECHAT_PLATFORM_PUBLIC_KEY_PEM | pub_key.pem 全文 |
| WECHAT_API_KEY_V3 | 那串 32 位密钥 |

**第 4 步 · 验证**
列表「密钥就绪」变 ✅ 绿；真机小程序下单付一笔 → 订单变「已支付」、会员激活；后台退一笔 → 微信商户平台能看到退款。

## 四、阶段②：成立公司，承接个体

1. admin「🏦 收款主体」→「新增收款主体」：类型选**公司**、渠道**微信**、填公司的 config（公司 mchid/证书序列号/appid）。
2. 该主体「密钥」→ 录入**公司的**三件套密钥。
3. 「密钥就绪」绿后 → 点「**设默认**」。
4. 完成。**从此新订单走公司收款；之前个体收的老订单，退款仍自动走个体**（因为订单固化了原主体）。
5. 个体主体**保持启用**，直到它名下老订单的退款/售后窗口都过完，再「停用」。

> 无需改服务器、无需重启、无需迁移老数据。

---

## 五、阶段③：总公司 + 地方子公司（按地区分收）

全程后台操作，无需 SQL：
1. admin「🏢 分公司管理」→「新增分公司」：填名称/法人/分成率/开户行/银行账户（银行账户加密存储）。
2. 该分公司「城市归属」→ 添加负责城市（城市编码；一个城市同一时刻只能归一家分公司）。
3. admin「🏦 收款主体」→「新增收款主体」：类型**子公司**、**关联该分公司**、填子公司商户 config + 「密钥」录入。
4. 之后：该城市学生下单 → **自动走子公司收款**；退款原路退回子公司；结算按分公司归集（`branch_settlements` 已含退款冲减）。

## 六、增加支付宝 / 其他渠道

1. 「新增收款主体」→ 渠道选**支付宝**（或苹果IAP等），填该渠道的 config。
2. 「密钥」录入该渠道所需密钥（系统会按渠道提示需要哪些 key）。
3. 渠道适配器已预留；**微信已真实可用，支付宝/苹果 IAP 需先完成各自的真实对接代码**（架构就绪，属后续开发）。

> 苹果 App 卖会员必须用苹果 IAP（抽成），且退款由苹果发起——这块系统按"对账"处理，不主动退。

## 七、退款怎么走（你只需点审核）

- 用户在小程序「我的→订单记录」申请退款/申诉。
- 7天内未使用 → 系统自动全额退；已使用 → 转人工。
- 你在 admin「💸 退款/申诉审核」队列**通过/驳回**；通过即按**订单原收款主体+原渠道**执行退款。
- 争议时可在该页导出「举证包」（订单+支付确认勾选+IP/UA+使用记录）。

## 八、安全须知

- **主密钥** `FIELD_ENCRYPTION_KEY`：唯一根密钥，离线备份、永不改动、不进代码仓库。
- **渠道密钥**：只能在后台录入，**加密存库、永不回显、接口不返回**；列表只显示「已配置/未配置」。
- **谁能操作**：仅平台超级管理员（`platform_admin`）能进收款主体页。
- 录入密钥请在**可信网络 + HTTPS**下操作；助手（我）不经手任何密钥。
- 生产务必 `WECHAT_PAY_SKIP_SIG_VERIFY=false`（回调验签）、`DEBUG=false`。
