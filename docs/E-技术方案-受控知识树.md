# E 期(简短方案)— 受控知识树:后台定结构,生成只"映射上树"

> 状态:**待确认范围**。系统未上线,可清库重建。

## 诊断(你说的"乱"的根因)
- `knowledge_nodes` **早有 `parent_id` 自引用树字段,但 60 个节点 0 使用**,全扁平。
- 根因:[persist_unit `_get_or_create_node`](../backend/app/services/curriculum_service.py) 对**任意 AI 知识点名都建 active 节点**(source=textbook)→ 名词不可控、无层级。
- 真题同理:对齐时未命中也会落候选/建点。

## 目标(翻转)
**树是唯一权威骨架(人工后台定义)。教材/真题生成时只做"映射":命中树上节点 → 挂内容/建边;未命中 → 进候选,人工挂到树,绝不自建 active 叶子。**

```
（轴=森林根） 知识轴
  ├ 句法 ── 句子种类 ── 陈述句 / 疑问句 …        ← 树:人工定义的受控知识点
  └ 词法 ── 名词 ── (book/apple… 走 vocab_node 挂在"名词"叶子下,不进树)
能力轴 / 考点轴 同理各成一棵
```

## 范围(分 3 步)

### E1 树结构 + 维护页
- 启用 `parent_id`;「知识图谱」页加**树视图**(轴→分类→子类→叶子),支持 加子节点 / 移动(改 parent)/ 改名 / 停用 / 排序。
- 后端:树查询(按 parent_id 组装)、建子节点、移动节点接口。
- 顶层骨架:先 **seed 一版**(按轴预置 句法/词法/篇章/题型… 顶层 + 常见子类)再 UI 微调。

### E2 生成改"映射上树"(治本)
- `persist_unit`:**不再自建 active 节点**。AI 出的知识点名 → 受控匹配树上既有节点:
  - 命中 → 挂讲解(node_resource)+ 建 unit_node 边;
  - 未命中 → 落 `kp_candidate`(pending),讲解暂存 `PendingKpContent`(已存在),等人工挂树。
- 真题 → `platform_question_kp` 只连树上既有节点;未命中 → 候选。

### E3 候选 → 挂到树
- 候选审批时**必须选父节点**(挂到树哪个分类下),通过后物化暂存内容到该节点。保持树整洁。
