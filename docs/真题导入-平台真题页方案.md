# 平台真题导入(KP-First)— 上传 → 抽题 → 校对 → 导入

## 背景

`platform_question`(type=real)的核心能力 `import_real_question`(录真题→受控匹配挂 node→
自动下架该点直生备选→可派生仿真)**已写好但没接 API、没页面**。旧「真题试卷管理」只存试卷元信息
(paper_url),不录结构化真题、走旧 simulated_questions。需补:**新建「平台真题」页 + 上传抽题导入链**。

## 可复用件(已存在)

- `ocr_service.run_ocr(image_url)` → OcrResult(印刷体+手写体),doubao 视觉
- `paper_split_service.split_paper_questions(ocr)` → [{question_no,question_type,stem,correct_answer,explanation}]
- `pdf_upload_service.extract_pages` → 文本 PDF 逐页文本
- `platform_question_service.import_real_question(...)` → 落 platform_question(real)+ match_kp 挂 node
- 异步任务范式:`curriculum_gen_job`(秒回 + 轮询 + 每项独立 commit + 重试)可照搬

## 待确认决策

- **D1 文件格式**:图片 / 扫描 PDF(走 OCR)+ 文本 PDF(pdfplumber 直取)**本期做**;
  **Word(.docx)需新增 python-docx 依赖** —— 本期加还是后置?
- **D2 抽题路径**:文本 PDF → pdfplumber 文本 → LLM split;图片/扫描 PDF → 转页图 → OCR → split。
  (扫描 PDF→页图需 pdf2image/pymupdf;若嫌重,扫描件先让用户转图片上传)
- **D3 异步**:抽题慢(整卷多题+LLM)→ 复用 job 模式,秒回 + 轮询进度(同教材流)。✅倾向是
- **D4 校对**:抽题结果进"待校对"列表,可逐题编辑 题干/选项/答案/解析/难度/**KP 名**,再批量导入
- **D5 KP 挂载**:导入时 kp_names → match_kp 挂 node/落候选(import_real_question 已做);校对时填/改 KP

## 分期实现

**TK1 后端基础(导入接口)** — 解锁一切
- `POST /admin/platform-questions` 单题导入 → import_real_question(stem/options/answer/explanation/
  difficulty/question_type/kp_names/exam meta)
- `POST /admin/platform-questions/bulk` 批量导入(校对后一次落多题)

**TK2 后端抽题(异步 job)**
- `real_question_import_job` 表(类比 curriculum_gen_job):文件 → 抽题 → 存 parsed 待校对
- `POST /admin/platform-questions/extract`(传文件/已传 file_id + 格式)→ 秒回 job_id,后台:
  文本PDF→pdfplumber→split / 图片→OCR→split,逐页/逐块抽题写 job.parsed
- `GET /admin/platform-questions/extract-jobs/{id}` 轮询进度 + 取 parsed 结果

**TK3 前端「平台真题」页**(新菜单)
- 列表:真题/仿真(复用 GET /platform-questions),按 node/type/status 筛
- 上传向导:传文件 → 抽题中(轮询)→ **校对编辑表格**(改题干/选项/答案/KP)→ 批量导入
- 行操作:派生仿真(gen-sim,已有)、审核发布(review,已有)

**TK4 Word 支持(若 D1 选本期)**
- 加 python-docx;`.docx` → 段落文本 → LLM split

## 验收
- 传一份真题(PDF/图片)→ 抽出结构化题 → 校对 → 导入 platform_question(real)→ KP 挂 node →
  可派生仿真 → 审核发布 → 学生练习"有源"
- 异步:秒回 + 进度 + 可关窗口;每题独立落库 + 失败重试
