### D-057｜Tech Spec Section 3 第十一至十五轮回归补全 G1-G13（v2.9 → v3.0）

**背景**：Section 3 经 R11-R15 共五轮累积回归，发现 13 处缺陷未修入。本轮统一补全，覆盖 nullable 缺失、FK 引用表缺失、字段缺失（updated_at / created_at / unbound_at）、DEFAULT 缺失四类问题。

**结论**：

1. **G1（nullable 缺失）refund_records.reason**：standard_7d 退款无需填写理由，字段应为 nullable；补 `TEXT (nullable)`
2. **G2（nullable 缺失）system_configs.description**：自解释的 key 无需描述，字段应为 nullable；补 `TEXT (nullable)`
3. **G3（FK 引用表缺失）essays.wrong_question_id**：FK 目标表未注明；补 `UUID FK → wrong_questions (nullable)`
4. **G4（FK 引用表缺失）practice_records.wrong_question_id**：FK 目标表未注明；补 `UUID FK → wrong_questions (nullable)`
5. **G5（nullable 缺失）branch_companies.contact_phone**：MVP 预留建表时联系方式未填，应为 nullable；补 `VARCHAR (nullable)`
6. **G6（nullable 缺失）ocr_tasks.provider**：供应商由 Layer 2 运行后确定，status=pending/processing 时未知；补 `ENUM(...) (nullable)`
7. **G7（字段缺失）teachers 补 updated_at**：cert_status 等关键字段变更无时间戳，无法审计认证状态流转；新增 `updated_at TIMESTAMPTZ`
8. **G8（字段缺失）student_relatives 补 unbound_at**：is_active=false 时无解绑时间戳，与 teacher_students.unbound_at 设计不对称；新增 `unbound_at TIMESTAMPTZ (nullable)`
9. **G9（DEFAULT 缺失）memberships.is_active**：全库其他 BOOLEAN 字段均有显式默认值，memberships.is_active 是唯一例外；补 `DEFAULT true`
10. **G10（字段缺失）students 补 updated_at**：grade / textbook_ver / semester 均可变更，无时间戳无法审计最后修改时间；新增 `updated_at TIMESTAMPTZ`
11. **G11（字段缺失）ocr_tasks 补 updated_at**：status / retry_count 中间态转换无时间戳，仅 completed_at 覆盖终态，无法分析排队耗时与执行耗时；新增 `updated_at TIMESTAMPTZ`
12. **G12（字段缺失）system_configs 补 created_at**：全库 37 张表中唯一缺 created_at 的表，无法审计配置项何时引入；新增 `created_at TIMESTAMPTZ`
13. **G13（字段缺失）assignment_submissions 补 updated_at**：score 为异步填入字段，与 wrong_questions / essays / listening_records 同类表均有 updated_at，此表遗漏；新增 `updated_at TIMESTAMPTZ`

**影响范围**：
- 域1 students / teachers / student_relatives：新增 updated_at / unbound_at
- 域2 memberships / refund_records：补 DEFAULT / nullable
- 域3 ocr_tasks：补 provider nullable + 新增 updated_at
- 域5 essays：补 FK 引用表
- 域6 practice_records：补 FK 引用表
- 域7 assignment_submissions：新增 updated_at
- 域9 system_configs：补 description nullable + 新增 created_at
- 域10 branch_companies：补 contact_phone nullable
- 文档版本：v2.9 → v3.0

### D-056｜Tech Spec Section 3 第十轮回归补全 G1-G5（v2.8 → v2.9）

**背景**：Section 3 第十轮精读，聚焦注册 IP 容错、异步状态表 updated_at 一致性、计时失败场景、知识树顶层节点描述，以及域 10 预留表负责人字段。

**结论**：

1. **G1（nullable 缺失）users.ip_at_registration 补标注**：代理/VPN 环境或负载均衡丢失 X-Forwarded-For 头时 IP 无法获取，字段应为 nullable；NOT NULL 会导致上述场景注册失败；补 `INET (nullable)`
2. **G2（字段缺失）listening_records 补 updated_at**：AI 评分状态从 processing→completed/failed 发生在同一行，无 updated_at 则无法知道"评分于何时完成"；与 essays 规则不一致；新增 `updated_at TIMESTAMPTZ`
3. **G3（nullable 缺失）practice_records.time_spent_sec 补标注**：前端切后台/锁屏/断网重连后提交时计时失败，用 NULL 而非 0 表达"无效计时"（0 会污染平均耗时统计）；补 `INT (nullable)`
4. **G4（nullable 缺失）knowledge_points.description 补标注**：知识点树顶层分类节点（"语法"/"词汇"）无需逐条描述，批量导入知识树时顶层节点 description 为 NULL；NOT NULL 会导致导入失败；补 `TEXT (nullable)`
5. **G5（nullable 缺失）branch_companies.manager_user_id 补标注**：域 10 MVP 预留建表时分公司负责人账号尚未注册或指定，应为 nullable；补 `UUID FK → users (nullable)`

**影响范围**：
- 域1 users：ip_at_registration 补 nullable
- 域4 knowledge_points：description 补 nullable
- 域5 listening_records：新增 updated_at
- 域6 practice_records：time_spent_sec 补 nullable
- 域10 branch_companies：manager_user_id 补 nullable
- 文档版本：v2.8 → v2.9

### D-054｜Tech Spec Section 3 第七、八轮回归补全 G1-G10（v2.6 → v2.7）

**背景**：Section 3 第七轮（5 处）和第八轮（5 处）回归精读，聚焦微信注册流程字段、学生资料可选性、异步任务错误追踪、词库完整性，以及跨表 nullable 标注一致性。两轮合并一次提交。

**结论**：

1. **G1（nullable 缺失）users.nickname / avatar_url**：微信 2021 年新隐私政策废弃自动获取，用户可跳过授权；两字段注册时可合法为 NULL；补 `(nullable)`
2. **G2（nullable 缺失）students.grade / textbook_ver / semester**：学生注册时仅需微信授权，三个学习配置字段在个人设置页补填；均补 `(nullable)`
3. **G3（字段缺失）ocr_tasks 补 error_message**：status=failed 时无错误详情，生产环境无法定位 OCR 失败原因；新增 `error_message TEXT (nullable)`
4. **G4（nullable 缺失）vocabulary_words.phonetic / examples**：专有名词/缩写词无 IPA 音标；部分词汇暂无例句；均补 `(nullable)`
5. **G5（DEFAULT 缺失）student_relatives.is_active 补 DEFAULT true**：亲人绑定成功即生效，无 DEFAULT 则 INSERT 时漏传导致 NULL 或报错；补 `DEFAULT true`
6. **G6（nullable 缺失）institutions.commission_rate**：机构 status=pending 审核期间平台尚未谈定分成比例，初始为 NULL；补 `(nullable)`
7. **G7（nullable 缺失）assignments.due_at**：出卷任务 draft 阶段可不填截止时间，发布前确定；补 `(nullable)`
8. **G8（字段缺失）essays 补 updated_at**：作文精修状态流转（draft→processing→completed）无时间戳；新增 `updated_at TIMESTAMPTZ`
9. **G9（字段缺失）branch_companies 补 updated_at**：commission_rate / 财税字段变更无审计时间戳；新增 `updated_at TIMESTAMPTZ`
10. **G10（标注不一致）students / teachers .institution_id 补显式 (nullable)**：两处仅靠注释暗示可空，与全文其他外键 `(nullable)` 显式标注规则不一致；补齐

**影响范围**：

- 域1 students：institution_id 补显式 nullable；grade / textbook_ver / semester 补 nullable
- 域1 teachers：institution_id 补显式 nullable
- 域1 student_relatives：is_active 补 DEFAULT true
- 域1 institutions：commission_rate 补 nullable
- 域3 ocr_tasks：新增 error_message
- 域5 vocabulary_words：phonetic / examples 补 nullable

### D-053｜Tech Spec Section 3 第七轮回归补全 G1-G5（v2.5 → v2.6）

**背景**：Section 3 第七轮精读，聚焦微信注册流程 nullable 遗漏、AI 异步写入时序、听力跟读缺失 status 字段，以及域 10 预留表的 nullable 完整性。

**结论**：

1. **G1（nullable 缺失）users.phone 补标注**：微信小程序 `wx.login` 只获取 openid，不含手机号；绑手机是注册后独立操作，初始值为 NULL；补 `VARCHAR (nullable)`
2. **G2（nullable 缺失）wrong_questions 三字段补标注**：`question_type` 由 LLM 判断题型后写入，`difficulty` 由 AI 诊断后写入，`tags` 由 AI 分析后写入；三字段写入时机均晚于记录创建，均补 `(nullable)`
3. **G3（字段缺失）listening_records 补 status 字段**：AI 发音评分为异步流程；score IS NULL 无法区分"处理中"与"评分失败"；新增 `status ENUM(processing / completed / failed)`；score 和 feedback 的注释改为 status=completed 后写入
4. **G4（nullable 缺失）branch_companies 财税字段补标注**：域 10 说明 MVP 阶段建表不填数据，legal_name / tax_number / bank_name / bank_account 四个财税字段分公司未成立时均为 NULL；均补 `(nullable)` 及说明
5. **G5（nullable 缺失）assignments.questions 补标注**：status=draft 时老师发起"AI生成题目"但 AI 尚未返回，questions 为 NULL；补 `JSONB (nullable)`

**影响范围**：
- 域1 users：phone 补 nullable
- 域3 wrong_questions：question_type / difficulty / tags 补 nullable
- 域5 listening_records：新增 status 字段；score / feedback 注释更新
- 域7 assignments：questions 补 nullable
- 域10 branch_companies：4 个财税字段补 nullable
- 文档版本：v2.5 → v2.6

### D-052｜Tech Spec Section 3 第五、六轮回归补全 G1-G10（v2.4 → v2.5）

**背景**：Section 3 数据模型第五轮（5 处）和第六轮（5 处）回归精读，聚焦异步写入流程的 nullable 标注、缺失字段及 nullable/NOT NULL 歧义。两轮合并一次提交。

2. **G2（nullable 缺失）ocr_tasks.raw_result 补标注**：pending/processing 状态下尚无 OCR 响应，`raw_result JSONB` 补 `(nullable)`
3. **G3（字段缺失）refund_records 补 wx_refund_id**：微信退款 API 返回退款单号，不存则无法对账及查询退款到账状态；新增 `wx_refund_id VARCHAR (nullable)`
4. **G4（nullable 缺失）essays.polished_text / dimensions 补标注**：status=draft/processing 时 AI 尚未完成精修，两字段为 NULL；各补 `(nullable)`

### D-051｜Tech Spec Section 3 第四轮回归补全 G1-G5（v2.3 → v2.4）

**背景**：Section 3 数据模型第四轮精读，聚焦约束表达合法性、nullable 标注完整性和复合唯一约束遗漏。

**结论**：

1. **G1（约束语法错误）student_relatives 改为 Service 层 NOTE**：`[CONSTRAINT: COUNT(relative_id) WHERE student_id <= 4]` 在 PostgreSQL 中非法（CHECK 约束不能用聚合函数）；改为 `[NOTE: 每学生最多 4 位亲人，Service 层在 INSERT 前 SELECT COUNT 校验，超限返回 3002 错误]`，与实际实现一致
2. **G2（nullable 缺失）orders.wx_transaction_id / paid_at 补标注**：status=pending 时两字段均为 NULL，但文档未标注 nullable；不补标则 Alembic 工程师会错误生成 NOT NULL 列；补充 `VARCHAR (nullable)` 和 `TIMESTAMPTZ (nullable)`
3. **G3（nullable 缺失）wrong_questions.mastered_at / ocr_tasks.completed_at 补标注**：is_mastered=false 时 mastered_at 为 NULL；status=pending/processing 时 completed_at 为 NULL；均补充 `(nullable)` 标注
4. **G4（唯一约束缺失）curriculum_units 补复合唯一约束**：同一学期同一教材版本可能重复录入相同单元号；补充 `[UNIQUE: (textbook_version, grade, semester, unit_no)]`
5. **G5（字段缺失）institutions 补 updated_at**：机构是唯一独立实体表中缺少 updated_at 的表；状态变更（pending→active→suspended）无时间戳无法审计；补充 `updated_at TIMESTAMPTZ`

**影响范围**：
- Section 3 域1 student_relatives：约束注释改为 Service 层 NOTE
- Section 3 域2 orders：wx_transaction_id / paid_at 补 nullable 标注
- Section 3 域3 wrong_questions：mastered_at 补 nullable 标注
- Section 3 域3 ocr_tasks：completed_at 补 nullable 标注
- Section 3 域4 curriculum_units：新增 UNIQUE(textbook_version, grade, semester, unit_no)
- Section 3 域1 institutions：新增 updated_at
- 文档版本：v2.3 → v2.4

### D-050｜Tech Spec Section 3 第三轮回归补全 G1-G5（v2.2 → v2.3）

### D-040｜用户与机构地区归属体系（为分公司按城市管理预留）

**背景**：后期业务扩展可能出现分公司，分公司可能涵盖多个城市。需要在注册/认证阶段就记录用户和机构的归属城市，以支持分公司按地区统计业绩和管理用户，同时机构认证需核实其所在地区的真实性。

**结论**：

1. **地区归属优先级**：机构城市（最高）> 认证核实城市 > 注册时 IP 城市（最低）
2. **自由学生/亲人/未认证老师**：首次注册时服务端静默 IP 解析到城市，写入 `city_code`，用户不感知，后续登录 IP 变化不更新
3. **已认证老师**：认证审核通过时，以核实的学校所在城市覆盖 IP 城市（`city_source=cert_verified`）
4. **机构学生/机构老师**：加入机构时以机构的认证城市覆盖个人城市（`city_source=institution`）
5. **机构**：入驻申请必填所在城市（省/市/区三级）+ 机构详细地址；审核时核实城市与营业执照注册地是否一致；认证通过后城市锁定，不可自行修改
6. **边界情况**：IP 解析失败/海外 IP → 标记 `unknown`，运营手动修正；老师调岗需平台超管操作；机构跨城展业须单独注册机构账号
7. **与分公司的衔接**：`users.city_code` 和 `institutions.city_code` 先行存储，等分公司架构确定后只需建 `branch_company_cities` 映射表即可反查归属

### D-039｜学生绑定老师主路径：短信邀请 + 小程序链接分享（两条路径）

**背景**：系统体量增大后，原「学生按学校名/老师名搜索认证老师」方案存在多重缺陷：同名老师无法区分、老师无接单上限、绑定即时生效老师无感知、搜索性能差。讨论中明确：学生（家长）几乎100%持有老师手机号，正确方式是系统向老师手机号发短信邀请，而非在平台内搜索老师手机号——后者会导致老师收到陌生学生莫名申请。

**结论**：

1. **主路径（学生发起）**：学生在 App 输入老师手机号 → 系统调腾讯云 SMS 发送邀请短信（含 Token 链接，48h 有效）→ 老师点链接进入小程序确认 → 绑定生效；若老师未注册，短信引导注册后自动完成绑定
2. **辅助路径（老师发起）**：老师生成专属小程序绑定链接（7天有效）→ 在微信/家长群分享 → 学生点击确认
3. **两条路径均需老师主动确认**，`teacher_students.status` 统一走 `pending → active`，老师不会被动接单
4. **废弃"平台内手机号搜索"**：手机号是短信发送目标，不是平台内搜索字段，不需要 `phone_searchable` 开关
5. **废弃邀请码方案**：小程序链接已覆盖其场景
6. **机构分配场景不变**：`institution_assigned` 由机构后台直接写 `status=active`，跳过 pending

**影响范围**：
- Tech Spec Section 1：架构图和 §1.4 NotificationService 补入腾讯云 SMS；关键技术决策表新增 SMS 条目
- Tech Spec Section 3：`teachers` 表删除 `phone_searchable`，保留 `subject`、`max_students`
- Tech Spec Section 3：`teacher_students.bind_source` 枚举 `phone_search` → `sms_invite`
- Tech Spec Section 4：`/students/bind-teacher` → `/students/invite-teacher`（触发短信）；删除 `/teachers/me/settings`（phone_searchable）；`/teachers/search` 降为辅助路径（仅按学校/姓名搜索）

### D-019｜退款规则重构为三层体系（含法律风险分析）

**背景**：原退款规则写"超过7天不支持退款"，经法律分析该表述存在被认定为霸王条款的风险；"给退款入口但后台默认拒绝"方案属于明确违法（消费者权益保护法第55条欺诈，三倍赔偿）。

**结论**：采用三层退款体系：

- **第一层（7天内，自动/人工）**：
  - 未使用（AI分析0次）→ 全额退款，系统自动通过
  - 已使用（AI分析≥1次）→ 按剩余天数比例退款，人工审核
  
- **第二层（超过7天，无理由）**：不支持，明确告知，合法合规

- **第三层（超过7天，有理由申诉通道）**：保留以下四种法定情形的申诉权：
  1. 平台系统故障连续48小时以上 → 延长时长或部分退款，平台主动赔付
  2. 服务内容与描述严重不符 → 全额退款或协商补偿
  3. 误操作重复购买72小时内且未使用 → 退重复订单
  4. 未成年人未经监护人同意购买 → 全额退款
  - 同一账号每自然年限申诉1次，申诉须填写原因并上传截图证明

**关键法律保护动作**：支付确认页独立弹窗，用户主动勾选两条确认项，服务器端留存勾选记录（含时间戳）作为举证材料。没有这一步，任何退款条款均面临被认定为霸王条款的风险。

**不可用方案**：给退款入口但后台默认拒绝 → 违反消费者权益保护法第55条（欺诈），面临三倍赔偿及行政处罚，绝对不可用。

**影响范围**：Section 八.4（退款规则，完整重构为三层体系含4.1-4.4四个子节）

- 分配方式：激活码发给学生 / 后台直接绑定手机号，时长从激活当日起算

**影响范围**：Section 九.1、九.2

### D-005｜会员时长最小购买单位为 1 学期（半年）

**背景**：原文档定义了半年/1年/2年/3年四档时长，未明确最小购买单位和续费规则。

**结论**：
- 新购、续费、亲人代付均以 **1 学期（半年）** 为最小单位，不支持购买不足半年的时长
- **到期前**续费：新购时长叠加至到期日顺延，权益不中断
- **到期后**续费：从购买当日重新起算，不再叠加

**影响范围**：Section 八.1（时长周期说明）、八.3.3（代付表格）

### D-004｜OCR 技术选型：不使用 DeepSeek，采用专用 OCR API 分层架构

**背景**：需求文档要求印刷体识别准确率 ≥99%、手写体 ≥90%，评估 DeepSeek 是否满足。

**调研结论**：
- DeepSeek 官方 API 截至 2026-05 不支持图像输入，无法直接接入
- DeepSeek-VL2 在 OCRBench v2 仅得 43.3/100，生产环境复杂文档实测 75-80%，不满足要求

**最终选型**：

| 场景 | 主选 | 备选 |
|------|------|------|
| 印刷体试卷 | **阿里云 OCR（读光高精度版）**，官方 >99.7% | **百度 OCR（通用高精版）**，官方 >99%，有免费额度 |
| 学生手写作答 | **腾讯云 OCR 手写识别**，官方 >90%，中文实测 94.7% | **Google Document AI**，英文手写实测 92-95% |
| 错题诊断/报告生成 | **DeepSeek / Claude 等 LLM**（OCR 输出文本后传入） | — |

**架构原则**：OCR 识别层与 LLM 诊断层必须分开，不可用同一模型包揽。

**影响范围**：Section 十.2、附录 A（OCR 技术选型调研报告）

### D-003｜平台题库不使用真题原题，改为 AI 参照真题生成仿真题

**背景**：原需求文档将"真题"与"平台题库"混用，存在版权风险且逻辑不清。

**结论**：
- 学生上传的是自己在学校获得的真实试卷（供 AI 识别分析错题），与平台题库无关
- 平台内置题库全部为 AI 原创生成的仿真题，以真题为参照，参照维度包括：知识点分布、题型结构、难度梯度、高频考点、干扰项逻辑
- 不存储、不收录任何真题原题，规避版权侵权问题

**影响范围**：Section 三.2、功能模块五（服务包说明）、六.2（AI 仿真题生成与质检标准）、功能模块 5B 步骤三

### D-001｜亲情账户体系合规修改：积分商城 → 亲情账户+直接代付

**背景**：原设计中亲人购买积分、学生兑换实物礼品，涉及平台虚拟货币双向兑换，存在被认定为未经审批虚拟货币或变相赌博的合规风险。

**结论**：
- 删除积分、虚拟货币、礼品兑换全部相关设计
- 改为「亲情账户 + 直接代付」模式：亲人直接为学生购买真实服务（会员新购/续费/升级/专项功能包）
- 所有亲人消费均为明确服务的直接付费，无积分中间层
- 代付项目：会员新购、续费（最小1学期）、档位升级、专项功能包、额外学期服务包

**影响范围**：Section 八.3（亲情账户与代付体系）、通知推送体系相关条目
