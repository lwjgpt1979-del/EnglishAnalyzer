### D-039｜学生绑定老师主路径：手机号搜索 + 小程序链接分享，废弃邀请码路径

**背景**：系统体量增大后，原「学生按学校名/老师名搜索认证老师」方案存在多重缺陷：同名老师无法区分、老师无接单上限、绑定即时生效老师无感知、搜索性能差。讨论了邀请码方案，最终判断手机号/微信方式更符合中国实际使用场景（家长和学生几乎100%持有老师手机号）。

**结论**：

1. **主路径**：学生通过手机号精确搜索老师（`phone_searchable=true` 才返回）→ 发起绑定申请（`status=pending`）→ 老师确认后生效（`status=active`）
2. **辅助路径**：老师在微信/群里分享专属绑定小程序链接（7天有效）→ 学生点击直接跳转绑定页 → 同样走老师确认流程
3. **废弃搜索姓名/学校为主路径**：降为辅助搜索（无手机号时的备用），不作主推
4. **废弃邀请码方案**（teacher_student_bind 类型）：链接分享已覆盖其场景，无需额外维护一批短期码
5. **机构分配场景不变**：`institution_assigned` 类型由机构后台直接写入 `status=active`，跳过 pending 流程

**影响范围**：
- Tech Spec Section 3：`teachers` 表新增 `subject`、`max_students`、`phone_searchable` 字段
- Tech Spec Section 3：`teacher_students` 表 `is_active BOOLEAN` → `status ENUM(pending/active/rejected)`，新增 `bind_source`、`requested_at` 字段，UNIQUE 约束更新
- Tech Spec Section 4：`/teachers/search` 新增 `?phone=xxx` 主参数；学生-老师绑定接口组重写（新增 bind-requests 确认流程、bind-link 分享链接、phone_searchable 设置接口）

### D-038｜Tech Spec Section 1 回归补全（G1-G6 六处缺口）

**背景**：对照 PRD § 10.1-10.6 进行 Section 1 系统性回归，发现 6 处缺口。

**结论**：

1. **G1**：补充 OCR 四层处理管道（§1.1），含备选服务商（百度OCR / Google Document AI）
2. **G2**：补充 7 条 API 设计约束原则（§1.2），包括统一响应格式、平台无关用户标识、JWT标准化、版本管理、文件上传通用化、推送渠道抽象、前后端分离
3. **G3**：补充性能 SLA（§1.3）：OCR≤60s、报告≤30s、可用性≥99.5%、非AI接口P99≤500ms
4. **G4**：补充 NotificationService 统一推送路由层（§1.4），替代直连各渠道方案
5. **G5**：补充老师双 OAuth 身份关联机制（§1.5）：普通微信 + 企业微信共享同一 user_id
6. **G6**：补充监控告警架构（§1.6）：CLS + 云监控 + 5 条告警规则 + 故障赔付触发条件
- 同步更新主架构图，版本升至 v1.4

**影响范围**：Tech Spec Section 1（新增约 162 行）。

### D-034｜第十二轮回顾遗留缺口修复（2处）

### D-033｜第十二轮回顾后的缺口修复（3处）+ 全局服务次数后台可配置化

**背景**：第十二次全文回顾，发现3处功能逻辑缺口。用户同时确认系统内所有服务次数限额均应由后台统一配置管理，不得在文档或客户端中硬编码。

**结论**：

1. **缺口①修复：Module 7 缺少个人老师月度限额预警通知**：四C 新增了个人认证老师月度使用限额，但 Module 7 推送事件表中没有对应预警。修复：在核心通知场景表中新增一行「个人老师月度限额剩余 ≤20% 时向已认证·个人老师推送预警，告知剩余次数并引导升级机构账号」，预警阈值在 5.6 后台配置。

2. **缺口②修复：九.1 机构套餐缺少AI资源配额列**：机构套餐表仅定义老师子账号数量，未定义机构整体月度AI资源上限，导致「机构老师无个人上限，由套餐统一配置」无落地依据。修复：在九.1 老师子账号套餐表新增「机构月出卷总量」和「机构月AI批改总量」两列（参考默认值：入门包100份/500次、标准包400份/2000次、旗舰包1000份/5000次），并注明所有数字均在 5.6 后台配置，运营可随时调整。

3. **缺口③修复：个人认证老师的推送渠道未明确**：Module 7 原文「B端（机构管理员/老师）通过企业微信推送」，但个人认证老师无企业微信，造成推送渠道空白。修复：将推送渠道说明改为分角色渠道表：学生/亲人=小程序subscribeMessage；**个人认证老师=小程序服务通知（同C端渠道）+ 铃铛，不走企业微信**；机构老师/机构管理员=企业微信推送 + 铃铛。

4. **全局原则确立：所有服务次数限额后台统一配置**：5.6 系统配置重构为全局服务次数配置注册中心，覆盖：学生AI分析每日次数（各档位）、题库练习每日题数（免费/基础/Pro/ProMax）、词力通每日新词上限（各档位）、个人老师月度绑定/出卷/批改上限及预警阈值和重置时间、机构套餐月度出卷/AI批改配额及子账号分配上限。各功能章节（四C老师限额表、Module 8 练习权限表、会员权益对比表）均追加「后台可配置，见 5.6」脚注。

**影响范围**：Module 7（推送渠道表 + 核心通知事件表）、九.1（老师子账号套餐表 + 配置说明）、5.6（全面扩展为多分类的配置中心）、四C 个人老师额度说明（新增脚注）、Module 8 §8.3（新增脚注）、会员权益对比表（新增注2脚注）。

### D-032｜第十一轮回顾后的缺口修复（3处）

**背景**：第十一次全文回顾，发现2处功能流程设计缺口 + 1处角色定义悖论。

**结论**：

1. **缺口修复：Module 5B 老师自定义题目缺少内容审核步骤**：5.6 承诺「老师自定义题目均需过滤」，但 Module 5B 的出卷6步流程中步骤3上传后直接跳步骤4预览，审核环节完全缺失。修复方案：在步骤3末尾补注「上传后立即触发内容审核」；步骤4补充「审核中/未通过题目不可分发」约束；在流程代码块后新增「老师自定义题目内容审核规则」章节，定义文字（实时敏感词过滤/阻断）与图片（实时检测+人工24h）两种上传类型的审核方式、通过/未通过处理，以及分发按钮在有未通过题目时置灰的交互规则。

2. **缺口修复：Module 5B-S 任务截止时间到达后的处理逻辑未定义**：5B 可设截止时间，5B-S 展示截止时间字段，但截止时间到达后的系统行为完整缺失。修复方案：在 5B-S 会员限制章节后新增「截止时间到达后的处理规则」，明确三种情形（已提交不变 / 未提交变「已截止」不可再提交 / 正在作答中自动提交已答内容留空而非计错）；定义老师侧推送通知（截止后推「X人已提交Y人未提交」）；定义补交机制（老师可为单个未提交学生延长最多7天，系统通知学生；30天后自动归档）。

3. **悖论修复：二.3 场景二升级提示通知接收方「学校负责人」角色不存在**：场景二方式②是学生自行购买+绑定认证老师，学校没有机构账号，不存在「学校负责人」，原文「系统自动提示学校负责人」的通知无人接收。修复方案：将通知接收方改为「该校所有已认证老师」（均为平台已有账号，推送可达）；同时在超管后台将该学校标记为「潜在升级机构」，供运营人员主动跟进，形成线上自动触达+线下人工跟进的双通道升级转化路径。

**影响范围**：功能模块 5B（步骤3/4 + 新增自定义题目内容审核规则章节）、功能模块 5B-S（新增截止时间处理规则章节）、二.3 师生绑定分层规则老师认证机制说明。

### D-019｜退款规则重构为三层体系（含法律风险分析）

**背景**：原退款规则写"超过7天不支持退款"，经法律分析该表述存在被认定为霸王条款的风险；"给退款入口但后台默认拒绝"方案属于明确违法（消费者权益保护法第55条欺诈，三倍赔偿）。

**结论**：采用三层退款体系：

- **第一层（7天内，自动/人工）**：
  - 未使用（AI分析0次）→ 全额退款，系统自动通过
  - 已使用（AI分析≥1次）→ 按剩余天数比例退款，人工审核
  
- **第二层（超过7天，无理由）**：不支持，明确告知，合法合规

- **第三层（超过7天，有理由申诉通道）**：保留以下四种法定情形的申诉权：
  1. 平台系统故障连续48小时以上 → 延长时长或部分退款，平台主动赔付
  2. 服务内容与描述严重不符 → 全额退款或协商补偿
  3. 误操作重复购买72小时内且未使用 → 退重复订单
  4. 未成年人未经监护人同意购买 → 全额退款
  - 同一账号每自然年限申诉1次，申诉须填写原因并上传截图证明

**关键法律保护动作**：支付确认页独立弹窗，用户主动勾选两条确认项，服务器端留存勾选记录（含时间戳）作为举证材料。没有这一步，任何退款条款均面临被认定为霸王条款的风险。

**不可用方案**：给退款入口但后台默认拒绝 → 违反消费者权益保护法第55条（欺诈），面临三倍赔偿及行政处罚，绝对不可用。

**影响范围**：Section 八.4（退款规则，完整重构为三层体系含4.1-4.4四个子节）

### D-004｜OCR 技术选型：不使用 DeepSeek，采用专用 OCR API 分层架构

- 不存储、不收录任何真题原题，规避版权侵权问题

**影响范围**：Section 三.2、功能模块五（服务包说明）、六.2（AI 仿真题生成与质检标准）、功能模块 5B 步骤三

### D-002｜「词力通」词汇模块自建，不集成百词斩

**背景**：原需求文档多次提及"百词斩词汇配套服务"，未明确是集成第三方还是自建。

### D-001｜亲情账户体系合规修改：积分商城 → 亲情账户+直接代付

**背景**：原设计中亲人购买积分、学生兑换实物礼品，涉及平台虚拟货币双向兑换，存在被认定为未经审批虚拟货币或变相赌博的合规风险。

**结论**：
- 删除积分、虚拟货币、礼品兑换全部相关设计
- 改为「亲情账户 + 直接代付」模式：亲人直接为学生购买真实服务（会员新购/续费/升级/专项功能包）
- 所有亲人消费均为明确服务的直接付费，无积分中间层
- 代付项目：会员新购、续费（最小1学期）、档位升级、专项功能包、额外学期服务包

**影响范围**：Section 八.3（亲情账户与代付体系）、通知推送体系相关条目
